# ROADMAP.md — 今後の計画

現況は `PLAN.md`、設計は `ARCHITECTURE.md`。ここは前向きの作業のみ。優先度は上から。

## フェーズ0（いま・着手済み）: 校正とバックテスト

**目的**: 抽出プロンプトが実データで効くことを、既存wikiを正解データにして確かめる。
**現状**: GPT sol（高）で2023年分の抽出を開始。モデルの癖（`loop_type`欠落・`evidence`のdict返し・字幕への`verbatim:true`）を確認し、スキーマ堅牢化で吸収済み（`PLAN.md`）。既存wiki2026年分での本格採点はこれから。

- 既存wikiの**2026年の年表・名言**を正解セットとして手元に用意する。
- `s2_pack --stream <vid>` で、wikiに記述のある2026年配信を3〜5本パック化。
- Claude最上位モデルで抽出①→`s2_ingest`。採点は3指標:
  1. **⚠件数**（逐語違反・スキーマ破棄・日付補正）: 少ないほど指示追従が良い。
  2. **再現率**: 既存wikiの出来事・名言をカードが拾えたか。
  3. **誤検出**: 出典確認で事実と違うカードの数。
- 取りこぼし/誤検出のパターンを見て `prompts/extract_stream.md` を調整。**完了条件**: ⚠が数件以内、主要な出来事の取りこぼしが無い。

**成果物**: 校正済みプロンプト、モデル別の採点結果（`MANUAL.md §4` 末尾を実測値で更新）。
**運用のコツ**: 各モデルの初回は破棄率・⚠内容を必ず確認する（モデルごとに出力の癖が違う）。破棄された伏線が惜しければ `loop_type`/`expected_signal` を手で補って入れ直す。

## フェーズ1: 全ログの取り込みと量産

- `s0_intake --src <logs>` 本実行 → `s1_normalize --all`（96本）。日付順処理で概要欄新規行検知が正しく育つ。
- `doctor.py` の所見に沿って `known_absent.tsv`（コメント無し回など）・`stream_relations.tsv`（アーカイブ対）を記入。
- `s2_pack --all` → WORKLIST順に量産抽出。長時間配信は自動分割。
- 週次で S3→S4→S5、月次で名言選考（`--mature-days 30`）・台帳棚卸し（`--list-open`）・doctor・回帰確認。

**注意**: 2023年配信はチャット密度・字幕品質・文化が2026年と異なる。フェーズ0の校正が2026年中心なので、
2023年で挙動が変わる可能性がある。最初の数本で再点検し、必要なら年代別のプロンプト補足を検討。

## フェーズ2: ソースの拡張

現在のログは「しずく本体アカ＋YouTube本編」に限られる。年表の網羅性には以下が要る（`DATA-ISSUES.md §5`）。

- **あき先生アカ（@cumulo_autumn）**: 技術告知・裏話の主要出典。TSVを同形式で `logs/twitter(x)/` に追加すれば S1 が投稿者ごと取り込む。抽出は掛け合い素材として `extract_x` を流用可。
- **メディア掲載**: 記事・受賞・イベント。スキルの media-coverage 運用が受け皿。収集は手動、出典書式はスキルに従う。
- **Discordログ**: S0は現状スキップ。フォーマットを確認し、`classify()` に種別を足すか専用取込を作る。ポモドーロ等Discord限定機能の裏取りに有用。

## フェーズ3: モデルB（Claude Code）への移行

**方針**: S0〜S4をエージェントが一括実行、**S5（試聴・逐語確定・採否・Fandom貼付）だけ人間に残す**。

- エージェントに `CLAUDE.md` を読ませ、「logsからパケットまで一括」を指示。抽出①・照合②はエージェント内のサブ呼び出しに置換。
- 冪等性は既に確保（manifest/extracted/match_seen/in_review）。`--redo` で再生成可。
- 大量処理でのモデル選択はコストが効くようになる（フェーズ0の採点結果を使う）。中位モデルへ落とす判断はここで。
- **移さないもの**: ゲート1（逐語）・ゲート2（公開）。品質の源泉であり、自動化しない。

## フェーズ4: 機能検知の強化

- **検知器の追加**: 現行5種（概要欄差分・新規性語彙×バースト・字幕沈黙×チャット密集・事後コメント時刻・X告知突合）に、
  サムネ/タイトルのパターン学習や、事後コメントの定量分析（何分に言及が集中したか）を追加検討。
- **レジストリの自動更新提案**: 採用した capability を `features_registry.tsv` へ書き戻す半自動化（現状は手動転記）。
- **初披露特定の精緻化**: 3段階強度（コーパス内初観測＜初見反応＜出典）を維持しつつ、X告知との時刻突合を自動化。

## フェーズ5: 品質・運用の底上げ

- **回帰テスト化**: `PLAN.md §2` の実測値を assert するスクリプトを追加し、変更時に自動チェック。
- **コラボ回の話者分離**: 抽出プロンプトに「話者不確かなら speaker=不明」を追加。恒久対応（話者分離モデル）は要検討。
- **wiki反映の追跡**: handoff→実際の編集差分→版のリンクを記録し、「どのカードがどの版で反映されたか」を辿れるように。
- **多言語字幕の活用**: 現在 `.en.srt` 等は無視。英語配信部分の扱いを決める（原則は日本語中心）。

## 判断が必要な分岐（メモ）

- **抽出の粒度**: 1配信=1パックを維持するか、シリーズ（3日間の思い出等）をまとめるか。現状は1配信単位。
- **名言の熟成期間**: 既定30日。運用実績で調整。
- **カード種別の増減**: 現在6種。新しい型が必要になったら `SPEC.md` と全スクリプトの分岐を同時に更新（`kind[:2]` の衝突に注意）。
- **モデル料金 vs 人手**: モデルAの間は人手が支配的なので最上位モデル固定でよい。Bで再検討。
