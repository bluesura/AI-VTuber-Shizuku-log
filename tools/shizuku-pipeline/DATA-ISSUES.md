# データ不備 対処マニュアル（本工程とは独立のトラック）

検査ツール: `python scripts/doctor.py` → `data/review/doctor_report.md` が生成されます。
レポートの各所見には本書の節番号（§n）が付いています。**ERROR=工程を止めて直す / WARN=読んで判断 / INFO=知っておく**。
以下、あなたのデータで実際に観測された数値つきで説明します。

---

## §1（D01）UTCとJSTの日付ずれ
- **症状**: Xログの「日付」列はUTC。JSTに直すと**日付が変わるポストが 234/2641件（約9%）**。深夜帯の投稿が多いため無視できない率。
- **影響**: 年表の日付が1日ずれる。スキルの規則（§3-1: 全日付はJST）に反する。
- **対処**: Step1が全ポストを自動でJST変換済み（`date_jst`）。**手作業でTSVから日付を写さない**こと。手で確認したい時: UTC時刻+9時間、`15:00Z` 以降は翌日。
- **実例**: 「ギャルボイスモデル」のポストはUTCでは2/27、**JSTでは2026-02-28**。台帳・年表はJST側を使う。

## §2（D02）ASRの固有名詞崩壊と補正辞書
- **症状**: 自動字幕は固有名詞を安定して壊す。実測: 7-24配信で「あき先生」が全て「秋先生」（22回）、「しずく」→「雫」「しず子」等。8-02では 秋先生×36 / 雫×138。
- **影響**: 検索・照合の取りこぼし。逐語と誤認する事故。
- **対処**: `config/asr_fixes.tsv` の辞書が **normalized層（norm列）だけ** に適用される。原文（asr列・raw/）は不変で残るので、いつでも監査できる。
- **辞書に入れてよい条件（ゲート3・人間承認制）**:
  1. その文字列がこの文脈で正表記以外を意味しない（「秋先生」→OK。「しず」「気づく」→**入れない**。一般語と衝突する）。
  2. チャット・Xには**絶対に適用しない**（視聴者の「もずく」「しずる」等のいじり表記は原文の価値。実測: チャットにあき先生43回・もずく1回）。
- **候補の見つけ方**: doctorが「字幕に頻出するのにチャットに一度も出ない語」を出す。実例（8-02）: `下打`（=舌打ち）、`先行花火`（=線香花火）、`山崎`（=デイリーヤマザキ）。**機械は候補提示まで、採否はあなた**。

## §3（D03）[音楽]混入と文の断片化
- **症状**: 字幕ブロックに `[音楽]` が混ざり（7-24: 268/1199ブロック）、文が任意の位置で切れる。
- **対処**: Step1が `[音楽]` 等を除去し、句読点で文を再結合（7-24: 1199ブロック→808文）。極短文（1〜2文字）はゴミの可能性が高く、doctorが件数を出す。**textにノイズ表記を残したまま引用しない**（抽出プロンプトでも禁止済み）。

## §3-2（D03）字幕フォーマットの混在（SBV / SRT / SRT.txt）
- **症状**: 時期によって字幕が `.ja.sbv.txt` だったり `.ja.srt` だけだったり `.ja.srt.txt` だったりする。SBVが存在しない回がある（例: 2023-01-23）。
- **影響**: SBV前提の処理では**過去ログの字幕が1本も読めない**。
- **対処**: Step0が形式を自動判別し、Step1はSBV/SRT/VTTのいずれでも処理する（両方あればSBV優先）。採用形式は `meta.json` の `subtitle_format`、およびdoctorのD03所見に表示される。
- **付随対応**: YouTube自動字幕のSRTは「前のキューを含んだまま伸びる」ローリング重複を持つことがある。直前と完全に前方一致する場合のみ差分だけを残す処理を入れてある（「しずくは特別ですから。しずくは?」のような**正当な繰り返しは保持**される）。

## §4（D04）字幕に写らないイベント（不備ではなく仕様）
- **症状**: 非言語音（舌打ち・鳴き真似・いびき・笑い声・声質転換）は**構造的にASRに写らない**。該当箇所の字幕は空白・`[音楽]`・ゴミ文字になる。実例: 8-02の36:55〜37:24、チャット爆発中に字幕29秒沈黙。
- **対処**: 欠陥として直そうとしない。Step1の**「字幕沈黙×チャット密集」ミスマッチ検知**が受け皿で、抽出プロンプトはこの区間をチャット反応から拾うよう指示済み。逐語は常に試聴で確定（ここは特に）。

## §5（D05）ソースの網羅性 — 本体アカだけでは足りない
- **症状**: 現行XログはしずくAI本体（@Shizuku_AItuber 2641/2641件）のみ。しかし年表の2023〜25年の出典は**あき先生アカ（@cumulo_autumn）と外部記事が中心** — つまり過去と同型の出来事が今も本体ログの外で起きうる。
- **対処**: 取得対象に (1) あき先生アカ (2) メディア掲載（スキルの media-coverage 運用が受け皿）を追加する。追加したTSVは同じ場所（`data/raw/x/`）に置けば、Step1が投稿者ごと取り込む（doctorが投稿者内訳を表示）。
- **注意**: 引用RT（QUOTE_RETWEET）の `引用内容` 列には既にあき先生の文面が一部含まれる。掛け合い素材としては使えるが、あき先生側の**単独ポストの網羅**にはならない。

## §6（D06）期間ギャップと「なし」型の空記録
- **症状**: `2025.txt` の中身は「なし」— TSVとして読めない。また月別0件の期間が出うる。
- **判断**: 2025年は**休眠期なので0件が正しい**（wiki既載の事実と整合）。それ以外の0件月は取得漏れを疑う。doctorが月別件数（実測: 2026-01:233 / 02:1148 / 03:773 / 04:396 / 05:91）と欠落月を出すので、カレンダー上の出来事（配信告知など）と突き合わせる。
- **対処**: 「なし」ファイルはそのまま置いてよい（記録として価値がある）。取得漏れなら再エクスポートして `data/raw/x/` に追加 → Step1再実行（post_id重複は自動排除）。

## §7（D07）ファイルの完全性
- **症状**: 4点セット（字幕 / live_chat / info / comments）の欠落、UTF-8で読めない文字、CRLF混在。字幕はSBV・SRTのどちらか1つあれば充足と判定する。
- **対処**: 種別ごとに重要度が異なる（字幕=ERROR / チャット・info=WARN / **コメント=INFO**）。元動画にコメントが無いのは普通なので、コメント欠落は既定で `[OK]` 扱い。
- **空ファイルを作らないこと**: 「取得済みで0件」と「未取得」が区別できなくなる。恒久的に存在しないものは `config/known_absent.tsv` に理由つきで登録する（報告から消え、理由が記録として残る）。s0/doctorが貼り付け用の候補行を出力する。文字コードは自動で置換継続されるが、件数が多い場合は取得手順を確認。CRLF/BOMは全パーサが吸収済み。

## §8（D08）チャット匿名化とASRのねじれ
- **症状**: チャットは `@User_ハッシュ` に匿名化済みだが、しずくの**音声側は視聴者名を読み上げる**ことがあり、字幕に名前の断片が残りうる。
- **対処**: wikiの現行様式は視聴者名を出さない（【ご主人様のコメント】方式）ので運用上は問題なし。名言起草時に字幕由来の固有名詞（ユーザー名らしき語）が混ざったら伏せる。逆方向の注意: 匿名IDをwikiに書かない。

## §9（D09）概要欄テンプレの揺れ
- **症状**: 概要欄テンプレは時期で変わる（4-26は旧テンプレで定型例文なし）。「新規行」検知は基準線を最初の1本から育てるため、**運用初期はテンプレ整備分も新規行として出る**（実測: 5-24で13行）。
- **対処**: 仕様として理解して読む。新規行はあくまで**候補提示**で、採用はパケットのチェックで決まる。数配信で落ち着く。

## §10（D10）チャットの負時刻・順序
- **症状**: 配信開始前の待機チャットは負時刻（例: `[-35:59] 最新のギャル語大丈夫そ？`）。まれに時刻の逆行。
- **対処**: 仕様。負時刻も保持される（開始前の期待感は文脈として有用）。タイムラインでは時系列順に整列済み。逆行が大量なら取得ツール側を疑う。

## §11 コラボ回の話者分離（将来の既知課題）
- **症状**: 自動字幕は話者を区別しない。コラボ配信では発話の帰属が崩れる。
- **対処**: 現コーパスはソロ配信のみ。コラボ回が来たら、(1) 抽出プロンプトに「話者不確かならspeakerを『不明』にする」を足す (2) 名言は試聴時に帰属確認、で運用する。恒久対応（話者分離モデル）はモデルB以降の課題。

## §13（D12）OCR復元チャット
- **症状**: ライブチャットのデータが残っていない配信について、映像のチャット欄を文字起こしして復元したもの（`*.live_chat_ocr.txt`）。実測（2026-03-03 全肯定ASMRアーカイブ）: 367件、時刻は**15秒グリッドに量子化**、ユーザー名は `@:` で空、OCR誤字あり（例:「ブ・ソリューション・スタジオミセママパンパカポー」「[?]をしまして」）。
- **影響**: (1) 逐語引用に使うと誤字がwikiに載る (2) 件数・時刻の精度が実チャットと異なるため、バースト密度をそのまま比較できない (3) 画面に映っていた分しか復元できないため**件数は下限値**。
- **対処**: 取り込みは可能（実チャットがあればそちらを優先）。ただし
  - パック冒頭に自動で警告文が入る。
  - **ingestがOCR由来の `verbatim: true` を機械的に却下**する（`⚠ OCR復元チャットのため逐語不可 → verbatim=false`）。名言の【ご主人様のコメント】側にOCRチャットは使えない、と考えてください。使いたい場合は映像を見て人間が書き起こす（＝ゲート1と同じ扱い）。
  - doctorがD12で件数と粒度を報告。
- **命名の注意**: ファイル名に**別の動画IDを含めない**こと。`_SulrjdfVDV0.live_chat_ocr.txt` のような2つ目のIDは誤帰属の原因になる。現状は「1フォルダ1 info.txt」規則で防ぎ、`要確認`に警告を出す。

## §14（D13）アーカイブ再アップ（投稿日 ≠ 出来事の日）
- **症状**: 元ライブが保存破損などで失われ、後日アーカイブとして別動画IDで再アップされる。実例: 2026-02-28 `qcqC3McRRX4`（破損・チャット無し） → 2026-03-03 `zZDlC3BcQ2M`（アーカイブ、チャットはOCR復元）。
- **影響**: **年表に誤った日付の行が生まれる**。「2026年3月3日：全肯定ASMR配信を実施」は事実に反する。放置すると出典URLと日付の食い違いとして後から発見しづらい。
- **対処**: `config/stream_relations.tsv` に `archive_of` を宣言する。s1がmetaに `event_date` を持たせ、s2_packが指示文を出し、**s2_ingestがカードの日付を自動補正**する（`upload_date` に元の投稿日を保持）。
- **補足**: 破損した元配信そのものは削除しないでください。配信が行われた事実・日付の根拠であり、`known_absent.tsv` に「チャットは破損」と登録しておけば警告も出ません。wikiに出典を書く際は、視聴可能な**アーカイブ側のURL**を使い、日付は元配信日にするのが正確です。

## §12 リポジトリの命名規則の揺れ（取り込み時）
- **症状**: 時期によって命名が異なる。(a) フォルダ名に動画IDが無くファイル名が `{動画ID}.*`、(b) フォルダ名とファイル名の両方がフルタイトル`_{動画ID}`、(c) Windows対応で短縮した新形式、が混在する。移行途中は同一リポジトリ内に3種が同居する。
- **対処**: Step0は**`info.txt` の「動画ID」「投稿日」を正**とし、フォルダ名・ファイル名は補助情報としてのみ使う。よって**リネームを戻す必要も、移行を中断する必要もない**。両者が食い違う場合は `info.txt` を採用し「要確認」に警告を出す。
- **確認方法**: `python scripts/s0_intake.py --src <リポジトリ> --dry-run --verbose`。取り込み後は各配信フォルダの `origin.json` に出所（元パス・採用した字幕形式）が記録される。
- **付随する運用上の注意**: フルタイトルをフォルダ名とファイル名の両方に持つ形式はパスが長く、Windowsの260文字制限に触れやすい。`git config --global core.longpaths true` を推奨。日本語や全角記号（`？` `【】`）自体は問題にならない。
