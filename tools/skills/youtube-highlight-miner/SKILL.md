# YouTube配信ログ → 配信分析台帳・ハイライト採掘スキル (v1.4.1)

## 目的と他スキルとの棲み分け

投げられた配信ログから、ファンや編集者が「見返したい・切り抜きたい・記録したい・複数配信を横断してAIに分析させたい」ポイントをタイムスタンプ付きで抽出し、**`&t=秒s` 付きURL** と **関連する Fandom Wiki ソース** を添えて **配信分析台帳（`<動画ID>.highlights.compiled.md`）** や Discord 共有用一覧に整理する。

- **`youtube-timestamp-comment` との違い**: コメント欄用の目次ではなく、Discord 共有・切り抜きネタ出し・Wiki 追記素材・動画フォルダ内の分析台帳向けのスキル。
- **サイズ設計（肥大化防止）**: 複数台帳をまとめてAIに読み込ませる前提で、**1配信あたり合計20〜25項目目安（4〜6KB / 100〜150行前後）** に収める。字幕・チャットの全文再掲や長文の読み物（オブザーバーノート等）は含めない。
- **知見の蓄積**: 分析で得られたしずくの用語・ネタ・技術的特徴は [しずく知見ベース](references/shizuku-knowledge.md) に、分析済みログの進捗は [分析済みログ一覧](references/analyzed-logs.md) に記録して重複分析を防ぐ。

## ワークフロー

### Step 1: 入力確認と前処理

1. 入力ファイルのキーワードを確認する：
   - **メタデータ**: `*info*.txt`, `*comments*.txt`
   - **画面字幕OCR（最優先で本文参照）**: `*screen-ocr*.txt` — 配信画面に表示された字幕テキストのOCR結果。YouTube音声字幕（`sbv`/`srt`）より文章の意味合い・漢字変換・固有名詞・語尾の正確性が高いため、**AI語・AI特有の言い間違いとASR誤認を切り分ける主軸**として使う。
   - **音声字幕（時刻基準）**: `*sbv*.txt`（優先）、無ければ `*.srt`（フォールバック）。
   - **比較用ASR**: `*qwen3-asr*.txt` — TTSの実際の読み上げ崩れ（音声側でどう聞こえたか）を確認する補助として使う。
   - **チャット**: `*live_chat*.txt` または `*chat*ocr*.txt`。
2. 同梱の `scripts/mine_highlights.py` を実行し、動画ID・ベースURL・`condensed.txt`・`timeline.txt`（`screen-ocr` 統合対応）・AI語スパイク（🟢高確度 / 🟡候補）・物語候補区間を出力する。

```bash
python3 scripts/mine_highlights.py <入力ディレクトリ> [--video-id <動画ID>] --out-dir /tmp
```

### Step 2: 通読と6カテゴリの採掘（合計20〜25項目目安）

`/tmp/condensed.txt` および `screen-ocr.txt` を通読し、チャット反応・事後コメント・初出性が高いものを優先して以下を抽出する（詳細は [抽出・照合ガイド](references/extraction-guide.md) 参照）。

1. **プロフィール・性格・個性（`profile_fact` / トレイト）**:
   - **新規**（初出の設定・好み・価値観）、**強化**（既存特性の裏付け）、**揺れ・矛盾**（既存設定と食い違う点＝`【要確認】`）に分類して1〜2行で記す。
   - その場の生成で変動しやすい好み等には `[TTL: 短期]` を付記し、**自発発言** か **視聴者誘導への返答** かを区別する。
2. **機能・システム挙動（`capability`）**: 新機能の実演、プロンプト・記憶・語尾制御などの仕様観察、TTS/ASRの特徴。
3. **癖・口癖・反応パターン**: 配信中に繰り返された口癖や特有のリアクション。
4. **AI語・謎言語・言い間違い（2段階出力＋OCR3層照合）**:
   - **`screen-ocr.txt` との照合ルール**: 音声字幕（`sbv`）が崩れていても、`screen-ocr.txt` が正常な日本語・英語であれば「ASR誤認」または「TTS読み上げ崩れ（発音問題）」と切り分け、AIテキストバグと誤認しない。逆に `screen-ocr.txt` 上でも崩れている・語尾が残存している箇所は、真のAIテキスト挙動として拾う。
   - **🟢 高確度**: 3人以上が同時に「なんて？ / AI語」反応（＋他言語質問なし）、または `screen-ocr` 上で明確な生成崩れ・語尾残存が確認できる箇所。
   - **🟡 候補（ASR誤認・TTS発音崩れ・他言語返答の可能性あり）**: 1〜2人反応や音声字幕のみの崩れ。
   - 他言語字幕が出たときは直前 30〜60 秒のチャットに質問（「英語で」「中国語話せる？」等）がないか確認し、**断定せず観測ベース**で書く。
5. **名言・迷言**: 本人の発言「」引用（`screen-ocr.txt` がある場合は画面表記を優先）と、自発／誘導の文脈。
6. **一連の流れ・物語 ＆ 未回収ネタ（`open_loop`）**:
   - 物語区間は `MM:SS〜MM:SS` で起承転結を整理。
   - 後日回収されうる宣言・定型ネタ・関係マーカーには `open_loop` として「期待シグナル（何が起きたら回収か）」を1行添える。

※時刻は必ず `/tmp/timeline.txt`（`sbv`/`screen-ocr`）で裏取りし、**オチの瞬間ではなく 1〜5 秒前のフリ**に合わせる（`&t=<秒数>s`）。OCR復元チャットのみの場合は時刻を例外なく字幕・OCR側で確定し、チャットの文字列を裏取りに使わない。

### Step 3: Fandom Wiki ソースの照合

抽出したエピソード・固有名詞・過去ネタについて、[しずく知見ベース](references/shizuku-knowledge.md) および利用可能な Wiki データ（`api-result.json` や Web 検索）で関連する Fandom Wiki を確認する。該当ページがあれば**タイトルと実在 URL** を添え、確認できない場合は「Fandomソース: 該当ページ未確認」と記載する（URL 捏造禁止）。

### Step 4: 出力形式・文字数調整・台帳ファイル出力

1. **動画台帳ファイル出力（`<動画ID>.highlights.compiled.md` / `.zip` 配布フォールバック）**:
   - リポジトリの配信フォルダ（`logs/youtube/<YYYY>/<YYYY-MM-DD_タイトル>/`）で管理する場合は、**`<動画ID>.highlights.compiled.md`** のファイル名で出力する（`<動画ID>.*` 命名規則＋AI生成物と一次資料を区別する `.compiled.md` 規則に準拠）。
   - **ダウンロード時のファイル名保持ルール**: 環境によって `.md` を直接ダウンロード・プレビュー（Canvas等）すると `.` やハイフン・大文字が `_` と小文字へ変換される場合がある。`.` 区切りのまま直接ダウンロードできる環境では `.md` をそのまま渡し、変換されてしまう場合は **`<動画ID>.highlights.compiled.md` を格納した `<動画ID>.highlights.compiled.zip`** を作成してダウンロード用に提示する（閲覧用の `.md` 表示と併用可）。
   - ファイル冒頭には、動画ID・タイトル・URL・公開日・生成日時・`資料種別: AI生成・未確認`・参照した一次資料一覧・注意書きを記載する（テンプレートは [抽出・照合ガイド](references/extraction-guide.md) §6 参照）。
2. **チャット出力（既定: Discord 埋め込み形式）**: `[MM:SS](<URL>)` でプレビュー展開を抑制し、2,000 文字を超える場合はカテゴリ単位で複数コードブロックへ分割する。

- **禁止事項**: 字幕の誤変換を事実や AI 語バグとして断定しない。チャットのユーザー名を出力に含めない。未確認の Fandom URL を捏造しない。一次ログを書き換えない。
