# 抽出基準・Fandom Wiki照合・出力フォーマットガイド (v1.3.0)

## 1. 4つの抽出カテゴリと採掘基準

| カテゴリ | 採掘する対象 | 記載のポイント |
|---|---|---|
| **① 癖・口癖** | 配信特有の言い回し、反応パターン、頻出フレーズ（例: 「はい、ご主人様。」、語尾変化、特有の笑い方） | 単発ではなく「この配信で何度も出た傾向」や初出・代表シーンをまとめる |
| **② AI語・謎言語・言い間違い** | 自動字幕の崩れ＋チャット反応、または `screen-ocr.txt` 上の生成崩れ・語尾残存 | **🟢高確度 / 🟡候補** に分け、`screen-ocr.txt` と照合して ASR誤認・TTS発音崩れ・LLM生成崩れを切り分ける（下記2章参照） |
| **③ 名言・迷言** | 配信者本人のキラーフレーズ、ツッコミ、愛のある暴言、心に残る一言 | `screen-ocr.txt` がある場合は画面表記を優先して「」引用し、その一言が出た文脈・フリを短く添える |
| **④ 一連の流れ・物語** | 前振り→展開→オチが繋がったエピソード（切り抜き・振り返り向け） | 単一時刻ではなく **`MM:SS〜MM:SS` の区間** で示し、起承転結の要約と引き金時刻を付ける |

## 2. `screen-ocr.txt` 活用と AI語・謎言語の切り分けルール

音声字幕（`sbv` / `srt`）のみでは、「本人の生成バグ（AI語）」と「YouTube自動字幕（ASR）の誤字」「TTS（COEIROINK等）の発音崩れ」を区別しにくい。`screen-ocr.txt` がある場合は以下のルールで高精度に切り分ける。

1. **3層照合による切り分け**:
   - **ケースA（YouTube ASR誤認）**: `sbv` が崩れているが、`screen-ocr.txt` は正しい日本語・英語（例：`sbv`「炎上」「4判子や第3電話」「長さ博士」→ `screen-ocr`「林業」「四暗刻や大三元」「阿笠博士」）。→ **AI語としては誤爆扱いとし、拾わない（またはASR誤認と注記）。**
   - **ケースB（TTS読み上げ崩れ）**: `screen-ocr.txt` は正しいスペルだが、TTSが変な発音をしてチャットや開発者がツッコんでいる（例：画面は `Call of Duty: Modern Warfare` だが音声が崩れて「名前言えてなくて草」反応）。→ **「画面テキストは正常、TTS読み上げ崩れ」として観測ベースで記録。**
   - **ケースC（真のAI生成崩れ・言い間違い）**: `screen-ocr.txt` 上でも文字が崩れている、または語尾初期化後も前語尾が混ざる・文脈が破綻している（例：初期化後に「うっぴっ…ぴ…うーん!」が残存、`goeにやん` 等）。→ **🟢高確度（または要耳確認付きの特記）として記録。**
2. **2段階の確度ランク分け（両方出す）**:
   - **🟢 高確度（ほぼ確実）**: チャットで **3人以上** が同時に「`なんて？` / `AI語` / `バグ`」と反応し、直前に他言語リクエスト等の別理由がない箇所、または `screen-ocr.txt` で明確な生成崩れ・語尾残存が確認できる箇所。
   - **🟡 候補（要確認・ASR誤字やTTS崩れ・他言語返答の可能性あり）**: チャット反応が 1〜2 人のみ、または音声字幕だけ不自然に崩れている箇所。
3. **直前 30〜60 秒の他言語フリ除外チェック**:
   - 英語・中国語等の非日本語字幕が出たときは、直前 30〜60 秒のチャット欄に「英語で話して」「中国語話せる？」等の質問がないか確認する。質問があれば AI 語バグと断定しない。
4. **「断定」ではなく「観測（現象ベース）」の書き方**:
   - ❌ 断定: `〜の途中で謎のAI語が混入` / `突然の中国語風AI語`
   - ⭕ 観測: `チャットに「なんて？」反応あり（ASR誤認またはTTS崩れ候補）`
   - ⭕ OCR確認済み: `画面字幕上でも「〜」となっており、語尾初期化後も前語尾が残存`

## 3. タイムスタンプ精度（1〜5秒前のフリ調整）

- 時刻は必ず字幕（`sbv` / `srt` / `screen-ocr`）側で確定する（OCR復元チャット時は特に厳守）。
- ジャンプしてすぐ状況が分かるよう、オチの瞬間ではなく **1〜5秒前のフリ・会話の入り** の時刻を採用する（`&t=<秒数>s`）。

## 4. Fandom Wiki ソース照合のルール

抽出したネタ・用語・関係性・過去配信への言及について、Fandom Wiki（`references/shizuku-knowledge.md` や `api-result.json` 等）に背景情報・出典ページがあるか確認する。

- 該当ページが確認できた場合は、**ページタイトルと実際の URL** を紐づける。
- 検索で確認できていない Fandom URL を推測・生成しない。ネット未接続環境や該当記事がない場合は `Fandomソース: 該当ページ未確認` と正直に記載する。

## 5. 出力形式と文字数分割（Discord対応）

- **Discord 埋め込み形式（既定）**: `[MM:SS](<https://www.youtube.com/watch?v=ID&t=秒s>)`（`< >` でプレビュー展開を抑制）。
- **生 URL 一覧 / Wiki 編集用テーブル**: 依頼に応じて切り替え可。
- **Discord 2,000 文字制限**: 超過する場合はカテゴリ単位（`[1/2]` `[2/2]`）でコードブロックを分割する。

## 6. 動画台帳ファイル出力（`<動画ID>.highlights.compiled.md`）

配信フォルダ（`logs/youtube/<YYYY>/<YYYY-MM-DD_タイトル>/`）内でハイライト台帳として管理する場合は、以下の規則でファイルを作成する。

- **ファイル名**: `<動画ID>.highlights.compiled.md`（例: `YuJ4oOGNGxg.highlights.compiled.md`）
  - `<動画ID>.*` の配置規則に揃えつつ、一次資料（`.info.txt`, `.sbv.txt`, `.screen-ocr.txt`, `.live_chat.txt` 等）と AI 生成の集計・要約ファイルを明確に区別するため `.compiled.md` を付与する。
- **必須ヘッダ項目**:

```markdown
# <動画ID> ハイライト・タイムスタンプ台帳

- **動画ID**: `<動画ID>`
- **タイトル**: `<配信タイトル>`
- **URL**: https://www.youtube.com/watch?v=<動画ID>
- **公開日**: YYYY-MM-DD
- **生成日時**: YYYY-MM-DDTHH:MM:SS+09:00
- **資料種別**: AI生成・未確認（`youtube-highlight-miner` v1.3.0 による抽出・整理）
- **参照した一次資料**:
  - `<動画ID>.info.txt`
  - ...

> ※自動文字起こし・画面OCRをもとに作成したタイムスタンプ台帳です（ネタバレ・ズレ・OCR/ASR誤認識を含む可能性があります。逐語確定には元動画の視聴が必要です）。
```
