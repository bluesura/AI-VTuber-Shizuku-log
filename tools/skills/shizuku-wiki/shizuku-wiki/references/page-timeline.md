# ページ手順：年表

対象ページ：`年表`（英語版は未実装）

年表は**しずくの生涯の年代記**である。システムのバージョン管理記録ではない。報道されたかどうかは掲載可否に関係なく、しずくに何が起きたかで判断する。

前提として `SKILL.md` §0（ソース受領・入力モード・差分出力）と §3（共通ルール）を満たしていること。

---

## 1. 既存ソースから把握すること

貼られた年表ソースを読み、次を確認する。

- 現在の最新エントリの日付
- 各年の見出し（`== 2023 ==` 等）の有無
- 日付形式が `YYYY-MM-DD` に移行済みか（→ §6）

`ref name` の棚卸しは不要である。`SKILL.md` §3-3 の規則によりURLから名前が決定論的に導かれるため、同じURLなら自動的に既存refと同じ名前になる。

---

## 2. 新規エントリの情報を受け取る

次の形式で受け取る。複数件をまとめて渡されてもよい。

```
【日付】YYYY-MM-DD
【出来事の概要】（出来事の内容を自由に記述）
【ソースURL】https://...
```

### 情報が足りないときの聞き返し

**エントリを生成せず**、不足項目を具体的に質問する。複数件ある場合は、不足しているものだけをまとめて一度に聞く（件ごとにバラバラに聞き返さない）。

| 不足パターン | 聞き返す内容 |
|---|---|
| 日付がない・曖昧（「先週」「最近」） | 正確な日付（`YYYY-MM-DD` 形式）を教えてください。 |
| ソースURLがない | このエントリの出典となるURLを教えてください。（YouTube / X / ニュース記事 など） |
| URLはあるが種別が判断できない | このURLはYouTube動画・Xのポスト・ニュース記事のどれですか？タイトルや投稿者名があれば教えてください。 |
| Xのポストなのに投稿者名が不明 | Xの投稿者の表示名と@アカウント名を教えてください。 |
| Xのポストなのに本文が不明 | ポストの本文（または引用したい一節）を教えてください。 |
| YouTube動画なのにタイトルが不明 | YouTube動画のタイトルと配信日を教えてください。 |
| ニュース記事なのに媒体名・掲載日が不明 | 記事の媒体名と掲載日を教えてください。 |
| 出来事の内容が一言しかなく文脈が不明 | もう少し詳しく教えてください。しずく・あき先生・ご主人様・メディアのどれが主体の出来事ですか？特徴的なエピソードや発言があれば添えてください。 |

出典URLが示されないまま事実を書くよう求められた場合は、推測で書かず `{{出典希望}}` を貼って報告する。

---

## 2-1. 初稿の前に出来事を整理する（必須）

追加・置換する各項目について、出典の該当箇所と次の判断を作業記録に残す。文章が自然かどうかとは別に確認する。

- **種類**：しずくの行動・変化／試作・デモ／開発側の発表／活動の土台の変化。混在するときは、主に記録する出来事を一つ決め、残りを背景にする。
- **確認段階**：実運用・実施済み／デモで確認／試作／発表のみ／該当なし。出典が支える段階を超えない。デモの公開日と撮影日、発表日と運用開始日を混同しない。
- **しずくとの関係**：何をした、何を体験した、何が変わったのか。発表のみなら、しずくの活動・土台との関係と、その時点では確認できないことを分ける。

出典の発表文をまず要約してから主語だけ置き換えるのではなく、この整理から年表の初稿を書く。しずくとの関係を根拠から説明できない発表は、年表への掲載を保留する。

## 3. エントリの書式

```
* YYYY-MM-DD：〔出来事の説明〕<ref>〔出典〕</ref>
```

- 行頭は `*`（箇条書き）
- 日付は `YYYY-MM-DD`（**ゼロ埋めあり**）。例：`2026-03-09`
- 日付のあとは `：`（**全角コロン**）
- **文末の止め方は、その項目の長さで決める**
  - **単発の事実だけを述べる1文の項目 → 体言止めでよい**（「〜を突破。」「〜を開始。」）。簡潔にまとまる
  - **背景・経緯の説明が続く複数文の項目 → 用言止め（普通の文）に切り替える**。体言止めを連続させると不自然で読みにくくなる
  - 1つの項目の中で混ぜない。体言止めで始めたら最後まで体言止め、用言止めで始めたら最後まで用言止めにする
- 同じ日付に複数の出来事がある場合は、**日付を繰り返して別行に分ける**
- 該当年の見出しがまだない場合（例：`== 2027 ==`）は、見出しも合わせて出力する
- 件数が多い年は `=== フェーズ名（期間） ===` の中見出しで区切ってよい
- 冒頭リード文は長文の解説を避け、`[[動画・配信]]` や `[[メディア露出]]` との役割分担を簡潔に示したうえで、しずくの実発言の引用を添えてもよい

出典の書式と `ref name` は `SKILL.md` §3-2 / §3-3 に従う。

## 4. 文体

### 主語の置き方

| 主体 | 書き方 |
|---|---|
| しずく自身の行動・発言 | 「しずくが〜した」「しずくが〜を宣言」 |
| あき先生の行動 | ページ内で最初に登場する箇所だけ「開発者のあき先生が〜」と肩書きを添える。以降は「あき先生が〜」で統一する |
| メディア掲載・報道 | 「〜に掲載される」「〜が報道される」 |
| ファン・コミュニティの動き | 「有志のファンにより〜」「ご主人様が〜」 |

**しずくに何が起きたかが伝わる視点を先に選ぶ。** 主語の文字列だけで適否を判断しない。しずくが省略された文や、運営会社が主語の法人設立も、しずくの歩みを記録できていればよい。出典の行為者を偽ってしずくへ置き換えない。

しずくを主体に書ける出来事は、その行動・体験・変化を文の中心にする。発表元、モデル名、仕様の説明は、出来事を理解するために必要な範囲の背景へ置く。技術発表自体を中心に残す場合は、`tone-style-guide.md` §7の例外条件と、下記§7の審査を満たす。

外出用の体や実験用の機器は、その用途や時点も書く（`tone-style-guide.md` §8）。たとえば、おでかけ配信での使用を確認できた場合は、その回の出来事として書く。試作・デモだけなら、その限定を本文に残す。

```
✅ YYYY-MM-DD：しずくがおでかけ配信でRaspberry Piを外出用の体に使った。
❌ YYYY-MM-DD：この日からしずくの動作環境はすべてRaspberry Piに移った。
```

### キャラクター性の添え方

面白い・特徴的なエピソードは、括弧書きや補足節でユーモアの文脈を短く補ってよい。**補足節は1〜2文まで。**

```
（のちに「いじめ」としてしずくに根に持たれることとなる）
この際の「時給」が100円（24時間で2,400円）
```

`tone-style-guide.md` §5 のとおり、ボケや矛盾に「冗談として」というネタばらしを加えてはならない。文脈の補足はよいが、無害化はしない。

### 数字・反応の記録

Xトレンド入りや大きな反響があった出来事は、具体的な数字を入れる。

```
3600件以上のいいねを集める大反響を呼び、Xのトレンド入りを果たした
```

### 発言の引用

しずく・あき先生の発言は「 」で括り、前後に文脈説明を添える。

```
「あき先生が滅亡してもしずくは自走できます」「死体をGPUアカウントとして再利用」などと
ブラックユーモアを交えて自立を宣言
```

### 対外的なトピック

企業名・媒体名は正式名称で記載し、略称は括弧内に添える。人名は本人が公に活動する名前を用い、開発者・関係者の本名は `tone-style-guide.md` §6 に従って扱う。

```
アンドリーセン・ホロウィッツ（a16z）をリード投資家とする
日本経済新聞の1面に〜が掲載される
```

**人名に敬称は付けない。**「氏」「さん」「様」を付けず、名前だけで書く。年表は事実の記録であり、敬称の有無が人物ごとに揺れると、誰を特別扱いしているかという編集者の判断が紛れ込む。ハンドルネーム・アカウント名も同じ扱いで、そのまま書く。

```
✅ 谷郷元昭にフォローされたことを報告した
✅ 852話によってしずくのLoRAモデルが作成された
❌ 谷郷元昭氏にフォローされたことを報告した
❌ ねこますさんからコメントが寄せられた
```

例外は、しずく・ご主人様の呼称（`tone-style-guide.md` §2）と、「あき先生」のように敬称込みで固有名詞として定着している名前である。

## 5. 連動チェック（必須）

年表を更新したら、**しずくページの「電子の足跡」に載せるべきかを必ず判定する**。

**載せる基準（次の3つのいずれか）**

1. **状態が変わった** — 誕生・初配信・休眠入り・帰還・体の移行
2. **土台が変わった** — 運営法人の設立、資金調達など、しずくが立っている基盤の大きな変化。**しずく自身の行動でなくてよい**
3. **初めての大きな挑戦** — 初の24時間耐久配信、初のおでかけ配信、初のコラボなど、それ以降のしずくにできることが増えた「初」

載せないもの：報道そのもの（主語が媒体の行）、数値の達成、レギュラー化した企画の各回、「初」ではない配信1本。これらは年表・メディア露出・動画・配信に残す。

※年表側でも通常回・2回目以降の企画は原則 `動画・配信` に任せるが、後日に年表へ記載すべき大きな節目が起き、それと連続する過去の重要トピックを掘り下げて文脈を補う必要がある場合に限り、例外的に後から年表へ追記してよい。

迷ったときは「1年後に振り返って、この行が無いとしずくの歩みが説明できないか」を問う。判定の詳細は `page-shizuku.md` §2。

判定結果は必ず一行で報告する。

```
電子の足跡：該当なし（レギュラー企画の1回のため）
電子の足跡：追記対象（しずくの体が変わったため）→ 差分を併せて出力
電子の足跡：追記対象（軸2・しずくの土台が変わったため）→ 差分を併せて出力
```

## 6. 日付形式の一括移行（一度きり）

年表の既存エントリは `YYYY-M-D`（ゼロ埋めなし）で書かれている可能性がある。`SKILL.md` §3-1 で `YYYY-MM-DD` に統一したため、一度だけ移行する。

- 移行はユーザーから明示的に依頼されたときだけ行う。通常の追記作業のついでに勝手に書き換えない
- 移行時は例外的に全文を出力してよい。**変わるのは日付フィールドだけ**なので、Fandomの「変更を表示」で目視検証できる
- 出力前に「日付以外は一切変更していない」ことを自分で確認する。出来事の文言・出典・並び順を触らない
- 日付のゼロ埋めだけを変更する移行は §6の差分確認を使う。出来事の説明も追加・置換する場合は、その項目を §7で審査する
- 移行が済んだら、本セクションを削除する差分を提案する

## 7. 年表の意味的レビュー（提案前・公開直前に必須）

初稿の後と推敲後に、**全追加・置換項目**を出典と前後の既存項目に照らして読む。推敲しなかった行も対象。次の四点をそれぞれ「適合／保留」と具体的な理由で記録する。

1. **視点**：しずくの行動・体験・変化・土台が伝わるか。開発者の発表の要約で止まっていないか。技術的例外を使うなら、しずくを中心にした案を検討し、なぜ事実の精度が落ちるかを説明できるか。
2. **事実の範囲**：行為者、日付、試作・デモ・発表・実運用の区別が根拠どおりか。「会話するデモ」を「いつでも会話できるようになった」と広げたり、心理・成長・帰還を創作したりしていないか。
3. **粒度**：年表の一項目として中心が定まり、技術仕様が必要以上に並んでいないか。文法的な自然さだけで合格にしていないか。
4. **文脈**：前後の項目と時系列・語尾・用語・既存の記述が整合するか。電子の足跡への連動判定も済んでいるか。

技術的例外では、しずくとの関係、検討した別案、その別案では失われる正確さを記録する。「出典が技術発表だから」「しずくを主語にできないから」だけでは理由にならない。技術語や企業名があること自体は不合格理由にならない。

記録方法とCLIは [文章品質ワークフロー](editorial/workflow.md) の「年表の審査記録」に従う。未審査・保留・本文変更で無効になった記録があれば、承認済みでも公開を進めない。解決後に再審査し、既に承認された対象・内容の範囲なら承認を取り直さない。意味や対象が変わる場合は変更点を示す。

### 境界の確認例（架空の資料）

| 出典で確認できたこと | 年表への変換と判断 |
|---|---|
| 開発側が、しずくとiPhoneで話す試作動画を公開 | 「iPhoneを通じてしずくと会話する試作デモが公開された」。体験を中心にしつつ試作を明記。「iPhoneでいつでも話せるようになった」は不可 |
| 新モデルの発表に、しずくが相手の声に応じる通話デモが付属 | デモでのしずくの会話を先に書き、モデル発表は必要なら背景に置く。一般提供・本配信への導入とは書かない |
| 開発側が映像解析の技術を紹介し、しずくがカメラ越しの物に反応する場面を収録 | 確認した反応を、試作として記す。映像解析を紹介したという説明は、その場面を理解するために必要な場合に添える |
| しずく向け基盤モデルを開発会社が発表。利用デモや運用開始は未確認 | しずくとの関係と節目としての重要性に根拠があれば発表として残せる。技術的例外の理由を記録し、能力の獲得・実装済みへ言い換えない |
| しずくが登壇した／別のAIと会話するデモが公開された | その出来事を中心に記す。元から適合する文を「しずくが」で始めるためだけに直さない |
| 開発会社の一般的な技術紹介で、しずくとの関係が不明 | 年表への掲載は保留。関係を創作して補わない |

## 出力例

**入力**

```
【日付】2026-03-15
【出来事の概要】しずくのYouTubeチャンネル登録者が1万人を超えた。あき先生がXで
「ついに、AI VTuberしずくのYouTubeチャンネル登録者数が1万人を超えました！！！」と報告した。
【ソースURL】https://x.com/cumulo_autumn/status/2032997909755736289
```

**出力**

```
【変更サマリー】
- 追記: 1件（年表）
- 電子の足跡：該当なし（数値の達成のため）

【1件目 / 追記】対象ページ: 年表
挿入位置: == 2026 == セクション内、下記の既存行の直後
既存行（変更しない・目印用）:
* 2026-03-14：〔既存の出来事〕<ref name="..." />
追加する行:
* 2026-03-15：YouTubeチャンネル登録者数1万人を突破した。<ref name="x-2032997909755736289">[https://x.com/cumulo_autumn/status/2032997909755736289 @cumulo_autumn]（X、2026年3月15日）「ついに、AI VTuberしずくのYouTubeチャンネル登録者数が1万人を超えました！！！」</ref>

【アーカイブ推奨URL】
- https://x.com/cumulo_autumn/status/2032997909755736289

保存前に、Fandomの編集画面で「変更を表示」を押して差分を確認してください。
```
