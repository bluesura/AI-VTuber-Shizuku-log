# ページ手順：メディア露出

対象ページ：`メディア露出`（英語版は未実装。作成する場合は `Media Coverage`）

**外部がしずくをどう扱ったかの記録**。年表が「しずくに何が起きたか」を書くのに対し、こちらは「誰がそれをどう報じたか」を書く。主語は媒体である。**Shizuku AI, Inc.／Shizuku AI JAPAN合同会社からの自社発信は外部メディア露出に含めない。**

前提として `SKILL.md` §0（ソース受領・入力モード・差分出力）と §3（共通ルール）を満たしていること。

---

## 0. 入力モード（メディア露出専用・`SKILL.md` §0-2の例外）

`SKILL.md` §0-2 の一般的な既定はモード1（新規情報はユーザーが貼ったテキストから取る）である。動画・配信ページには専用の自動フローがあるが、**メディア露出ページでは新規記事のWeb調査を次のように扱う。**

| 状況 | やること |
|---|---|
| 更新を頼まれ、新規記事のテキスト・URL等が何も貼られていない | 下記の自動調査モードへ |
| 更新を頼まれ、新規記事のテキスト・URL等が貼られている | 通常どおり、貼られた内容から直接差分を作る（自動調査はしない） |

対象ページの**現在のwikiソースを確認する**という `SKILL.md` §0-1 の要件は、このページでも変わらない。メディア露出ページには専用のAPI取得フローがまだないため、既存の掲載状況（最新掲載日・既存の`ref name`）を把握するにはユーザーが貼ったソースを使う。

### 自動調査モードの手順

1. 受け取ったwikiソースの最新掲載日・既存`ref name`一覧から、確認済みの範囲を把握する
2. Web検索で新規の報道・言及を調べる（クエリ例：「Shizuku AI」「しずく AITuber」「a16z Shizuku」等。日本語・英語の両方で行う）
3. 見つかった記事ごとに、本ファイル §1（掲載基準）で掲載可否を判定する。判定理由も残す
4. 掲載候補を、日付・媒体・種別・概要・判定理由が分かる形でレポートとしてまとめ、ユーザーに提示する。**この時点ではまだwikiへの差分にしない**
5. ユーザーが候補を承認したら、`SKILL.md` §5 の差分形式で追記案を出す

日付が特定できない、または一次情報の有無が判断できない記事は、掲載候補から外し、理由とともに報告する（推測で埋めない。`SKILL.md` §0-2 共通ルール）。

## 1. 掲載基準：一次性で判断する

このページの役割は**外部一次ソースの索引**である。したがって判断軸は「しずくが主役かどうか」だけではなく、まず「**Shizuku AI側から独立した外部発信か**」、そのうえで「**その記事に一次情報があるか**」になる。Shizuku AI自身の一次発表は、一次性が高くてもこのページの対象外である。

### 載せる

| 種別 | 定義 |
|---|---|
| ニュース | 記事媒体による報道 |
| 新聞 | 紙面掲載を伴う報道 |
| テレビ・ラジオ | 放送番組への出演・紹介 |
| インタビュー | しずく／あき先生への取材記事 |
| 公式発表 | 投資家・コラボ先・イベント主催者など、**Shizuku AI以外の外部組織**が自らの立場から行う発表 |
| 言及 | しずくが主題ではないが、独自取材の中で扱われたもの |

**この6つ以外の種別を新設しない。** 必要だと判断したら、勝手に作らずユーザーへ提案する。

### 自社発信の扱い

- **Shizuku AI, Inc.／Shizuku AI JAPAN合同会社が発信主体のプレスリリース・公式サイト記事・告知は載せない。** 外部配信プラットフォーム上に掲載されていても同じ。例：Shizuku AI JAPAN合同会社がPR TIMESで配信したプレスリリースは、自社発信なのでメディア露出ではない
- PR TIMES等は「掲載サイト」ではなく**発信主体を確認して判定する**。投資家・コラボ先・イベント主催者など外部組織が発信主体なら、上の「公式発表」として掲載候補になりうる
- 自社発表で新しい出来事が確認できた場合は、内容に応じて `年表`・`動画・配信`・`公式リンク` 等の該当ページへの反映を検討する

### 載せない

- Shizuku AI, Inc.／Shizuku AI JAPAN合同会社による自社発信
- 他媒体の転載
- 独自取材のない後追い記事（同じ発表を追いかけただけのもの）
- 自動生成まとめ・アグリゲータ
- SNSの反応まとめ
- 独自取材のない個人ブログ

判断に迷ったら「この記事にしかない情報があるか」を問う。なければ載せない。索引に後追い記事が並ぶと、一次ソースへ辿り着く速度が落ちる。

### 既存エントリは再審査しない

この基準は**新規から適用**する。過去のエントリを基準に照らし直して削除しない。一人運用では再審査のコストが回収できない。

## 3. テーブルの書式

```
| 日付（JST） | 媒体 | 種別 | 概要 | 出典 |
```

- **並び順は古い日付順**（昇順）。年ごとに `== 2026年 ==` のセクションで区切る
- 日付は `YYYY-MM-DD`。列見出しがJSTなので、**必ずJSTに変換した日付**を入れる
  - 例：a16zの発表は米国時間2026年2月9日 → 日付列は `2026-02-10`、米国時間は注記セクションへ
- 媒体列は媒体名を外部リンクにする：`[URL 媒体名]`
- 概要は1文。テーブルのセルなので**体言止めでよい**（「〜を報道。」「〜を掲載。」）。地の文は述語で終える
- 出典列は `<ref>` を置く。書式と `ref name` は `SKILL.md` §3-2 / §3-3

### 記載例

```
| 2026-03-19 | [https://panora.tokyo/archives/134794/ PANORA] | インタビュー | 開発者であるあき先生へのロングインタビューを掲載。 | <ref name="panora-20260319">[https://panora.tokyo/archives/134794/ 生みの親・あき先生が語るAITuber「しずく」愛]（PANORA、2026年3月19日）</ref> |
```

## 4. 注記セクション

本文テーブルに収まらない補足は `== 注記 ==` にまとめる。

書くもの：

- 現地時間とJSTがずれる場合の対応関係
- 会員限定記事・有料記事であること
- 同じ出来事を扱う記事が複数ある場合の関係（どれが一次か）
- 番組の放送日と配信開始日が異なる場合

## 5. 連動チェック（必須）

報道が**新しい事実**を伝えている場合は、年表にも出来事として1行を追記する。報道そのものは年表に書かない。

```
✅ 年表：2026-02-10：アンドリーセン・ホロウィッツ（a16z）をリード投資家とするシード資金調達を発表した。<ref>...</ref>
❌ 年表：2026-02-10：GIGAZINEがShizuku AIの資金調達を報道した。
```

しずくページの「電子の足跡」には、**報道そのものは載せない**（主語が媒体の行を作らない）。ただし、その報道が伝えている出来事の方は、資金調達のように**しずくの土台を変えるもの**であれば足跡の対象になりうる。判定は `page-shizuku.md` §2 の3軸で行う。

判定結果は必ず一行で報告する。

```
年表：追記対象（資金調達という新しい事実のため）→ 差分を併せて出力
電子の足跡：該当なし（報道のため）
```
