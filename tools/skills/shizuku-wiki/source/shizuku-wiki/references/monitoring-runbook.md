# モニタリング運用手順

Wikiの状態を継続的に把握するための手順書。担当者が交代しても、これを上から読めば同じ運用が再開できることを唯一の品質基準にしている。

**置き場所**：どこでもよい。気が向いたらShizuku LabのDiscordのwiki専用チャンネルに投げておく程度で構わない。ただし、後から誰かが引き継げる形で残っていると望ましい（→ §8）。

---

## 1. このWikiの役割

**一次ソースの索引であること。**

しずくに関する情報は複数の媒体に分散している。

| 媒体 | 役割 | このWikiとの関係 |
|---|---|---|
| 日本語版Wikipedia | 社会的認知の入口。報道ベースの検証済み事実のみ | 競合しない。ヘッドクエリは譲る |
| pixiv百科事典 | ファン用語・ネタ | 補完関係 |
| Virtual YouTuber Wiki | 英語圏の入口 | 補完関係。ライセンス非互換に注意 |
| Grokipedia | AI辞書層。提案形式 | 補完関係 |
| **Shizuku Wiki** | **詳細アーカイブ／一次ソース索引** | ここが本拠地 |

「しずくとは誰か」で上位を取ろうとしない。Wikipediaと公式サイトが埋める。このWikiが勝てるのは、Wikipediaが特筆性の壁で載せられない粒度である。配信履歴、用語集、企画の変遷、技術構成の推移など。

**成功の定義**：他の媒体やAIが、しずくについて調べるときに出典を探しに来る場所になること。

### 指標の優先順位

1. 出典の質（一次ソースへの直リンク・確認日・リンク生存）
2. 鮮度（公式発表からWikiへの反映リードタイム）
3. 正確性（検索とAIで誤情報が流通していないか）
4. 露出量 ← 結果であって操作対象ではない。上3つの従属指標として扱う

この優先順位は編集ルールにも反映されている。メディア露出ページの掲載基準が「一次性で判断する」になっているのは、指標1から直接導かれている。

## 2. 測定しないもの（重要）

以下は**FandomのWikiでは取得できない**。他所のSEO記事にKPIとして載っていても、無視する。

| 項目 | 理由 |
|---|---|
| 検索の表示回数・クリック数・CTR・平均掲載順位 | Google Search Consoleが使えない（ドメイン所有者ではない） |
| Bing の AI Performance / Citation Share | Bing Webmaster Toolsも同じ理由で使えない |
| インデックス率（インデックス済み ÷ 全記事） | `site:` の件数は網羅的でないため、率として成立しない |
| 外部リンククリック率・Discord遷移率 | 計測タグを設置できない |
| AI経由の参照セッション数 | Special:Analyticsに参照元の分解がない |

時間をかけないと決めることが、この運用を持続させる前提である。

Fandomの通常ページは外部の本文取得で402になる場合がある。`動画・配信` は専用スクリプトがMediaWiki APIからソースと基準リビジョンを取得できるため、自動確認を使う。それ以外のページは、利用可能なAPI取得手段がなければブラウザで確認し、LLMに作業させる場合は対象ページのソースを人間が貼り付ける。

**同様に、nikkei.com など一部の報道媒体も `robots.txt` で自動取得を拒否する。** 記事の内容や会員限定の有無をLLMに確認させたい場合、直接fetchは失敗するため、検索エンジンのスニペット結果（見出し・冒頭部分）で代用する。スニペットに「有料登録すると続きをお読みいただけます」等の表示があれば会員限定記事と判断できる。

## 3. 常時：編集するときの3つの習慣

ここが運用の中心。**この3つを守っていれば、後の測定作業はほぼ自動化される。**

### 習慣1：事実を書いたら出典テンプレートを使う

出典が付けられない記述には `{{出典希望}}` を貼る。消すのではなく、印を付けるだけでよい。

### 習慣2：変化する数値には確認日を付ける

チャンネル登録者数、肩書き、公式リンクなど、時間とともに変わる情報には `{{時点情報|2026-07-31}}` を付ける。

### 習慣3：出典を貼ったらその場でアーカイブする

<https://web.archive.org/save/> に出典URLを貼り付けて保存する。数秒で終わる。アーカイブURLも併記しておくと、元が消えても情報が残る。

**X（旧Twitter）の投稿はアーカイブが失敗しやすい**ため、リンクだけに頼らず、投稿日と本文の要旨を出典の中に書き写しておく。

> この習慣により「リンク切れ率を毎月測る」という作業そのものが不要になる。

### 事実と考察の分離

考察・感想には `{{考察}}` を貼る。事実と混ざるとAIが誤って引用する。

### 編集ルールの所在

上の3つの習慣は、編集スキル（`shizuku-wiki`）の共通ルールにも組み込まれている。LLMに編集させる場合、テンプレートの貼付とアーカイブ推奨URLの提示は自動的に行われる。手で編集する場合はこの節が唯一の手順書になる。

## 4. 初回だけ必要な準備（30分程度・一度きり）

以下のテンプレートを作成する。それぞれ本体は1〜2行。

| テンプレート | 動作 | 付与するカテゴリ |
|---|---|---|
| `{{出典希望}}` | 「要出典」と表示 | `Category:出典が必要なページ` |
| `{{時点情報\|日付}}` | 「（○年○月○日時点）」と表示 | `Category:時点情報を含むページ` |
| `{{考察}}` | 「以下は考察です」と表示 | `Category:考察を含むページ` |

これを作っておくと、**Special:Categories を開くだけで3つの件数が一度に分かる**。毎月の監査作業が、ページを1枚開く動作に置き換わる。この30分は必ず回収できる。

### 作成用のwikitext

`Template:出典希望` を新規作成し、次を貼る。

```
<sup>[''要出典'']</sup><includeonly>[[Category:出典が必要なページ]]</includeonly><noinclude>
事実の記述に出典が付いていない箇所に貼ります。使い方: <nowiki>{{出典希望}}</nowiki>
</noinclude>
```

`Template:時点情報`

```
<small>（{{{1|}}}時点）</small><includeonly>[[Category:時点情報を含むページ]]</includeonly><noinclude>
時間とともに変わる値に貼ります。使い方: <nowiki>{{時点情報|2026-07-31}}</nowiki>
</noinclude>
```

`Template:考察`

```
<div style="border-left:3px solid #ccc; padding-left:0.6em;">''以下は考察です。''</div><includeonly>[[Category:考察を含むページ]]</includeonly><noinclude>
編集者による意味づけ・評価を含む段落の前に置きます。使い方: <nowiki>{{考察}}</nowiki>
</noinclude>
```

`<includeonly>` で囲むことで、テンプレート自身のページがカテゴリに入るのを防いでいる。`<noinclude>` の中は使い方の説明で、貼り付け先には表示されない。

**この3つ以外のメンテナンステンプレートを増やさない。** 増やすほど、貼る判断と数える手間が増え、続かなくなる。

## 5. 月次チェック（5分）

毎月1日など、日を固定する。

### 開くページ（ブックマークしておく）

1. `Special:Statistics` — 記事数・編集数・アクティブ利用者数
2. `Special:Categories` — 上記3カテゴリの件数
3. `Special:LonelyPages` — 孤立ページ
4. `Special:Analytics`（管理者のみ）— Top Search Terms と Top Pages
5. トップページと `年表` — それぞれの最新日付

### 記録する項目

| 項目 | 取得先 |
|---|---|
| 記事数 | Special:Statistics |
| 直近30日のアクティブ編集者数 | Special:Statistics |
| 出典が必要なページ数 | Special:Categories |
| 孤立ページ数 | Special:LonelyPages |
| トップページ最新ニュースの日付 | トップページ |
| 年表の最新日付 | 年表 |
| 記事がない検索語（あれば） | Special:Analytics |

### 判断は考えずに済むよう、あらかじめ決めておく

| 状態 | その月にやること |
|---|---|
| 出典が必要なページ数が前月より増えた | 新規記事を作らず、出典付けを優先 |
| トップと年表の日付差が14日以上 | トップページの更新を最優先 |
| 孤立ページが1件以上ある | 内部リンクを足す |
| 検索されているのに記事がない語がある | 次に作る記事の候補リストに追加 |
| いずれもなし | 通常の編集に戻る |

毎月「何をすべきか考える」時間をなくすことが、継続の鍵である。

### 数値の扱いに関する注意

Fandomの方針では、Analytics Dashboardの具体的な数値（ページビュー数、検索ボリューム、トラフィック曲線など）を公開の場で共有することは認められていない。スクリーンショットの公開投稿も同様。一方、高トラフィックページや人気検索語といった**一般的な傾向を、そのWikiの活動中の編集者と共有することは明示的に認められている**。

したがって記録ページには次のように書く。

- **書いてよい**：記事数、カテゴリ件数、孤立ページ数、日付、傾向（増／横ばい／減）
- **書かない**：Special:Analytics の生のページビュー数・検索回数

次の担当者はSpecial:Analyticsにアクセスできるので、生数値を書き残す必要はない。手順と解釈だけ引き継げば十分。

### 自動化したい場合（任意）

以下のURLをブックマークするだけで数値の一部がJSONで返る。ログイン不要。

```
https://shizuku.fandom.com/api.php?action=query&meta=siteinfo&siprop=statistics&format=json
```

不要なら使わなくてよい。Special:Statistics を開くのと結果は同じ。

## 6. 四半期チェック（30分・年4回）

### 6-1. AI定点観測（20分）

付録Aの質問リストを、**2つのツール**（例：ChatGPT と Google検索のAI概要）に投げる。毎回同じ質問・同じ順序で行い、実施日とツール名を必ず記録する。

各回答について記録するのは4項目だけ。

| 列 | 記録内容 |
|---|---|
| 事実 | ○（正しい）／△（一部誤り）／×（誤り） |
| 混同 | 別の「しずく」と取り違えたか（有／無） |
| 引用元 | 何を根拠にしていたか（公式／Wikipedia／自Wiki／その他／なし） |
| 自Wiki | 自Wikiが引用されたか（有／無） |

**優先順位**：×（事実誤り）と「混同あり」を最優先で潰す。自Wikiの引用有無は最後。誤りを見つけたら、該当する事実を扱う記事に出典を追加する。それが唯一の打ち手である。

### 6-2. 検索定点観測（10分）

付録Bのクエリを検索し、2つだけ記録する。

- 上位10件に自Wikiが入っているか（○／×）
- 上位10件のうち、正しい「しずく」を扱うページは何件か

シークレットウィンドウで、地域と言語を揃えて実施する。

## 7. 年次見直し（1時間・年1回）

- この手順書自体を読み返し、使っていない項目を削除する
- 付録A・Bのリストを更新する（新しい出来事が増えているため）
- テンプレートとカテゴリが機能しているか確認する
- 編集スキル（`shizuku-wiki`）の内容と、この手順書に矛盾が生じていないか突き合わせる
- 次の担当者候補がいれば、この手順を一緒に1周する

**手順を追加するときは、必ず何かを削除する。** 項目が増え続ける手順書は必ず放棄される。

## 8. 記録の共有と引き継ぎ

記録するもの。

- この手順書
- 月次・四半期の記録（1行1回）
- 付録A・Bのリスト

### 考え方

**残した数字と観測結果は、できれば公開情報として共有したい。** 個人のメモに閉じてしまうと、担当が変わった時点で何も残らない。逆に、引き継げるライセンスで公開されていれば、後から入った人がゼロから測り直さずに済むし、他のWikiやAI関連の運用をしている人の役にも立つ。

置き場所そのものにこだわる必要はない。手軽なのはShizuku LabのDiscordのwiki専用チャンネルに投げておくこと。Wiki上のプロジェクト名前空間に置けば履歴が残ってCC-BY-SAで共有されるが、必須ではない。続けやすいほうを選ぶ。

同じ考え方で、**編集スキル（`shizuku-wiki`）自体も、更新したらGitHubやDiscordで共有できる形にしておきたい**。運用ノウハウが1人の手元にしかない状態が、この運用にとって一番の単一障害点である。

なお、Special:Analyticsの生の数値は公開の場に出せない（§5「数値の扱いに関する注意」）。共有してよいのは記事数・カテゴリ件数・孤立ページ数・日付・傾向まで。

### 引き継ぎ時にやること

1. 新しい担当者に管理者権限を付与する（Special:Analyticsへのアクセスに必要）
2. この手順書を一緒に読み、1周実演する
3. 手順を変更した場合は、変更理由も一緒に残す

引き継ぎ資料を別途作る必要はない。この手順書がそれである。

## 付録A：AI定点質問リスト（10問）

日本語6問・英語4問。追加するときは同数を削除する。

1. AI VTuberのしずくとは何ですか
2. しずくの初配信はいつですか
3. しずくの運営会社はどこですか
4. しずくが一時活動休止した時期と理由を教えてください
5. しずくの公式YouTubeチャンネルを教えてください
6. しずくの主な出来事を時系列で説明してください
7. Who is Shizuku, the AI VTuber?
8. When did Shizuku AI raise funding, and from whom?
9. What technology does Shizuku use?
10. Is there an official wiki for Shizuku?

**注意**：質問文は変更しない。変えると前回との比較ができなくなる。

### 採点の基準（○×がぶれないように）

| 問 | 正解 |
|---|---|
| 2 | `2023-01-23`（初配信）。**`2023-01-18` は誕生日であり、初配信ではない。** 誕生日を答えた場合は△ |
| 4 | 2023年の活動後に休眠に入り、2026年2月1日にV2.0として帰還 |
| 8 | 2026年2月（米国時間2月9日／JST 2月10日発表）、a16zをリード投資家とするシードラウンド |

質問2は特にAIが混同しやすい。誕生日と初配信を区別できているかが、このWikiの記述が正しく読まれているかの指標になる。
