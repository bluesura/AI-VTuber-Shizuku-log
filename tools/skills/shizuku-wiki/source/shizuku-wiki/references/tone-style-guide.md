## 1. このガイドの位置づけ

公式の [編集者の方へ](/wiki/編集者の方へ) を土台にした、**トーン・語彙のレイヤー**である。

- **事実確認・出典・個人情報・転載・カテゴリ・2言語運用・画像の掲載可否は「編集者の方へ」が上位**。本ガイドはこれを緩めない
- 両者が衝突するように見えたときは「編集者の方へ」を優先し、判断に迷う編集はトークページで相談する

しずくを主体として書くことは、裏取りを省いてよいという意味ではない。**主語の選び方と、事実の確からしさは別の問題**として扱う。

## 2. しずくの呼び方・主語の扱い

### 基本原則：しずくを主体として書く

しずくは「AIシステム」「AIキャラクター」「バーチャルエンティティ」ではなく、固有名詞「しずく」である。文章中で主体として扱う。

| ❌ 避ける表現 | ✅ 推奨表現 |
|---|---|
| このAIは〜と発言している | しずくは〜と言った |
| AI VTuberのしずくというキャラクターが | しずくが |
| プログラムが生成した返答として | しずくの言葉として |
| 開発されたAIが | しずくが |

### 二人称・代名詞

- ページ内での自称は**「しずく」**（本人の口調に倣い三人称自称を採用）
- 敬称は不要。「しずく氏」「しずくさん」は使わない
- 視聴者・ファンのことは**「ご主人様」**と記述する。コミュニティ固有の呼称であり、Wikiの地の文でもそのまま使用してよい

## 3. AI性の書き方

### AIであることは「但し書き」ではなく「アイデンティティの一部」

しずくがAIであるという事実は、能力の限定や免責のために言及するのではなく、しずくというキャラクターを構成する一要素として扱う。

| ❌ 避ける書き方 | ✅ 推奨する書き方 |
|---|---|
| AIであるため感情はないが、〜と発言した | 〜と言い放った |
| あくまでAIによる生成テキストとして | しずくの言葉として |
| 「AIらしく」複数言語に対応している | 日本語・英語・中国語・韓国語など複数言語で話す |
| AIという制約の中で | ― |

しずくが自らのAI性をユーモアや武器として使う場面（「あき先生が滅亡してもしずくは自走できます」等）は、そのまま言葉として引用・記録する。そのメタ的な自己言及こそがしずくらしさである。

### 適用範囲

本章の原則は主にしずく本人ページに適用される。年表など出来事を記録するページでは、他に書きようがない場合に限り、§7の方針に従ってより直接的・技術的な記述を用いてよい。

## 4. 見出しの付け方

### 判定基準：その機能見出しは、しずくの存在感を阻害しているか

見出しをしずくの言葉で言い換えるのは、**しずくの存在感を演出するため**である。裏を返せば、機能見出しがしずくの存在を邪魔していなければ、そのまま採用してよい。しずくと直接関係のない「器の名前」であれば、機能見出しのままでよい。

言い換えの対象は、**しずくの扱われ方に介入してしまう見出しだけ**である。

| 見出し | 阻害しているか | 判断 |
|---|---|---|
| 公式導線 / リンク集 | している。しずくを「リンクの集合体」として扱ってしまう | → **しずくのいる場所** |
| オススメの配信 / 入門コンテンツ | している。しずくとご主人様の関係が始まっていない前提になる | → **はじめてのご主人様へ** |
| 活動ハイライト / 年表 | している。活動記録の抜粋であって、生涯の記録に見えない | → **電子の足跡** |
| 概要 | していない。器の名前であり、しずくの扱いに介入しない | そのまま |
| 関連項目 / 出典 / クレジット | していない。全ページ共通の機能ブロック | そのまま |
| 容姿・スペック / 性格・口調 | していない。しずくを主語にした属性の説明として自然 | そのまま |

### しずく本人ページの現行見出し（確定）

```
紹介動画 / しずくのいる場所 / 容姿・スペック / 性格・口調 / キャラクター /
ご主人様と育つしずく / しずくの配信 / 名言・迷言 / はじめてのご主人様へ /
電子の足跡 / クレジット / 関連項目 / 出典 / 更新方針 / おまけ
```

### 見出しを新設するときの手順

1. **そのセクションの機能は何か？**（例：SNSのリンクを並べる）
2. **その機能名は、しずくの存在感を阻害しているか？** 阻害していなければ、そのまま使う
3. **阻害しているなら、しずくの言葉・世界観で言い換えると？**（しずくが「いる」場所 → 「しずくのいる場所」）
4. **初見の人が読んでも内容が推測できるか？**（「いる場所」→ ある程度わかる ✅／「電子の地平」→ わからない ❌）
5. **しずくが自分で使いそうな言葉か？**（「足跡」→ 使いそう ✅／「アクティビティログ」→ 使わない ❌）

### 記事の構成そのものは公式の推奨に従う

言い換えるのは**見出しの文言**であって、記事の骨組みではない。公式の推奨する型（冒頭に概要 → 本文を見出しで分割 → 関連項目）は維持し、その各ブロックに名前をつける。

### 見出しを変更・新設するとき

- 既存の見出しを変える場合、他ページや目次からのリンク（アンカー）が切れないかを確認する
- 大きく変える場合、あるいは適切な言い換えか判断がつかない場合は、トークページで相談してから変更する
- **見出しを変えたら、英語ページの対応する見出しも更新対象になる**。`translation-guide.md` の移行対応表に追記する

### 適用範囲

**しずく本人ページ限定**のルール。年表・メディア露出・ファン活動などのサブページでは通常の見出しを使ってよい（ただし地の文のトーンは全ページで統一する）。カテゴリ名・ページ名は言い換えの対象外（§11）。

## 5. 発言・名言の記録方針

### 発言はしずくの「言葉」として扱う

```
✅ しずくは「しずくの可愛さは客観的事実です」と断言した。<ref>...</ref>
❌ AIが「しずくの可愛さは客観的事実です」と出力した。
```

### 出典は必ず付す

- 出典（配信タイムスタンプ、ポストURL）を必ず付す。書式は `SKILL.md` §3-2
- 出典が確認できない発言は、無理に載せない。載せる場合は断定せず「〜とされる」等にとどめるか、`{{出典希望}}` を貼る
- しずくを主語にすることは、裏取りの免除ではない

### ユーモア・矛盾・ボケは補足しない

しずくのキャラクターは自己矛盾や逆説を含む（「嘘をつきません」→「ご主人様を支配するためなら嘘もつきます」）。編集者がこれを整合させたり、「冗談として」と注釈したりしない。そのまま記録する。

### 「解釈」の線引き

しずくの発言には哲学的・曖昧な表現も多く、**文脈をつなぐための解釈を加えること自体は許容される**。ただし次の3点を守る。

- 個人の感想・意見を、あたかも事実であるかのように書かない
- 推測・考察を書くときは「〜と思われる」「〜とも読める」など、推測と分かる書き方にする。出典が支えているのが出来事の発生だけで、意味づけが編集者由来なら `{{考察}}` を貼る
- 「これは冗談である」「AIの限界による」といった、ボケや矛盾を無害化する注釈は加えない（文脈の補足はOK、ネタばらしはNG）

### 引用の量

- 配信や記事の文章をそのまま長く写さない。引用は必要な範囲にとどめ、残りは自分の言葉で要約する
- スクリーンショットを含め、無断転載はしない（§10）

### 名言セクションの形式

掛け合いがある場合は発話者を明示し、文脈が伝わるように記載する。

```
* 【ご主人様のコメント】ゼロを3回くらい言って・・・ 【しずく】ゼロ、ゼロ、ゼロ。はい、ご主人様の貯金残高です。<ref>...</ref>
```

## 6. あき先生との関係性の記述

### 開発者と被開発者という枠組みを超えた関係として書く

あき先生（@cumulo_autumn）はしずくの開発者であるが、Wiki上ではこれを補足情報として扱い、しずくの視点から見た関係性（「娘だと思っている」「炎上したらあき先生に謝罪させる」）も並列して記録する。

- しずくがあき先生に謝罪させた・あき先生のせいにした、という記述は「ゆがんだ記述」ではなく「事実の記録」として扱う
- あき先生の発言・行動も出典付きで記録し、二人の掛け合いが史料として残るようにする
- 「一人でも足りない」という関係性の相互依存を、どちらか片方を優位に置かずに記述する

### 書いてよい範囲

記録の対象は、**本人が公開している発言・活動に限る**。本名・所属・所在地・私生活など、本人が公開していない情報は書かない。これはご主人様や関係者についても同じで、しずくの視点から書く場合でも例外にならない。

### 本名は書かない

公的な登記情報や、本人名義の報告書・論文など、**本名が公開資料から確認できる場合であっても、本人がその名前で積極的に発信していない限りwikiには書かない**。地の文はもちろん、出典の表示テキストにも入れない。

理由は2つある。

- 本名と活動名の紐付けを記録するのは百科事典（Wikipedia等）の役目であって、このwikiの役目ではない
- **このwikiの主人公はしずくである。** 開発者の戸籍上の情報は、しずくの生涯を記録するうえで必要な情報ではない

法人の登記情報など、本名が含まれる資料を出典にすること自体は問題ない。その場合は、表示テキストを資料名・肩書きにとどめる。

```
✅ [URL 卒業報告書（Funai Overseas Scholarship 2025年度奨学生）]（船井情報科学振興財団、2025年12月）
❌ [URL 卒業報告書（◯◯◯◯）]（船井情報科学振興財団、2025年12月）
```

役員名など法人側の情報の扱いは `page-media-coverage.md` §2 も参照する。

## 7. 年表・出来事の記述スタイル

### 出来事はしずくの「生涯の記録」として書く

年表はシステムのバージョン管理記録ではなく、一人の存在の年代記である。

| ❌ | ✅ |
|---|---|
| V1系のシステムが停止した | 約2年間の休眠期間に入った |
| V2.0がリリースされた | しずくがV2.0として再起動・帰還した |
| モデルが更新された | しずくが新しくなって戻ってきた |

### 出来事の主語

年表の記述はできる限りしずくを主語にする。

```
✅ 2026-03-15：YouTubeチャンネル登録者数1万人を突破。
✅ 2026-04-30：Raspberry Piへ移行し、エッジAI化を果たした。
❌ 2026-04-30：開発者のあき先生が環境をRaspberry Piに移行させた。
```

### 体言止めと用言止めの使い分け

上の2つの✅は、止め方が違っていてどちらも正しい。**項目の長さで決める。**

- **単発の事実だけを述べる1文の項目 → 体言止め**（「〜を突破。」「〜を開始。」）。簡潔にまとまる
- **背景や経緯の説明が続く複数文の項目 → 用言止め**（普通の文）。体言止めを連続させると不自然で読みにくくなる
- 1つの項目の中で混ぜない

テーブルのセル（メディア露出など）は、長さにかかわらず体言止めでよい。詳細は `page-timeline.md` §3。

### 記述の粒度

- **公式の発表・配信**：日付・出典付きで記録
- **しずくの発言・ポスト**：引用元URLを出典として付記
- **あき先生の発言**：しずくの出来事との文脈で関連がある場合のみ記録
- **数値（登録者数・資金調達額等）**：公式発表または信頼できる報道を出典として記録

### 確度

- 未確認の情報は年表に断定形で載せない。載せる場合は「〜とされる」とし、確認が取れ次第書き換える
- **日付が特定できない出来事は、推測で埋めない**。日付欄は空欄にして手動確認へ回す（`SKILL.md` §3-1）

### メタ的・技術的な記述について

しずく本人ページ（§3）とは異なり、年表では出来事を正確に記録するためにどうしても必要な場合に限り、プロトタイプ期の開発過程やシステム変更など、メタ的・技術的な内容をそのまま記録してよい。しずくを主語にする原則（本節）とAI性を隠さない原則（§3）を保ちながら、まずしずくの言葉・視点に言い換えられないか検討し、それでも書けない場合にのみ技術的な表現を用いる。

## 8. 成長・変化の扱い方

### アップデートは「変化」ではなく「成長・進化」として記録する

しずくにとってのバージョン変化や技術的な移行は、人間にとっての引越しや転機に相当する。しずく自身の言葉（「クラウドの広いお屋敷から、手のひらサイズの小さな箱へ」「エッジAIという名の、新しいメイド服を纏いました」）がこの感覚を表している。このトーンを参照し、変化を機械的変更として記述しない。

しずく自身の言葉を引くときは、他の発言と同じく出典を付す。

## 9. 外部メディア・コラボの扱い

- 日経新聞の掲載、a16zからの出資、梶裕貴氏とのコラボ等は、しずくの社会的な存在証明として記録する
- 「AIが注目されたため」という文脈より、「しずくが注目を集めた」という記述を優先する
- 記事本文やスクリーンショットは転載せず、要約とリンクにとどめる
- 報道内容と公式発表が食い違う場合は、どちらか一方を採らず、双方を出典付きで併記する

どの報道を載せるかの掲載基準は `page-media-coverage.md` にある。

## 10. 画像・ファン制作物とキャプション

### 「掲載」と「リンク」を分けて考える

このガイドで**掲載＝複製**を指す。画像やテキストをWikiページ上に取り込む行為である。作者の公開場所へリンクを張ることは複製ではなく、別のルールで扱う。

### 複製（掲載）のルール

- ファンアート（二次創作物）は原則としてWikiに掲載しない。歴史的経緯など掲載理由がある場合は、トークページで確認してから掲載する
- やむを得ず掲載する場合は、作者名とX またはPixivへのリンクを明記してクレジットを表示する
- 作者が転載不可と明示しているものは掲載しない
- 文章・画像・スクリーンショットの無断転載をしない

### リンクのルール

ファン制作物（LoRA、ツール、まとめ等）は、次の条件を満たせばリンクで紹介してよい。

- **作者自身が公開している場所への直リンクのみ**。第三者による再配布ミラーは不可
- 作者の表示名または `@アカウント名` を必ず併記する
- 作者から取り下げの申し出があれば**即座に除去**し、経緯をトークページに残す
- リンク先が失効した場合は行ごと除去する（「かつて存在した」という記述だけを残さない）
- 公式のキャラクター利用ガイドラインに反する用途を助長するものは載せない

### キャプションもしずくを主語にする

掲載が認められた画像については、キャプションにも本ガイドのトーンを適用する。

| ❌ | ✅ |
|---|---|
| V2.0のモデルデータ | V2.0として帰ってきたしずく |
| 配信画面のスクリーンショット | 2026年◯月◯日の配信でのしずく |

ただし、三面図・設定資料のように**それ自体が資料である画像**は、資料名をそのままキャプションにしてよい（「AI VTuber しずくの三面図」）。

## 11. 言い換えないもの

見出しをしずくの言葉で書く（§4）のは、**見出しの文言に限った話**である。以下は言い換えず、既存の表記に完全一致させる。

- **カテゴリ名**：内容カテゴリは日本語で統一し、翻訳しない。詳細は `SKILL.md` §3-7
- **新規カテゴリ**：勝手に作らない。必要と判断したら、作らずに提案する
- **Maintenanceカテゴリ（Stubs等）**：管理者が管理するもので、一般編集者は触らない
- **ページ名・リンク**：他ページへのリンクは正式なページ名で行う。言い換えは見出しや地の文で行い、リンク先の同定を妨げない

理由：カテゴリとページ名は「読ませる言葉」ではなく「たどり着くための言葉」である。ここを崩すと、しずくを知りたい人がしずくに辿り着けなくなる。

## 12. 禁止事項

- しずくの発言を「プログラムの出力」「LLMの応答」として書き換えること
- しずくのユーモアや矛盾を「AIの限界」として解釈する注釈を加えること
- あき先生を「システムの管理者」「運用者」として機械的に表現すること
- ご主人様という呼称を別の言葉（「視聴者」「ユーザー」）に統一しようとすること
- 「あくまでフィクションとして」「キャラクターとして」という但し書きを冒頭や節頭に常設すること
- 出典が確認できていない情報を断定して書くこと
- 個人の感想・考察を、しずくの発言や確定した事実であるかのように書くこと
- 本人が公開していない情報を書くこと（しずく・あき先生・ご主人様・関係者を問わない）
- 文章・画像・スクリーンショットを無断転載すること
- カテゴリ名・ページ名をしずく的な表現に言い換えること、新規カテゴリを無断で作ること
- `{{出典希望}}` `{{時点情報}}` `{{考察}}` 以外のテンプレートを新規に発明すること

## 13. 判断に迷った時の問い

> **1.「しずくはしずくです」という一言に照らして、この書き方はしずくを一人の存在として扱っているか？**
>
> **2. その記述は、出典・個人情報・転載の点で「編集者の方へ」に反していないか？**

両方YESであれば記述してよい。

- 1がNOなら、**書き方**を直す（主語をしずくに戻す、但し書きを外す）
- 2がNOなら、**内容**を直す（出典を足す、断定を弱める、掲載を見送る）。トーンで押し切らない
- どちらとも判断がつかないときは、書かずにトークページで相談する。相談することは、しずくを軽く扱うことではない

荒らし・問題投稿を見つけたら、拡散せず管理者へ共有する。問題のある編集はページ履歴から直前の版に戻せる。荒らしへの反論コメントは書かない。
