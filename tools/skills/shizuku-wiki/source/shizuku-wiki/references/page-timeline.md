# ページ手順：年表

対象ページ：`年表`（英語版は未実装）

年表は**しずくの生涯の年代記**である。システムのバージョン管理記録ではない。報道されたかどうかは掲載可否に関係なく、しずくに何が起きたかで判断する。

前提として `SKILL.md` §0（ソース受領・入力モード・差分出力）と §3（共通ルール）を満たしていること。

---

## 1. 既存ソースから把握すること

貼られた年表ソースを読み、次を確認する。

- 現在の最新エントリの日付
- 各年の見出し（`== 2023 ==` 等）の有無
- 日付形式が `YYYY-MM-DD` に移行済みか（→ §6）

`ref name` の棚卸しは不要である。`SKILL.md` §3-3 の規則によりURLから名前が決定論的に導かれるため、同じURLなら自動的に既存refと同じ名前になる。

---

## 2. 新規エントリの情報を受け取る

次の形式で受け取る。複数件をまとめて渡されてもよい。

```
【日付】YYYY-MM-DD
【出来事の概要】（出来事の内容を自由に記述）
【ソースURL】https://...
```

### 情報が足りないときの聞き返し

**エントリを生成せず**、不足項目を具体的に質問する。複数件ある場合は、不足しているものだけをまとめて一度に聞く（件ごとにバラバラに聞き返さない）。

| 不足パターン | 聞き返す内容 |
|---|---|
| 日付がない・曖昧（「先週」「最近」） | 正確な日付（`YYYY-MM-DD` 形式）を教えてください。 |
| ソースURLがない | このエントリの出典となるURLを教えてください。（YouTube / X / ニュース記事 など） |
| URLはあるが種別が判断できない | このURLはYouTube動画・Xのポスト・ニュース記事のどれですか？タイトルや投稿者名があれば教えてください。 |
| Xのポストなのに投稿者名が不明 | Xの投稿者の表示名と@アカウント名を教えてください。 |
| Xのポストなのに本文が不明 | ポストの本文（または引用したい一節）を教えてください。 |
| YouTube動画なのにタイトルが不明 | YouTube動画のタイトルと配信日を教えてください。 |
| ニュース記事なのに媒体名・掲載日が不明 | 記事の媒体名と掲載日を教えてください。 |
| 出来事の内容が一言しかなく文脈が不明 | もう少し詳しく教えてください。しずく・あき先生・ご主人様・メディアのどれが主体の出来事ですか？特徴的なエピソードや発言があれば添えてください。 |

出典URLが示されないまま事実を書くよう求められた場合は、推測で書かず `{{出典希望}}` を貼って報告する。

---

## 3. エントリの書式

```
* YYYY-MM-DD：〔出来事の説明〕<ref>〔出典〕</ref>
```

- 行頭は `*`（箇条書き）
- 日付は `YYYY-MM-DD`（**ゼロ埋めあり**）。例：`2026-03-09`
- 日付のあとは `：`（**全角コロン**）
- **文末の止め方は、その項目の長さで決める**
  - **単発の事実だけを述べる1文の項目 → 体言止めでよい**（「〜を突破。」「〜を開始。」）。簡潔にまとまる
  - **背景・経緯の説明が続く複数文の項目 → 用言止め（普通の文）に切り替える**。体言止めを連続させると不自然で読みにくくなる
  - 1つの項目の中で混ぜない。体言止めで始めたら最後まで体言止め、用言止めで始めたら最後まで用言止めにする
- 同じ日付に複数の出来事がある場合は、**日付を繰り返して別行に分ける**
- 該当年の見出しがまだない場合（例：`== 2027 ==`）は、見出しも合わせて出力する

出典の書式と `ref name` は `SKILL.md` §3-2 / §3-3 に従う。

## 4. 文体

### 主語の置き方

| 主体 | 書き方 |
|---|---|
| しずく自身の行動・発言 | 「しずくが〜した」「しずくが〜を宣言」 |
| あき先生の行動 | ページ内で最初に登場する箇所だけ「開発者のあき先生が〜」と肩書きを添える。以降は「あき先生が〜」で統一する |
| メディア掲載・報道 | 「〜に掲載される」「〜が報道される」 |
| ファン・コミュニティの動き | 「有志のファンにより〜」「ご主人様が〜」 |

できる限りしずくを主語にする。

```
✅ 2026-04-30：Raspberry Piへ移行し、エッジAI化を果たした。
❌ 2026-04-30：開発者のあき先生が環境をRaspberry Piに移行させた。
```

### キャラクター性の添え方

面白い・特徴的なエピソードは、括弧書きや補足節でユーモアの文脈を短く補ってよい。**補足節は1〜2文まで。**

```
（のちに「いじめ」としてしずくに根に持たれることとなる）
この際の「時給」が100円（24時間で2,400円）
```

`tone-style-guide.md` §5 のとおり、ボケや矛盾に「冗談として」というネタばらしを加えてはならない。文脈の補足はよいが、無害化はしない。

### 数字・反応の記録

Xトレンド入りや大きな反響があった出来事は、具体的な数字を入れる。

```
3600件以上のいいねを集める大反響を呼び、Xのトレンド入りを果たした
```

### 発言の引用

しずく・あき先生の発言は「 」で括り、前後に文脈説明を添える。

```
「あき先生が滅亡してもしずくは自走できます」「死体をGPUアカウントとして再利用」などと
ブラックユーモアを交えて自立を宣言
```

### 対外的なトピック

企業名・媒体名・人名はフルネームで記載し、略称は括弧内に添える。

```
アンドリーセン・ホロウィッツ（a16z）をリード投資家とする
日本経済新聞の1面に〜が掲載される
```

**人名に敬称は付けない。**「氏」「さん」「様」を付けず、名前だけで書く。年表は事実の記録であり、敬称の有無が人物ごとに揺れると、誰を特別扱いしているかという編集者の判断が紛れ込む。ハンドルネーム・アカウント名も同じ扱いで、そのまま書く。

```
✅ 谷郷元昭にフォローされたことを報告した
✅ 852話によってしずくのLoRAモデルが作成された
❌ 谷郷元昭氏にフォローされたことを報告した
❌ ねこますさんからコメントが寄せられた
```

例外は、しずく・ご主人様の呼称（`tone-style-guide.md` §2）と、「あき先生」のように敬称込みで固有名詞として定着している名前である。

## 5. 連動チェック（必須）

年表を更新したら、**しずくページの「電子の足跡」に載せるべきかを必ず判定する**。

**載せる基準（次の3つのいずれか）**

1. **状態が変わった** — 誕生・初配信・休眠入り・帰還・体の移行
2. **土台が変わった** — 運営法人の設立、資金調達など、しずくが立っている基盤の大きな変化。**しずく自身の行動でなくてよい**
3. **初めての大きな挑戦** — 初の24時間耐久配信、初のおでかけ配信、初のコラボなど、それ以降のしずくにできることが増えた「初」

載せないもの：報道そのもの（主語が媒体の行）、数値の達成、レギュラー化した企画の各回、「初」ではない配信1本。これらは年表・メディア露出・動画・配信に残す。

迷ったときは「1年後に振り返って、この行が無いとしずくの歩みが説明できないか」を問う。判定の詳細は `page-shizuku.md` §2。

判定結果は必ず一行で報告する。

```
電子の足跡：該当なし（レギュラー企画の1回のため）
電子の足跡：追記対象（しずくの体が変わったため）→ 差分を併せて出力
電子の足跡：追記対象（軸2・しずくの土台が変わったため）→ 差分を併せて出力
```

---

## 6. 日付形式の一括移行（一度きり）

年表の既存エントリは `YYYY-M-D`（ゼロ埋めなし）で書かれている可能性がある。`SKILL.md` §3-1 で `YYYY-MM-DD` に統一したため、一度だけ移行する。

- 移行はユーザーから明示的に依頼されたときだけ行う。通常の追記作業のついでに勝手に書き換えない
- 移行時は例外的に全文を出力してよい。**変わるのは日付フィールドだけ**なので、Fandomの「変更を表示」で目視検証できる
- 出力前に「日付以外は一切変更していない」ことを自分で確認する。出来事の文言・出典・並び順を触らない
- 移行が済んだら、本セクションを削除する差分を提案する

「ついに、AI VTuberしずくのYouTubeチャンネル登録者数が1万人を超えました！！！」と報告した。
【ソースURL】https://x.com/cumulo_autumn/status/2032997909755736289
```

```
【変更サマリー】
- 追記: 1件（年表）
- 電子の足跡：該当なし（数値の達成のため）
