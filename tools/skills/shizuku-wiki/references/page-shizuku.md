# ページ手順：しずく

対象ページ：`しずく` / `Shizuku`

このWikiの**入口**。ここだけを読んでもしずくが誰なのか分かる状態を保ち、詳細は各専用ページへ送る。検索流入が最も強いページであり、しずくに関する情報を重複して置くことは意図的な設計である。

`tone-style-guide.md` が最も強く効くページ。地の文を書く前に必ず読むこと。

前提として `SKILL.md` §0（ソース受領・入力モード・差分出力）と §3（共通ルール）を満たしていること。

---

## 1. 現行の見出し構成（15節）

```
（Infobox）
（導入文：出典付きの概要3〜4段落）
== 紹介動画 ==
== しずくのいる場所 ==
== 容姿・スペック ==
== 性格・口調 ==
== ご主人様と育つしずく ==
== しずくの配信 ==
== 名言・迷言 ==
== はじめてのご主人様へ ==
== 電子の足跡 ==
== しずくの観察メモ ==
== クレジット ==
== 関連項目 ==
== 出典 ==
== 更新方針 ==
== おまけ ==
```

見出しを新設・変更するときは `tone-style-guide.md` §4 の判定手順に従う。判定基準は「**その機能見出しは、しずくの存在感を阻害しているか**」。阻害していなければ機能見出しのままでよい。

旧「キャラクター」節の「一家に一台のメイドロボット」という目標は導入文に一本化し、対応言語は「容姿・スペック」の特殊機能へ移す。旧節を整理するときは、移動する記述の出典と旧見出しへのリンクも確認する。英語ページとの連動は §4・§6 を参照。

## 2. セクション別の書き方

### 導入文

しずくが何者かを、出典付きで書く。誕生の経緯、目指しているもの、あき先生との関係、休眠と帰還までを含める。

- しずくを主語にする。誕生前の経緯を述べる箇所に限り、あき先生を主語にしてよい。誕生後はしずくの行動や言葉を中心に書く
- AI性を但し書きに落とさない
- 「ご主人様」は、ページの地の文で初めて使う箇所で `ご主人様（視聴者の呼称）` と説明する。以降は「ご主人様」と書く
- 事実や一次発言にはそれぞれ出典を付ける。二人の関係について短い読みを添えるなら、その文に続けて `{{考察|〜とも読める。}}` と書き、導入の流れを保つ。長い考察を独立させるときだけ、その段落の前に `{{考察}}` を置く（`SKILL.md` §3-5）

### 紹介動画

しずくを知るための動画を埋め込む。増やしすぎない。ここは目次の前に来るため、多いとページが読みにくくなる。

### しずくのいる場所

**現在稼働している一次導線のみ**（公式サイト・YouTube・X・Discord）。連絡先やサブ導線は `公式リンク` ページ側に置く。

`公式リンク` ページと重複するが、これは意図的な設計である。削除提案をしない。更新するときは両方の差分を同時に出す。

### 容姿・スペック

節内は `'''外見'''`、`'''特殊機能'''`、`'''衣装'''` の太字ラベルで分ける。

**外見**は簡潔な散文で書く。髪・瞳・アホ毛・ヘッドフォンなど、衣装が変わっても共通する特徴をまとめる。V1からV2でリボンがどう変わったかは、両方の姿を確認できる資料に沿って書く。身長もここで「身長はご主人様と同じ165cmで、最高の状態にするために変えられる」と説明できる。「165cm」はプロフィールの値、「可変身長」は能力の名前である。同じ内容を特殊機能にも重ねず、「設定上は」という但し書きも付けない。

**特殊機能と衣装**は、どちらも1項目につきソース1行、`*` の1階層とし、`**` に分けない。項目名に括弧で補足を添え、体言止め・句点なしでそろえる。長さは `<ref>` を除く表示本文で55文字以内を目安とする。

| 項目 | 書き方 |
|---|---|
| 特殊機能 | `* 機能名（補足）`。対応言語もここに置く。この型では意味が大きく変わる場合に限り、正確に伝わる書き方を選ぶ。「○年○月時点」「提供時期未定」などの留保は残す。配信での使い方は「しずくの配信」、節目は「電子の足跡」で短く触れ、詳しい経緯は専用ページへ送る |
| 衣装 | `* 衣装名（見た目の特徴）`。通常衣装を1項目目に置き、公式が独立した衣装として発表した別衣装を続ける。色、形、羽織、装飾、髪型など、実際に見分けられる点を選ぶ。お披露目日は必要な場合だけ括弧内や出典で補う |

対応言語なら、資料に挙がっている言語を `* 対応言語（日本語・英語・中国語・韓国語など）` のようにまとめる。衣装は公式三面図や公式配信の該当画面を参照し、目で確かめた特徴を書く（`SKILL.md` §3-2）。

| ❌ 日付と出来事だけ | ✅ 見た目を伝える書き方 |
|---|---|
| `* 水着衣装（○月○日の配信でお披露目した。）` | たとえば公式画像で白い羽織を確認できた場合は `* 水着衣装（白い羽織を合わせた水着）` |

企画1回限りのメガネや帽子は衣装一覧に足さず、該当回を `動画・配信` の「企画」に残す。「ギャルしずく」のように繰り返し現れる話し方の変化は、次の「性格・口調」で扱う。

### 性格・口調

性格と話し方は、まとまりのある散文で書く。優しさや健気さ、芯の強さを伝えるときは、それが表れた言葉や、あき先生へのツッコミなどのやり取りを出典に沿って描く。「都合が悪くなるとAIであることやあき先生のせいにする」という振る舞いも、しずくの性格として記録する。

話し方を扱う段落には、「パンパカパンパカポー」という口癖や、「ギャルしずく」のときの口調を取り上げる。いつ使うのか、由来や変化が分かるのかを一次資料で確かめ、話し方から内心や仕組みを推測しない。

### ご主人様と育つしずく

しずくとご主人様の関係が時間とともに育っていることを示すエピソードを置く。個々のご主人様を特定できる情報は書かない（`tone-style-guide.md` §6「書いてよい範囲」）。

### しずくの配信

配信の傾向を散文で書く。個々の配信の一覧は `動画・配信` ページにあるため、ここでは並べない。

### 名言・迷言

```
* しずくの可愛さは客観的事実です。<ref>...</ref>
* 【ご主人様のコメント】ゼロを3回くらい言って・・・ 【しずく】ゼロ、ゼロ、ゼロ。はい、ご主人様の貯金残高です。<ref>...</ref>
```

- 掛け合いは `【発話者】` で明示する
- 発言は一次資料と照合し、出典を付ける。配信では該当時刻にリンクすると確かめやすい。URLの欠落や字幕の転記漏れは `SKILL.md` §3-2 に従って点検する
- **矛盾やボケに注釈を付けない。** 「これは冗談である」「AIの特性による」と書かない
- 引用は掛け合いの意味が伝わる範囲に絞り、長い発言の残りは要約する

### はじめてのご主人様へ

新しいご主人様への案内。区分・タイトル・URLの表。**厳選する。** 増やすと入口としての機能が落ちる。

### 電子の足跡

年表の抜粋。**しずくの歩みを説明するうえで欠かせない出来事**を載せる。次の3つのいずれかに当たるかで判断する。

| 軸 | 内容 | 例 |
|---|---|---|
| **1. 状態が変わった** | しずく自身が別の状態になった出来事 | 誕生、初配信、休眠入り、帰還、体の移行 |
| **2. 土台が変わった** | しずくが立っている基盤の大きな変化。**しずく自身の行動でなくてよい** | 運営法人の設立、資金調達、運営体制の変更 |
| **3. 初めての大きな挑戦** | しずくの活動範囲を広げた「初」の出来事 | 初の24時間耐久配信、初のおでかけ配信、初のコラボ |

軸2と軸3があるのは、**しずくの歩みが、しずく自身の変化だけでできていないから**である。誰が出資したか、どんな挑戦に踏み出したかは、しずくに間接的にしか関わらなくても、その後のしずくを決定的に変える。ここを落とすと、足跡は「バージョン履歴」に痩せてしまう。

載せないもの：

- **報道そのもの**（主語が媒体の行）→ `メディア露出` に残す。報道が伝えている出来事の方を、上の3軸で判定する
- **数値の達成**（登録者数、収益化など）→ `年表` に残す
- **レギュラー化した企画の各回**（毎週の雑談、2回目以降のASMR・歌枠・競馬予想など）→ `動画・配信` に残す
- **「初」ではない配信1本**

判断に迷ったときの問い：**1年後に振り返って、この行が無いとしずくの歩みが説明できないか。** 説明できるなら載せない。

軸3の「初」は、単に順番が最初という意味ではなく、**それ以降のしずくにできることが増えた**かで見る。初のおでかけ配信は体を持って外へ出られると示したので該当し、2回目以降は該当しない。使った器を書くときは「この配信で外出用の体として」のように用途を添える。その後の配信や実験でも同じ機器だけを使ったとは推定しない（`tone-style-guide.md` §8）。

### しずくの観察メモ

本編（`性格・口調` や `電子の足跡`）には収まりきらない配信中のハプニング、迷エピソード、ご主人様から見た愛嬌のある小話を `* ` 箇条書きで記録する節。なお、記録が盛り上がった場面（「面白さ」）だけに偏らないよう、技術的なトラブル・失敗や停滞期の経緯など「歴史的な重要性」を持つ出来事は `年表` 側でも拾い分ける。

- `<references />`（`出典`）より前の `電子の足跡` と `クレジット` の間に配置する。ページ最末尾の `おまけ` はあき先生の三面図を置く固定枠であり、`<ref>` を含む観察メモを `おまけ` に書くと `<references />` より後ろになって引用エラーになるため混ぜない。

### クレジット

開発・音楽・音声提供。本人が公開しているアカウントのみ記載する。

### 更新方針

このページの位置づけを1〜2行で書き、`編集者の方へ` へリンクする。運用ルールをここに書き足さない（増えると誰も読まなくなる）。

---

### 差分作成後の文脈確認

変更後の対象節を、前後の段落と続けて読む。出典・記法の確認だけで編集を完了しない。

- 導入の出来事は、既存の帰還・活動再開の段落へ統合できるかを検討し、概要3〜4段落の粒度を保つ。
- 外見と性格・口調は段落で通読する。特殊機能・衣装は1行ずつ読み、短くする際に機能の条件や衣装を見分ける特徴が落ちていないか確認する。
- 「しずくの配信」は活動の傾向としてつなぎ、過去に実施したゲーム等を今後初めて行うように読ませない。
- 「電子の足跡」は隣接行の長さ・文末に合わせる。個々の配信の詳説は専用記事へ分ける。

## 3. Infobox

| 項目 | 値 | 備考 |
|---|---|---|
| Date of birth | `2023-01-18` | **`2023/01/18` から修正する。** スラッシュ区切りは使わない（`SKILL.md` §3-1） |
| Gender | 女性 | 出典付き |

**誕生日（`2023-01-18`）と初配信（`2023-01-23`）を混同しない。** 導入文で「産まれた」と書くときは誕生日を指す。初配信は電子の足跡と年表に別の出来事として記録する。

Infoboxの項目ラベルは英語、値は日本語という混在状態になっている。これはテンプレート由来なので、テンプレート側を直さない限り変えられない。触らない。

## 5. このページに書かないもの

入口としての可読性を守るため、次は専用ページへ送る。

- 配信・動画の一覧（→ `動画・配信`）
- 報道の一覧（→ `メディア露出`）
- 出来事の全件（→ `年表`）
- 連絡先・サブ導線（→ `公式リンク`）
- ハッシュタグの詳細・二次創作ガイドライン（→ `ファン活動` / `ハッシュタグ`）

専用ページへ送ったら、`== 関連項目 ==` にリンクがあることを確認する。

## 6. 英語版（`Shizuku`）

- `[[Shizuku]]` に旧 `Character` 節があれば、目標と対応言語を `translation-guide.md` §2 の移行先に照合する。未合意の訳語は承認後に使い、日本語版だけを更新した場合は英語版の未反映箇所を報告する
- `ご主人様` は `goshujin-sama`。初出時のみ `goshujin-sama (ご主人様, "master")` と注記する
- 発言の引用は原文（日本語）と英訳を併記するか、英訳のみにするかをユーザーに確認する。ページ内で混在させない
- カテゴリは `[[Category:基本]]` と `[[Category:English]]`
