# YouTube配信ログ → コメント用タイムスタンプ生成

## 目的とスコープ

YouTube の配信ログを読み込み、コメント欄にそのまま貼り付けられるタイムスタンプ付きシーン説明を生成する。

- **最大の目的は「要約」ではなく「予告（Teaser）」**: 事務的な議事録やオチのネタバレではなく、視聴者が「何があったのか」気になって思わずクリックしたくなる目次を作る。
- **出力先**: 生成した目次本文は**チャットに直接**返し、投稿用の完成ファイルは作らない。投稿・編集・削除はユーザーが手動で行い、エージェントは行わない。
- **他スキルとの境界**: YouTubeとFandom「動画・配信」の一覧照合、対象動画の選定、未収録ログの収集・ASR文字起こし、Wiki編集は別作業として扱い、このスキルの必須手順に含めない。

## 配信者・方向性・NGワードの初期確認

1. **配信者の特定**: `info` ファイルのタイトル・概要欄と `sbv` 冒頭の自己紹介を確認する（ユーザー指定を最優先）。メイン配信者が **「しずく」**（または既定）であれば [しずく固有リファレンス](references/shizuku-profile.md) の誤変換辞書・定型句を参照する。
2. **トーンとNGワードの確認**: 指示がなければ既定トーン（`standard`：ストレートなリスナー目線）で即座に進める。ユーザーから固さ・やわらかさ・面白さ等の希望や **NGワード（投稿弾かれ対策）** が指定されていれば、[表現・検証ガイド](references/editorial-craft.md) のプリセットと回避ルールを適用する。
3. **対話チューニング（必要なときだけ）**: 基本は質問せず即生成する。ただし「相談しながら作りたい」と求められた場合や、長尺歌枠の収録範囲など方針が大きく割れる場合のみ、`editorial-craft.md` の手順で 1〜3 問だけ確認する。

---

## Step -1: 既存目次の充実度確認【最優先】

字幕の前処理や目次生成の前に、対象動画の既存コメントを確認する。詳細は [既存目次の確認・手動投稿手順](references/existing-timestamps.md) に従う。

1. **投稿待ち・公開未確認の記録を確認**: `awaiting_manual_post` / `posted_unverified` がある場合、新しい案を重ねて作らず続きの確認を行う。
2. **既存目次の充実度を判定**: 保存済み `comments` と `info` の公式チャプターの**本文を読んで**判断する（単発の時刻やファイルヘッダー・投稿日時は目次として数えない。ハッシュタグ `#` の有無も条件にしない）。配信の主要な話題を広く案内できる目次があれば生成を省略して終了する。
3. **不足・未収録時の再取得**:
   - **リポジトリ環境**（`tools/scripts/check_youtube_timestamps.py` がある場合）: `--refresh` で公開通常コメントを再取得して再判定する。取得失敗・不完全なら「目次なし」とみなさず保留する。
   - **単体環境**（ログファイルのみ渡された場合）: 添付された `comments` と `info` の範囲で判定し、公開コメントの再取得ができない環境であればその旨を明示して不足範囲の作成へ進む（またはユーザーに判断を仰ぐ）。
4. **手動投稿後の公開確認**: ユーザーが投稿したら、投稿（または投稿連絡）から**最低限 2〜3 分（運用上 3 分）待ってから**コメントを再取得して今回の本文を確認する。投稿直後の結果で非表示・スパムと断定しない。

既存確認で終了する動画には、以降の SBV 必須・前処理手順を適用しない。

## 入力ファイルの特定と前処理

ファイル名は配信ごとに揺れるため、拡張子の完全一致ではなく**ファイル名に含まれるキーワード**で判定する。**`.srt` ファイルは重複・照合ズレの原因になるため無視する。**

| 種別 | 判定キーワード | 必須 | 備考 |
|---|---|---|---|
| ① 動画メタ情報 | `info` | 推奨 | タイトル・概要欄・企画構成・コマンド説明の確認 |
| ② 字幕・発言ログ | `sbv` | **必須** | 無ければ、またはパース失敗時は作業を止めてユーザーへ確認 |
| ③ ライブチャット | `live_chat`（`ocr` を含まない） | 推奨 | 通常版があればこちらだけを使い、OCR版は無視する |
| ③-B チャット（OCR復元） | `live_chat_ocr` / `ocr` | ③が無い場合の代替 | 信頼度が低いため **OCRモード制約** を厳守 |
| ④ 投稿後コメント | `comments` | Step -1 で使用 | 投稿日時（動画内時刻ではない）。感想のヒントにも使用可 |

### 前処理スクリプトの実行

新規生成が必要な動画では、規模にかかわらず**必ず同梱の `scripts/build_timeline.py` を実行してから読み始める**（`sbv` は 2〜4 秒ごとに分断されており、生読みはハルシネーションの原因になる）。

```bash
# クラウド/単体環境（ディレクトリ省略時は /mnt/user-data/uploads またはカレントディレクトリ）
python3 scripts/build_timeline.py <入力ディレクトリ>

# ローカルリポジトリなど複数動画が混在するディレクトリの場合（--video-id を必ず指定）
python3 scripts/build_timeline.py <入力ディレクトリ> --video-id <動画ID> --out-dir /tmp
```

出力ファイルと用途:

- **`/tmp/condensed.txt`（通読用）**: まず最初から最後まで通読し、配信全体の話題・感情の流れ・チャット反応の盛り上がりを掴む。
- **`/tmp/timeline.txt`（時刻確定用）**: シーンを決めた後、`grep` で該当発言を引いて秒単位の正確な時刻を確定する。
- スクリプト標準出力の **運営 `#` コメント**、**コーナー切れ目候補**、**チャット反応スパイク上位30** も確認する。出力内のユーザー名は運営特定などの内部判断のみに使い、**最終出力には一切含めない**。

### OCRモード（`live_chat_ocr` のみ）の厳格な制約

前処理で `OCR復元チャットモード` の警告が出た場合、チャットは「約15秒刻みに丸められた、取りこぼしと誤読を含む断片」である。

- **出力の時刻は例外なく `sbv` 側で確定する**（チャットの丸め時刻を写さない）。
- **件数・流速を根拠にしない**: 「チャット欄が一瞬で流れた」等の表現を書かない。薄い区間を「盛り上がらなかった」と解釈せず `sbv` だけで判断する。
- **文字列をそのまま引用・裏取りしない**: 同じ誤読が全視聴者に起きるため、固有名詞の裏取りに使えない。同一時刻バケット内の並びも投稿順を保証しない。

## タイムスタンプ抽出の手順

1. **Step 0（前処理検証）**: `build_timeline.py` の `sbv` 件数が 0 件でないこと、OCRモード有無を確認する。
2. **Step 1（概要把握）**: `info` を読み、企画名・公式チャプター・`@`/`#` コマンド体系を確認する。コマンドがある、またはチャットに `@`/`#` が見られる場合は [コマンド制チャットの扱い](references/command-driven-chat.md) を参照する。
3. **Step 2（全体通読）**: `condensed.txt` を頭から最後まで読み飛ばしなく通読する。
4. **Step 3（構成確定）**: 運営 `#` コメントとコーナー定型句からセクション分割の単位を決める。
5. **Step 4（ハイライト抽出）**: チャット反応スパイクと `condensed.txt`・`comments` の感想を照らし合わせ、以下の優先度で候補を拾う。

| カテゴリ | 具体的なシグナル | 優先度 |
|---|---|---|
| **ハプニング・事件** | エラー・バグ・予期しない展開（運営 `#` の訂正・謝罪含む） | 高 |
| **感動シーン** | チャットに「泣いた」「エモ」「いい話」が集中 | 高 |
| **笑いどころ・ネタ** | チャットに「草」「ｗ」「マジか」が集中 | 中 |
| **正解・不正解の盛り上がり** | クイズ・ゲームでの正解発表、盛り上がる瞬間 | 中 |
| **話題の転換点** | コーナー開始、運営 `#` の「次の問題」等の節目 | 低 |
| **視聴者参加の見せ場** | 順番待ち `@` コメントへの返答、特定のやりとり | 低 |

### 配信時間別タイムスタンプ数の目安

- **30分以下**: 10〜15個 / **30〜60分**: 20〜30個 / **60分以上**: 30〜50個
- これはノルマではない。淡々とした回は少なくてよく、見どころ密集区間は増やしてよい。**数合わせの薄いタイムスタンプを 1 つ入れるより削る方を優先する。**

6. **Step 5（時刻確定・執筆・双方向検証）**: `timeline.txt` を `grep` して正確な開始時刻を確定し、下記ルールと [表現・検証ガイド](references/editorial-craft.md) に沿って執筆・推敲・双方向照合を行う。

## シーン説明の作成ルール

### 1. 「要約」ではなく「予告（Teaser）」にする【最重要】

オチ、クイズの答え、発言の核心など**読んで満足してしまう内容は絶対に書かない**。「好奇心の空白（Curiosity Gap）」を作り、クリックを誘う寸止め表現にする。

- **良い例**: `28:30 まさかの爆弾発言でチャット凍りつく`
- **悪い例**: `28:30 〇〇は嫌いだと発言し爆笑`（オチを書いているため NG）
- **連続ネタバレ禁止**: 「謎かけ」の直後に「答え」のタイムスタンプを置かない。
  - NG: `05:50 チャットを惑わす第1問` → `06:37 「牛乳を注ぐ女」スタート`
  - OK: `05:50 チャットを惑わす第1問` → `06:37 ようやく合点がいったチャット欄`

### 2. 自動文字起こしの誤変換を持ち込まない【最重要】

`sbv` の固有名詞・専門用語・早口は高確率で誤変換される（実例は `references/shizuku-profile.md` 参照）。

- **人物名・固有名詞は必ず正規表記に直す。** 作品名・曲名・固有名詞が `info` や通常チャットで確定できない場合は、必要最小限の Web 検索で一次情報を確認し、それでも不明なら書かない。
- **意味が壊れた行や 1 回きりの怪しい固有名詞を起点にしない。** 特に「配信者が言い間違えた／矛盾した／自爆した」と書きたくなったら、まず文字起こし誤認を疑い前後 30 秒とチャット反応を確認する（チャットが無反応なら誤変換）。
- 通常版 `live_chat` で複数人が独立して同じ語句を書いていれば裏取りに使える（OCR版では不可。音声認識とOCRの両方で一致した場合のみ信頼度が上がる）。

### 3. 必ず `sbv` の発言か運営 `#` コメントを起点にする

視聴者の通常チャットや `@` 質問・`#` 感想が面白くても、対応時刻の `sbv` に配信者の発言・反応が無ければタイムスタンプを作らない。

### 4. 文体・AI臭さ排除・簡潔さ

- **トーンとAI臭さ排除**: 指定されたトーン（既定 `standard`）に合わせつつ、「核心に迫る」「温度感」「〜を実施」などの AI 特有の抽象表現・硬い漢語は避け、具体的な行動や反応で書く（詳細は `references/editorial-craft.md`）。
- **簡潔さ**: 1つのシーン説明は **1〜2行（最大 30 文字程度）** に収める。`sbv` の丸写しはしない。
- **適切な粒度**: 「雑談」「ゲーム開始」などの大雑把な見出しや、2〜3分ごとの細かすぎる羅列は避ける。複数人配信では誰の発言か明記する。
- **効果的なテクニック**: 「」での一言引用（オチ以外）、行動→反応の矢印、名物の決め台詞やコールを取り入れる。

### 5. センシティブな話題の扱い

下ネタや際どい話題は、面白く盛り上がっていない限り取り上げない。盛り上がって見えても、**配信者が無理をして捌いている・閉鎖的ないじり・無自覚ないじめ構造**の場面は**絶対に出力しない**。配信者側が明確にノって展開を広げている場合のみ、直接的な語を避けて「持論が展開される」程度の匂わせに留める。

## 出力形式

YouTube コメント欄の「続きを読む」折りたたみ（目安 4000 文字）を考慮し、**冒頭に最も魅力的なハイライトと注意書きを配置**し、コピペしやすいよう **全体を 1 つのコードブロックにまとめて**出力する。

```text
【タイムスタンプ集】① オープニング〜〇問目
🌟ハイライト：05:50 （このパートで最も気になるシーンの寸止め説明）
※これは自動文字起こしからAIによって生成したタイムスタンプのため、ネタバレや誤り、時間のズレを含む可能性があります。

01:20 シーン説明
05:50 シーン説明
…

【タイムスタンプ集】② 〇問目〜〇問目
🌟ハイライト：28:30 （このパートの目玉シーン）

28:30 シーン説明
…
```

- **時刻形式**: 60 分未満は `MM:SS`（例: `05:50`）、60 分以上は `H:MM:SS`（例: `1:05:50`）。角括弧 `[ ]` は付けない。
- **注意書き**: コードブロック全体の**冒頭パートにのみ**記載する。
- **🌟ハイライト**: セクションごとに 1 つ設定し、**本文リストにも同じ時刻・同じ説明で再掲する**。単なる進行の節目より「結果や顛末が気になる」フック性のあるシーンを優先する。
- **セクション分割**: 1 セクション 10〜15 個が目安。20 個を超えそうな場合は自然な流れの切れ目でさらに分割する（単純な構成なら分割不要）。
- **終盤の省略**: 定型挨拶やコール練習の繰り返し区間は、特筆すべき要素がなければ省略可。

## 出力前チェックリスト（双方向照合・独立レビュー）

出力前に必ず以下を確認する（詳細は `references/editorial-craft.md`）。

- [ ] **既存確認**: 保存済みコメント・公式チャプターの本文と作業記録を確認し、投稿待ちの重複生成や未公開時の誤判定をしていないか
- [ ] **双方向照合**: 全見出しを `timeline.txt` で裏取りし、同時に `condensed.txt` の主要トピック・スパイクの取りこぼしがないか確認したか（推敲後の事実ズレ含む）
- [ ] **OCR制約（該当時）**: 時刻はすべて `sbv` 側で確定したか。チャットの件数・流速の断定や文字列の丸写し・裏取りをしていないか
- [ ] **Teaser化・AI臭さ排除**: オチ・連続ネタバレがなく、AI 調の抽象表現（「核心」「実施」「温度感」等）を具体的な行動・反応に直したか
- [ ] **誤変換・NGワード・個人情報**: 固有名詞は正規表記に直し、指定された NG ワード・チャットユーザー名（運営含む）・個人特定情報を除外したか
- [ ] **配慮と簡潔さ**: いじり／いじめ構造を拾っていないか。各説明は 1〜2 行（30文字程度）に収まり、数合わせの薄い項目が無いか
- [ ] **書式**: 全体が 1 つのコードブロックにまとまり、冒頭に注意書き、時刻は `MM:SS` / `H:MM:SS`（角括弧なし）、🌟ハイライトが本文にも再掲されているか
