# YouTube配信ログ → コメント用タイムスタンプ生成 (v2.1.0)

## 目的とスコープ

YouTube の配信ログを読み込み、視聴者が「見たい場面にすぐ飛べる」「思わずクリックしたくなる」タイムスタンプ付き目次を生成する。

- **出力先**: 生成した目次本文は**チャットに直接**返し、投稿用の完成ファイルは作らない。投稿・編集・削除はユーザーが手動で行い、エージェントは行わない。
- **他スキルとの境界**: YouTubeとFandom「動画・配信」の一覧照合、対象動画の選定、未収録ログの収集・ASR文字起こし、Wiki編集は別作業として扱い、このスキルの必須手順に含めない。

## 実行モードの分岐（即生成 vs 対話選択）【重要】

Step -1（既存確認）と前処理・概要把握を行ったあと、ユーザーの指示に応じて分岐する。

1. **パターンA：「さくっとタイムスタンプ作成して」等の即生成指示がある場合**:
   - 確認や質問を挟まず、**既定設定（話題階層・構造型 × `standard` トーン × バランス文字数 × パワーワード解禁 × 日本語）**でタイムスタンプ作成まで一気に進める。
   - **出力後のひとこと提案**: 作成後、「※今回は標準設定で作成しましたが、この配信は〇〇が多いため『△△型（例: ファン特化・区間リスト等）』も相性が良さそうです。切り替えますか？」と別パターンを提案する。
2. **パターンB：通常の依頼（またはユーザーが配信の思い出・思想を語った場合）**:
   - ユーザーが配信への思いやこだわりを多く語った場合は、まず [表現・検証ガイド](references/editorial-craft.md) の **grilling（設計ツリー・ラウンド制）** で意図と方向性を整理する（個人特化が強い場合は「感想を添える」構成も提案する）。
   - ログから配信内容を把握したうえで、**作成前に選択肢（型・装飾/絵文字/ファンマーク・文字数・ネタバレ加減・言語）と推奨案**を提示し、合意した方針で作成する。

## 配信者・知見蓄積・NGワードの確認

- **配信者の特定**: `info` と字幕冒頭を確認（ユーザー指定を最優先）。メイン配信者が **「しずく」**（または既定）なら [しずく固有リファレンス](references/shizuku-profile.md) を参照する。
- **汎用知見の蓄積**: ユーザーから「これも覚えておいて」と指示された汎用ルール・装飾の好み・NGワード等は [汎用蓄積リファレンス](references/custom-notes.md) に記録する（特定テーマや配信者の蓄積が増えたら専門リファレンスへ分離する）。
- **NGワード（投稿弾かれ対策）**: 事前または事後に NG ワードが指定された場合は、出力本文から該当語（表記揺れ含む）を確実に除外し、文脈を保った安全な言い換えに置換する。

## Step -1: 既存目次の充実度確認【最優先】

字幕の前処理や目次生成の前に、対象動画の既存コメントを確認する。詳細は [既存目次の確認・手動投稿手順](references/existing-timestamps.md) に従う。

1. **投稿待ち・公開未確認の記録を確認**: `awaiting_manual_post` / `posted_unverified` がある場合、新しい案を重ねて作らず続きの確認を行う。
2. **既存目次の充実度を判定**: 保存済み `comments` と `info` の公式チャプターの**本文を読んで**判断する（単発の時刻やファイルヘッダー・投稿日時は目次として数えない。ハッシュタグ `#` の有無も条件にしない）。配信の主要な話題を広く案内できる目次があれば生成を省略して終了する。
3. **不足・未収録時の再取得**:
   - **リポジトリ環境**（`tools/scripts/check_youtube_timestamps.py` がある場合）: `--refresh` で公開通常コメントを再取得して再判定する。取得失敗・不完全なら「目次なし」とみなさず保留する。
   - **単体環境**（ログファイルのみ渡された場合）: 添付された `comments` と `info` の範囲で判定し、公開コメントの再取得ができない環境であればその旨を明示して不足範囲の作成へ進む。
4. **手動投稿後の公開確認**: ユーザーが投稿したら、投稿（または投稿連絡）から**最低限 2〜3 分（運用上 3 分）待ってから**コメントを再取得して今回の本文を確認する。投稿直後の結果で非表示・スパムと断定しない。

既存確認で終了する動画には、以降の字幕必須・前処理手順を適用しない。

## 入力ファイルの特定と前処理

ファイル名は配信ごとに揺れるため、拡張子の完全一致ではなく**ファイル名に含まれるキーワード**で判定する。**`sbv` がある場合は `.srt` を無視し、`sbv` が無い場合のみ `.srt` をフォールバックとして使用する。**

| 種別 | 判定キーワード | 必須 | 備考 |
|---|---|---|---|
| ① 動画メタ情報 | `info` | 推奨 | タイトル・概要欄・企画構成・コマンド説明の確認 |
| ② 字幕・発言ログ | `sbv`（無ければ `.srt`） | **必須** | `sbv` 優先。どちらも無い／パース失敗時は停止して確認 |
| ③ ライブチャット | `live_chat`（`ocr` を含まない） | 推奨 | 通常版があればこちらだけを使い、OCR版は無視する |
| ③-B チャット（OCR復元） | `live_chat_ocr` / `ocr` | ③が無い場合の代替 | 信頼度が低いため **OCRモード制約** を厳守 |
| ④ 投稿後コメント | `comments` | Step -1 で使用 | 投稿日時（動画内時刻ではない）。感想のヒントにも使用可 |

### 前処理スクリプトの実行

新規生成が必要な動画では、規模にかかわらず**必ず同梱の `scripts/build_timeline.py` を実行してから読み始める**。

```bash
# クラウド/単体環境（ディレクトリ省略時は /mnt/user-data/uploads またはカレントディレクトリ）
python3 scripts/build_timeline.py <入力ディレクトリ>

# ローカルリポジトリなど複数動画が混在するディレクトリの場合（--video-id を必ず指定）
python3 scripts/build_timeline.py <入力ディレクトリ> --video-id <動画ID> --out-dir /tmp
```

- **`/tmp/condensed.txt`（通読用）**: 最初から最後まで通読し、話題・感情・チャット反応の流れを掴む。
- **`/tmp/timeline.txt`（時刻確定用）**: `grep` で該当発言を引き、**オチ直前ではなく「フリ・状況が理解できる 1〜5 秒前」の開始時刻**を確定する。
- スクリプト標準出力の運営 `#` コメント、コーナー切れ目候補、反応スパイク上位30も確認する。出力内のユーザー名は内部判断のみに使い、**最終出力には一切含めない**。

### OCRモード（`live_chat_ocr` のみ）の厳格な制約

`OCR復元チャットモード` の警告が出た場合、チャットは「約15秒刻みに丸められた、取りこぼしと誤読を含む断片」である。

- **出力の時刻は例外なく字幕（`sbv`/`srt`）側で確定する**。
- **件数・流速を根拠にしない**: 「コメントが爆速で流れた」等を書かない。薄い区間も字幕だけで判断する。
- **文字列のそのままの引用・固有名詞の裏取りに使わない**（同一時刻バケット内の並びも投稿順を保証しない）。

## タイムスタンプ抽出と執筆のルール

1. **Step 0〜2（検証・概要・通読）**: 字幕件数 > 0 を確認し、`info`（`@`/`#` コマンドがある場合は [コマンド制チャットの扱い](references/command-driven-chat.md) 参照）と `condensed.txt` を最後まで通読する。
2. **Step 3〜4（方針分岐・候補抽出）**: パターンBなら `grilling` で選択肢を提示して方針を確定する。優先度（ハプニング・感動 ＞ 笑い・盛り上がり ＞ 話題転換・視聴者やりとり、または特殊性癖・セトリ等の指定軸）で候補を拾う。目安は 30分以下: 10〜15個 / 30〜60分: 20〜30個 / 60分以上: 30〜50個（薄い項目は削る）。
3. **Step 5（執筆・デザイン・双方向照合）**: `timeline.txt` で時刻を確定し、[表現・検証ガイド](references/editorial-craft.md) に沿って執筆・検証する。

### 執筆時の絶対ルール

- **字幕（または運営 `#`）起点**: 視聴者チャット単独でタイムスタンプを作らない。
- **誤変換を持ち込まない**: 自動文字起こしの誤変換は正規表記に直す。意味が壊れた行を「言い間違い／自爆」と誤認しない。固有名詞がログで確定できないときは最小限の Web 検索で確認し、不明なら書かない。
- **コラボ・ゲストの出入りフォロー**: 複数人や凸待ち・ゲスト回では、合流・離脱の時刻や誰の発言かを分かりやすく明記する。
- **リズムと視認性**: 同じ文型・文字数の連続を避け、選択された装飾・文字数設定・絵文字/ファンマーク方針に従って緩急をつける。AI 調の抽象語（「核心に迫る」「温度感」「〜を実施」「予想外の展開」等）は使わない。
- **センシティブな話題**: 無理をして捌いているいじり／いじめ構造は出力しない。配信者が明確にノっている場合のみ直接語を避けて匂わせに留める。

## 出力形式とコメント分割機能

- **時刻形式**: 60 分未満は `MM:SS`（例: `05:50`）、60 分以上は `H:MM:SS`（例: `1:05:50`）。既定は角括弧なし（装飾指定で `〔05:50〕` や `[05:50]` を選んだ場合はそれに従う）。
- **折りたたみ対策（1〜3行目）**: 冒頭（`続きを読む` の前）には注意書きと配信開始（声入り）時刻を置き、ネタバレになりうる見どころは 4 行目以降に配置する。`【タイムスタンプ集】` やハイライトの重複再掲は原則使わない。
- **長文時のコメント自動分割**: YouTube の 1 コメント上限（安全目安 **8,000 文字**、最大 10,000 文字）を超える場合は、セクションの切れ目で `親コメント`（末尾に `↓↓ 続きは返信欄へ ↓↓`）と `返信コメント`（別コードブロック）に自動分割する。

## 出力前チェックリスト

- [ ] **既存確認**: 保存済みコメント・公式チャプターの本文と作業記録を確認し、重複生成や未公開時の誤判定をしていないか
- [ ] **モード適合**: パターンAなら既定で即生成＋最後に別パターン提案、パターンBなら対話で決めた型・装飾・文字数・言語・ファンマークに沿っているか
- [ ] **双方向照合**: 全見出しを `timeline.txt`（1〜5秒前フリ調整含む）で裏取りし、`condensed.txt` の主要トピック漏れがないか（推敲後の事実ズレ含む）
- [ ] **OCR制約（該当時）**: 時刻は字幕側で確定し、件数・流速断定や文字列の引用・裏取りをしていないか
- [ ] **表現・配慮・NGワード**: AI 臭い抽象語・誤変換・指定 NG ワード・ユーザー名が混ざっていないか。ゲスト出入りは明確か
- [ ] **書式・文字数**: 時刻表記が統一され、上限超過時は適切に分割されているか（音声レベルの微調整注意点を必要に応じて添えたか）
