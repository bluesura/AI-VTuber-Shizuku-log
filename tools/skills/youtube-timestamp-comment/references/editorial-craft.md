# 表現チューニング・スタイル設計・根拠検証 (v2.1.0)

国内外のタイムスタンプ実例と `evidence-first-writing` / `grilling` の知見を統合し、作成スタイル・デザイン装飾・基礎テクニック・対話フローをまとめたガイド。

## 1. 作成スタイル（5つの型）

配信のジャンルやユーザー目的に応じて選ぶ（パターンA即生成時は **② 話題階層・構造型** が既定）。

| 型 | 向いている配信・目的 | 特徴と構成 |
|---|---|---|
| **① 厳選ハイライト型** | 長尺雑談・忙しい人向け | 1時間あたり 10〜20 項目に厳選し、全体像と目玉だけをサクッと追える構成 |
| **② 話題階層・構造型（既定）** | 雑談・ゲーム実況・企画回 | 親見出しの下に `├` `└` で小ネタ・発言（子）をぶら下げ、空行でブロック化（時間なしの補足行も可） |
| **③ ここ好き・ファン特化型** | 推し活・リアクション・**特殊性癖特化** | 生セリフ「」・`w`・絵文字・感想を添えて温度感を伝える。**悲鳴・くしゃみ・噛み・お水等のピンポイント特化**にも対応 |
| **④ セトリ・インデックス型** | 歌枠・マシュマロ・大人数コラボ | `MM:SS [曲番] 曲名 / アーティスト (年)` やマロ番号・**ゲストの出入り（合流・離脱）**など検索性を最優先 |
| **⑤ 区間リスト型（ネタバレ完全ゼロ）** | シリーズ企画・大会・オムニバス | 文章を極力書かず `1. 00:00〜15:20` / `2. 15:20〜32:10` のように切れ目と区間だけを示す |

## 2. 調整軸（パターンBで選択・カスタマイズ可能）

| 軸 | 選択肢 | 既定（パターンA） |
|---|---|---|
| **トーン** | `standard`（リスナー標準） / `straight`（固め・簡潔） / `soft`（やわらかめ） / `playful`（面白さ全振り） | `standard` |
| **1行の文字数** | `短め`（スマホ折り返し防止・〜20字） / `バランス`（〜30字） / `長め`（背景や感想込み） | `バランス` |
| **ネタバレ加減** | `オチ隠し強め`（完全Teaser） / `パワーワード解禁`（声やリアクションが本体の引用は出す） / `ありのまま` | `パワーワード解禁` |
| **デザイン・装飾** | 罫線（`├` `└` `●──●`）・括弧（`【】` `〔〕` `«»` `()`）・YouTube記法（`*太字*` `-打消し-`）の積極活用 or シンプル | シンプル階層 |
| **絵文字・ファンマーク** | 使わない（文字のみ） / シンプル（1〜2種） / 華やか。**ユーザーのファンマーク指定**（例: 🍣, 💧）があれば見出しや注目行に配置 | シンプル |
| **言語** | 日本語のみ / 指定言語（英語等） / **日本語＋他言語の併記**（海外ファン向け） | 日本語のみ |
| **感想の添え方** | なし（目次のみ） / 末尾や冒頭に一言感想・推しポイントを添える（思い入れを語った場合は推奨） | なし |

## 3. タイムスタンプ制作の基礎テクニック

国内外の職人知見から取り入れた基本原則：

1. **状況が理解できる「1〜5秒前のフリ」から打つ**: オチの瞬間ピッタリではなく、話題の入り・前置き・質問が聞こえる 1〜5 秒前を `timeline.txt` から確定する（3秒遅れより数秒早い方がコンテキストが伝わる）。
2. **「声を被せない」調整の限界と引き継ぎ**: テキスト字幕（`sbv`/`srt`）のみを扱う環境では、無音ギャップやリップ音・息継ぎ等の音声波形は確認できない。AI 側は文の頭・会話の切れ目に時刻を合わせ、音声レベルの 0.5〜1 秒微調整はユーザー投稿時の任意確認として任せる。
3. **YouTube「続きを読む」折りたたみ対策（1〜3行目）**: コメント冒頭 3〜4 行は折りたたまれないため、注意書きと配信開始（声入り）時刻を置き、ネタバレになりうる見どころは 4 行目以降に配置する。
4. **リズムと緩急**: 同じ文型・文字数の連続を避け、短い体言止め・生セリフ「」・`├` `└` の階層（文末時刻 `«12:42»` や時間なし補足行も含む）・空行ブロックを組み合わせる。
5. **NGワード・誤解されるワードの見直し**: 事前・事後に指定された NG ワードや差別語・過激すぎる直接表現は安全な言い換えに直す（ただし AI 側で「特定の単語がスパム原因だった」と断定はしない）。

## 4. 「AI臭い見出し」の排除と配信スラングの保護

- **避けたい AI 調表現**: `温度感の高い雑談` / `熱量のある語り` / `解像度が上がる` / `核心に迫る` / `思考のOS` / `静かに崩壊` / `幕を開ける` / `〇〇を実施` / `多角的な検証` / `予想外の展開に` / `〜した結果…`
- **保護する配信語彙**: 「草」「エモい」「限界化」「沼る」「総ツッコミ」「神回」等のリスナー語彙はトーンに合わせて残す。

## 5. パターンB：grilling 対話設計と外部調査

- **対話の進め方（ラウンド制）**: ユーザーが「相談したい」「方向性を掘りたい」場合や配信への思い出・思想をたくさん語った場合は、決めるべき分岐（設計ツリー）のうち、いま決められる問いを **1ラウンド 1〜3 問** に絞って投げ、必ず **推奨案（➡️）と「選ぶとどう変わるか」** を添えて確認する。
- **外部調査**: 固有名詞・曲名・コラボ相手がログから確定できないときだけ、問いを 1 つに絞って Web 検索で公式表記を確認する（見つからなければ書かない）。

## 6. 双方向照合（出力前検証）

1. **案 → `timeline.txt`**: 全見出しについて時刻前後を確認し、人物名・行動・因果・引用「」が字幕に実在するか裏取り（推敲後の事実ズレも再確認）。
2. **`condensed.txt` → 案**: 主要なコーナー・スパイク・ゲスト出入りの取りこぼしがないか確認。
3. **最終点検**: AI 臭い抽象語・指定 NG ワード・文字数・装飾ルール違反がないか確認する。
