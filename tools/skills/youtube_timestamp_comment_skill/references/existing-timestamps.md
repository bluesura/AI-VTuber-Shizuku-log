# 既存目次の確認・手動投稿・コメントの再収録

対象動画のコメント確認から、ユーザーの手動投稿後の公開確認までを扱う。YouTubeとFandomの一覧照合やWiki編集は別スキルの作業であり、実行の前提にしない。

## 実行環境による分岐

- **リポジトリ環境**（`tools/scripts/check_youtube_timestamps.py` が存在する場合）: 下記の補助コマンドで保存済みコメントの確認と再取得を行える。
- **単体環境**（チャットにログファイルのみ添付された場合）: 添付された `comments` ファイルと `info` ファイルの本文を読んで充実度を判定する。ネット接続や補助スクリプトがない環境では公開コメントの再取得はできないため、不足や未収録があればその旨を明示して判断を仰ぐか、提供済みログの範囲で作成する。

## 目次の充実度を判断する

通常コメントの本文を読む。ライブチャットの時刻、コメント投稿日時、ファイルヘッダーは既存目次として数えない。`03:22`、`1:00:25`、括弧付き `[03:22]`、同じ動画の時刻付きリンクが候補となる。ハッシュタグの有無は条件にしない。

| 確認できた内容 | 判断と次の操作 |
|---|---|
| 主要な話題を広く案内する目次 | 十分。生成を省略する |
| 単発の時刻・一部の見どころのみ | 部分的。再取得してから不足範囲を検討する |
| 歌枠の曲目一覧 | 曲探しには十分。雑談等の案内も必要か、配信内容と依頼の範囲から判断する |
| 概要欄に公式チャプター | コメントとは区別して記録し、重複を避ける。章が粗い場合は不足を説明する |
| 目次がない | 再取得してから生成の要否を判断する |
| 取得失敗・不完全・判断不能 | 保留。目次なしと確定しない |

項目数や最初と最後の時刻だけで充実度を確定しない。複数コメントで十分に案内されている場合もある。不足すると判断したら理由（例: 曲目は揃っているが長い雑談部分が未収録）と作成範囲を示し、補足で足りる場合は補足を優先する。他人のコメントを改変したり、その人が書いたように案を扱ったりしない。

## リポジトリの補助コマンド

リポジトリルートから実行する。

```bash
# 保存済みコメントだけを確認する
python tools/scripts/check_youtube_timestamps.py <動画ID> --check-only

# 不足・未収録の場合、または手動投稿後に公開コメントを再取得する
python tools/scripts/check_youtube_timestamps.py <動画ID> --refresh
```

複数IDを指定できる。このツールは時刻の検出とコメントの収集を担当し、**目次の充実度や投稿状態は判定しない**。出力JSONの `generate` は「時刻があるか」に基づく補助値であり、本スキルの最終判断に直結させない。

| ツールの結果 | スキル側で行う判断 |
|---|---|
| `existing_local` / `existing_after_refresh` | 本文を読んで充実度を確認。不足なら `--refresh` 後に再判定する |
| `needs_generation` | 再取得では時刻なし。公式チャプターと投稿待ち記録も確認して作成を判断する |
| `refresh_required` | ローカルだけでは不足。再取得してから判断する |
| `refresh_failed` | 保留。生成へ進まない |

引数なしの既定動作はローカルに時刻があれば再取得を省略するため、「時刻はあるが目次が不足する」場合は明示的に `--refresh` を使う。通常コメントだけを既存の匿名化・書式で更新し、旧コメントは `outputs/youtube-timestamps/comment-refresh/` へ退避する。匿名化前の著者情報や対応表は保存しない。

## 手動投稿を挟む進捗

リポジトリ環境では、案を作成した動画の進捗を Git 管理外の `outputs/youtube-timestamps/status/<動画ID>.json` に記録する（単体環境では同等の作業記録またはチャット上の合意で管理する）。

記録項目: 動画ID、状態、更新日時（タイムゾーン付き）、提示本文の SHA-256（コードブロック内を LF 統一・末尾改行除去・UTF-8）、既存目次の評価と不足理由、公開確認の結果・確認日時（分かれば `posted_at`、次の確認目安 `check_after`）。認証情報や視聴者の表示名は含めない。

| 状態 | 意味と次の操作 |
|---|---|
| `awaiting_manual_post` | 案を提示済み。ユーザーの投稿を待つ。同じ案を新規生成しない |
| `posted_unverified` | ユーザーから投稿済みとの連絡あり。再取得して今回の本文を探す |
| `verified` | 今回の本文を公開取得し、匿名化したコメントファイルへ保存できた |
| `check_blocked` | 取得失敗等で判断できない。前の投稿状態を保持し、確認だけを再開する |

### 投稿後の公開確認と待機ルール

1. ユーザーの「投稿した」という連絡で `posted_unverified` に進める。
2. **投稿から最低限 2〜3 分（運用上は 3 分）待ってから再取得する。** 投稿時刻が不明なら投稿連絡から 3 分空ける。投稿直後の結果で非表示と判断しない。
3. 他の既存タイムスタンプが見つかっただけで `verified` にしない。今回の本文に特有の見出し・時刻・順序を照合する（改行等の表示差は許容）。
4. `verified` は確認時点の観測であり、後日見えなくなったら過去の確認記録を残して `posted_unverified` に戻す。

## ユーザー提供リストとの照合と既存本文の改稿

ユーザーのURL一覧・本文は収集済み公開コメントと区別し、シークレットウィンドウでの見え方もスパム判定の確定根拠にしない。

- リスト外で目次不足が新たに見つかった場合は、作成前にユーザーへ確認する。
- 本文が提供されている動画は、元ログへ照合して配信固有の言い回しを保ちつつ、過剰な煽り・ネタバレ・誤認識を整理する。提案は **1動画ずつ** 主な変更理由とコピー可能な本文を提示する。
- 既存本文の改善依頼が明示されている場合は、投稿待ち・公開未確認でも改稿を行える（旧案との関係を記録し、新規別投稿扱いにしない）。

## 公開未確認・スパム判定への対応

YouTubeはコメントを自動判定し確認のため保留することがある（[公式ヘルプ](https://support.google.com/youtube/answer/9482362?hl=ja)）が、公開取得できないことだけでスパム・削除の原因を断定しない。

- 取得できなくても今回の本文を捏造して `comments.txt` に追記しない。
- 「投稿済み・公開未確認」と報告して止める。短時間の再取得ループ、再投稿の催促、自動での文面変更・予約監視は行わない。
- 「特定の文字数やハッシュタグなら必ず公開される」等の保証はしない。公開の可否と本文品質は分けて報告する。

完了時は動画IDごとに、既存目次の評価、生成／省略／保留、投稿状態、コメントファイルの更新結果を簡潔に示す。
