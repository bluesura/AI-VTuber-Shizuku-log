# 表現チューニング・根拠検証・品質レビュー

`evidence-first-writing` のエッセンス（根拠照合・AI臭さ排除・外部調査・対話チューニング・独立評価）を、YouTube タイムスタンプ向けに凝縮したガイド。

## 1. トーン（固さ・やわらかさ・面白さ）のチューニング

ユーザーから特別な指定がなければ **`standard`（既定）** で即座に生成する。指定があれば以下のプリセット（または自由指定）に合わせて文体を調整する。

| プリセット | 特徴・使いどころ | 語彙と表現の目安 |
|---|---|---|
| **`standard`（既定）** | ストレートなリスナー目線。迷ったらこれ | 「草」「エモい」「総ツッコミ」等の配信語彙を自然に混ぜつつ、簡潔な Teaser にする |
| **`straight`（固め・簡潔）** | 事実ベース・スラング控えめ。公式寄りや記録重視の回 | ネットスラングを抑え、起きた出来事・話題を端正な体言止めや短い文で伝える |
| **`soft`（やわらかめ・親しみ）** | 雑談・ASMR・ほのぼの回向け | 角の立たない穏やかな言い回しにし、空気感や配信者のリアクションを柔らかく伝える |
| **`playful`（面白さ・ネタ重視）** | ハプニング・ゲーム・盛り上がり回向け | 本人の一言「」引用や「行動→反応」の矢印を強めに効かせ、思わず笑う・気になるフックを作る |

## 2. NGワード（投稿弾かれ対策）の事前・事後指定

YouTube のコメントフィルタや配信側のNGワード設定で投稿できない場合に対応するため、ユーザー指定の NG ワードを確実に回避する。

- **事前指定**: 依頼時に NG ワード（例: `NGワード: 〇〇, △△`）が指定された場合は、出力案および注意書き以外の本文から該当語（表記揺れ・部分一致を含む）を除外し、文脈を保った安全な言い換えや匂わせ表現に置き換える。
- **事後指定（改稿）**: 投稿後に弾かれた・公開未確認になった際、ユーザーから避けたい語句の指定を受けたら、該当タイムスタンプだけを配信文脈と時刻を保ったまま書き換える。
- **原則**: 「特定の単語がスパム原因だった」とエージェント側で勝手に断定はしない。あくまで「ユーザーが指定した回避ワードを確実に外す」ことに徹する。

## 3. 「AI臭い見出し」の排除と配信スラングの保護

タイムスタンプは 30 文字前後の短文であるため、AI 特有の抽象的・大げさな定型句が最も目立ちやすい。以下を見出しに使わず、**配信で実際に起きた具体的な行動・言葉・反応**で書く。

| 避けたい AI 調パターン | 具体的な NG 例 | 直し方（具体的な行動・反応へ） |
|---|---|---|
| **質感を装う抽象語** | 温度感の高い雑談 / 熱量のある語り / 解像度が上がる | 何をどう語ったか（例: `〇〇愛を3分間ノンストップで語る`） |
| **大げさな熟語・比喩** | 配信の核心に迫る / 思考のOS / 静かに崩壊 / 幕を開ける | 実際の変化・結果の寸止め（例: `突然の仕様変更にチャット困惑`） |
| **硬い漢語・名詞化** | 〇〇を実施 / 多角的な検証 / 価値を最大化 | 平易な動詞（`〇〇を試す→予想外のオチ`） |

**保護する表現**: 「草」「エモい」「限界化」「沼る」「総ツッコミ」「神回」など、配信カルチャーに根付いたリスナー語彙は AI 臭さとして削らず、トーンに合わせて「味」として残す。

## 4. 必要なときだけの外部調査（固有名詞の確定）

`sbv` の自動文字起こしで作品名・曲名・人名・専門用語が崩れており、`info` や通常 `live_chat` からも正規表記を確定できない場合は、**問いを 1 つに絞って Web 検索（外部調査）を行い、公式表記を確定する。**

- 検索で見つからないからといって推測で当て字を作らない（確認できなければその語を見出しに使わない）。
- 外部情報から配信内で起きていない出来事を補作しない。

## 5. 対話チューニング（grilling：方向性を掘るモード）

基本は質問せず即生成するが、以下のいずれかに当てはまる場合のみ、作成前に **1 回あたり 1〜3 問** に絞って対話で方向性を詰める（推奨案と「選ぶと何が変わるか」を添える）。

1. ユーザーが「相談しながら作りたい」「方向性を一緒に決めたい」と明示した場合
2. 配信構成が特殊で方針が大きく割れる場合（例: 歌枠で曲目リストに特化するか雑談も拾うか、コラボ回で誰中心の見出しにするか、既存コメントへの「追記分」だけ作るか「全体改稿」にするか）

## 6. 双方向照合と初見レビュー（出力前検証）

案を書き終えたら、出力前に次の 3 段階でセルフチェック（利用可能なら独立したレビュー文脈）を通す。

1. **案 → `timeline.txt`（順方向照合）**: 全タイムスタンプについて時刻前後を確認し、人物名・行動・因果・否定・引用「」が `sbv` に実在するか裏取りする。**推敲で見出しを面白く整えたあと、元の事実からズレていないか必ず再確認する。**
2. **`condensed.txt` → 案（逆方向照合）**: 配信の主要なコーナー・大きなスパイク・ハプニングが抜け落ちていないか確認する。
3. **初見リスナー視点レビュー**:
   - オチや答えをバラしていないか（直前直後の連続ネタバレ含む）
   - 「核心」「実施」「温度感」などの AI 臭い抽象表現が残っていないか
   - ユーザー指定の NG ワードが 1 つも残っていないか
