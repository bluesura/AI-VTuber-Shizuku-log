# コマンド制の配信チャット（`@` / `#`）の扱い

**このファイルは、クイズ・ゲームなど進行管理のあるイベント配信でのみ参照する。**

雑談配信・ASMR・歌枠などの通常配信では `@` `#` コマンドは基本的に登場しない。次のいずれかに該当する場合のみ開く。

- `info` ファイルの概要欄に `@` `#` コマンドの説明が書かれている
- `live_chat` ファイルの本文（ユーザー名の後）が `@` や `#` で始まる行が実際に見られる
- **OCR復元版（`live_chat_ocr`）しか無く、`info` の概要欄にコマンドの説明がある**（記号が脱落している可能性があるため、行の見た目だけで判断しない）

## コマンド体系

まず `info` ファイルの概要欄にある配信独自のコマンド説明を確認し、次の一般的な意味と照合する。

- `@` なし = 普通のコメント（ランダムに反応）
- `@` 先頭 = 順番待ち列に入るコメント（質問・話しかけ）
- `#` 先頭 = 配信者にスルーされるコメント（感想・リアクション専用）

## コメント種別の判別

| 行の先頭パターン | 意味 | 扱い |
|---|---|---|
| `@ユーザー名: （普通の本文）` | 通常のビューワーコメント | 視聴者反応として参照する |
| `@ユーザー名: @（本文）` | 順番待ち列コメント | 配信者が応じた可能性あり。`sbv` の返答と照合 |
| `@ユーザー名: #（本文）` | 視聴者の感想・リアクション専用 | 反応の補足情報として参照 |
| **運営者の `#` コメント** | 配信設定・進行の説明・訂正 | シーン理解に有用（例: `#1問目` `#正解です！` `#次へ行きます`） |

特定のユーザーが `#` 付きで進行情報・訂正・補足を繰り返し投稿していれば運営アカウントとみなしてよい。ただし**チャットのユーザー名は出力に一切含めない**。

## 該当条件で開いたが、実際には 0 件だった場合

`info` に説明があっても実際の配信では使われなかったケースがある。

1. `grep -c ': #' *live_chat*.txt` と `grep -c ': @' *live_chat*.txt` で本当に 0 件か確認する（`build_timeline.py` が正常に `chat` 件数を読み込めていることも確認し、パース失敗と取り違えない）。
2. どちらも 0 件なら運営 `#` コメントによる節目検出は諦め、`sbv` の発言のみを起点とする。

**OCR復元版（`live_chat_ocr`）の注意点**: OCRでは行頭の `#` `@` が脱落・誤読されやすい。概要欄にコマンド説明があるのに 0 件なら、まず記号脱落を疑い、運営らしきアカウントが進行情報（「1問目」「正解です」等）を記号なしで投稿していないか本文を `grep` する。それでも判別できなければ無理に推定せず `sbv` のみを起点とする。
