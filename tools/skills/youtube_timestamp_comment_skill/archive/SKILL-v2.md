# YouTube配信ログ → コメント用タイムスタンプ生成

## 目的

YouTube からダウンロードした 4 種類の生ファイルを直接読み込み、YouTube コメント欄に貼付可能なタイムスタンプ付きシーン説明を生成する。

単なる事務的な事象の羅列（議事録）ではなく、配信の熱量や文脈（Vibe）が伝わる魅力的な目次を作る。特に **「要約」ではなく「予告（Teaser）」** として機能させ、視聴者が「何があったのか」気になって思わずタイムスタンプをクリックしたくなるよう誘導することが最大の目的である。

出力は**チャットに直接**返す。ファイルは作らない。

## 配信者の扱い

メイン配信者は基本的に**「しずく」**として扱ってよい。ただしイベント回などで配信者が入れ替わる可能性があるため、次を確認してから書き始める。

- info ファイルのタイトル・概要欄、sbv ファイル冒頭の自己紹介に別名義が出ていないか
- ユーザーが配信者名を明示している場合は、そちらを最優先で採用する

以降の記述で「しずく」とあるのは「その回のメイン配信者」と読み替えること。

---

## 入力ファイルの特定

通常は `/mnt/user-data/uploads/` に置かれている。**ファイル名は配信ごとに揺れる**（`◯◯_ja_sbv.txt` / `◯◯.sbv.txt` / `◯◯_live_chat.txt` など）ため、**拡張子の完全一致で探してはいけない。ファイル名に含まれるキーワードで判定する。**

| 種別 | 判定キーワード（ファイル名に含まれる） | 必須 |
|------|--------------------------------|------|
| ① 動画メタ情報 | `info` | 推奨 |
| ② 字幕・発言ログ | `sbv` | **必須** |
| ③ ライブチャット | `live_chat` | 推奨 |
| ④ 投稿後コメント | `comments` | 任意 |

- **`.srt` ファイルは無視する。** sbv ファイルと内容が重複するうえ、行分割・番号付けが異なり照合を誤る原因になる。
- glob は `*sbv*.txt` / `*live_chat*.txt` / `*info*.txt` / `*comments*.txt` の形で書く
- 欠けているファイルがある場合は、その旨を伝えたうえで揃っているファイルだけで進めてよい
- ただし **sbv ファイルは必須**。無い場合、またはパースに失敗した場合は、ハルシネーション防止のため作業を止めてユーザーに確認する

## 各ファイルのフォーマット

### ① info ファイル（動画メタ情報）

```
# 動画情報
タイトル  : （動画タイトル）
投稿日    : YYYY-MM-DD
動画ID    : （ID文字列）
URL       : https://www.youtube.com/watch?v=（ID）

────────
【説明】
────────
（概要欄テキスト）
```

読み取るべき情報:

- 配信タイトル・投稿日（出力ヘッダーへの参照用）
- 概要欄のコマンド説明（`@` `#` プレフィックスの意味を理解するために必須）
  - `@` なし = 普通のコメント（ランダムに一つ反応）
  - `@` 先頭 = 順番待ち列に入るコメント（必ず読まれる）
  - `#` 先頭 = しずくにスルーされるコメント（感想・リアクション専用）
- 概要欄に書かれた企画・コーナー名（構成の予告になっていることが多い）

### ② sbv ファイル（字幕・発言ログ）

**SBV 標準形式**。1 エントリは「開始時刻,終了時刻」の行 → 次の行が発言内容、の 2 行構成。エントリ間は空行で区切られる。

```
0:03:11.400,0:03:20.910
こんにちは。

0:03:44.920,0:03:47.760
配信の[音楽]感想はシャープしずく実験

0:05:09.740,0:05:15.829
[音楽]
```

- 時刻は `H:MM:SS.mmm`。**カンマ区切りで開始・終了が並ぶ**（`[H:MM:SS]` のような角括弧形式ではない）
- 使用するのは**開始時刻のみ**
- 改行コードが CRLF（`\r\n`）のことがあるので `\r` を除去してからパースする
- `[音楽]` / `🎵 [音楽]` は BGM 区間。発言テキストの途中に `[音楽]` が挿入されることも多い
- これは**配信者の発言のみ**を記録したもの
- **1 エントリは 2〜4 秒程度で、文の途中でぶつ切りにされる。** 1 エントリだけ読んでも意味が取れないので、必ず前後を連結して読む（後述の集約タイムラインを使う）
- live_chat ファイルの `[M:SS]` と表記単位が異なる。相互参照時は秒数に揃えて照合する（sbv の `0:04:43` = チャットの `[4:43]`）

### ③ live_chat ファイル（ライブチャットログ）

```
# ライブチャット一覧
# 動画: （タイトル）
# URL : （URL）
# 件数: （件数）

[-M:SS] @ユーザー名: コメント内容   ← 配信開始前（負の時刻）
[M:SS] @ユーザー名: コメント内容    ← 配信中（正の時刻）
```

- タイムスタンプ形式は `[M:SS]`。60分を超える場合は `[H:MM:SS]` になることもある
- 負のタイムスタンプは配信開始前の待機中コメント
- 各行は `[タイムスタンプ] @ユーザー名: メッセージ`

コメント種別の判別（info ファイルのコマンド説明と照合する）:

| 行の先頭パターン | 意味 | 扱い |
|----------------|------|------|
| `@ユーザー名: （普通の本文）` | 通常のビューワーコメント | 視聴者反応として参照する |
| `@ユーザー名: @（本文）` | 順番待ち列コメント（質問・話しかけ） | 配信者が応じた可能性あり。sbv の返答と照合 |
| `@ユーザー名: #（本文）` | 視聴者の感想・リアクション専用 | 反応の補足情報として参照 |
| **運営者の `#` コメント** | 配信設定・ゲーム進行の説明・訂正 | シーン理解に非常に有用（例「#1問目」「#正解です！」「#次へ行きます」） |

運営 `#` コメントの見分け方: 特定のユーザーが `#` 付きで進行情報・訂正・補足を繰り返し投稿していれば、そのアカウントは運営とみなしてよい（例 `@aki5503: #すみません、答え設定間違えましたｗｗ`）。配信の内部進行を知る重要な手がかりなので積極的に参照する。ただし**チャットのユーザー名は出力に一切含めない**。

#### コマンドが 1 件も使われていない配信の扱い

**雑談回・ASMR回・歌枠などでは、`@` も `#` も 1 件も出現しないことがある**（クイズやゲームの進行管理が不要なため）。この場合の手順:

1. まず本当にゼロかを確認する。`grep -c ': #' *live_chat*.txt` と `grep -c ': @' *live_chat*.txt` を実行する
2. どちらもゼロなら、**運営 `#` コメントによる節目検出は諦め、sbv ファイルの発言のみを起点とする**
3. 節目（コーナーの切れ目）は、後述の「コーナー検出」で配信者の定型句から拾う
4. **「運営コメントが 0 件」という出力を、パース失敗と取り違えないこと。** 前処理スクリプトが表示する件数（sbv 件数・chat 件数）が正常であることを先に確認する

---

### ④ comments ファイル（投稿後コメント）

```
# コメント一覧
# 動画: （タイトル）
# URL : （URL）
# 件数: （件数）

[YYYY-MM-DD HH:MM UTC] @ユーザー名（👍 N）
コメント内容
```

- 動画投稿後の通常コメント。時刻は動画内時刻ではなく投稿日時なので、シーンの時刻とは対応しない
- 視聴後の感想・評価として参照する
- 件数が少ない場合や、罵倒・スパム系のみの場合は無視してよい

## 前処理

規模にかかわらず、**必ず次のスクリプトを実行してから読み始める**。sbv は 1 エントリ 2〜4 秒でぶつ切りにされているため、生のまま読むと文脈が繋がらず、時刻照合もずれてハルシネーションの原因になる。

スクリプトを `/tmp/build_timeline.py` に保存して実行する。

```python
import re, sys, glob
from collections import Counter

BASE = sys.argv[1] if len(sys.argv) > 1 else "/mnt/user-data/uploads"

# 盛り上がりの指標になる語
REACT = ["草","ｗ","笑","泣","エモ","すご","ヤバ","やば","マジ","まじ","神","かわい","かわよ",
         "!?","！？","？？","88","おめ","天才","尊い","惜し","正解","不正解","www",
         "たすかる","助かる","へぇ","ひゅー","ヒュー","えぇ"]
# 挨拶・定型句はシーンとしては無価値なのでスパイク検出から除外する
NOISE = ["待機","おつしず","パンパカ","お疲れ","おつかれ","こんばんは","こんにちは",
         "こんちわ","おはよう","初見","乙"]
# コーナーの切れ目を示す配信者の定型句
CORNER = ["コメントで教えて","コメントで自慢","コメントしてください","ここで1つ",
          "ではこう聞きましょう","質問です","コーナー","でいきますよ","1つに絞る",
          "お知らせ","次は","いってみましょう"]

def to_sec(ts):
    neg = ts.startswith("-"); s = 0
    for p in ts.lstrip("-").split(":"): s = s * 60 + int(float(p))
    return -s if neg else s

def fmt(sec):
    h, r = divmod(abs(sec), 3600); m, s = divmod(r, 60)
    sign = "-" if sec < 0 else ""
    return f"{sign}{h}:{m:02d}:{s:02d}" if h else f"{sign}{m}:{s:02d}"

# ---- sbv（SBV標準形式: 開始,終了 → 次行が本文）----
sbv = []
for path in glob.glob(f"{BASE}/*sbv*.txt"):
    lines = open(path, encoding="utf-8", errors="replace").read().replace("\r", "").splitlines()
    for i, line in enumerate(lines):
        m = re.fullmatch(r"(\d+(?::\d{2})+(?:\.\d+)?),(\d+(?::\d{2})+(?:\.\d+)?)", line.strip())
        if m and i + 1 < len(lines) and lines[i + 1].strip():
            sbv.append((to_sec(m.group(1)), lines[i + 1].strip()))
sbv.sort()

# ---- live_chat ----
chat = []
for path in glob.glob(f"{BASE}/*live_chat*.txt"):
    for line in open(path, encoding="utf-8", errors="replace"):
        m = re.match(r"\[(-?\d+(?::\d{2})+)\]\s*(@[^:]+):\s*(.*)", line.replace("\r", "").rstrip("\n"))
        if m: chat.append((to_sec(m.group(1)), m.group(2), m.group(3).strip()))
chat.sort()

# ---- 検証: ここで止まったら先に進まない ----
assert sbv, "sbv のパースに失敗（0件）。ファイル名・フォーマットを確認し、作業を止めてユーザーに確認する"
print(f"== 読み込み結果 ==\n  sbv: {len(sbv)}件 / 最終 {fmt(sbv[-1][0])}\n  chat: {len(chat)}件")

# ---- 1) 精密タイムライン（最終的な時刻確定用。grepして使う）----
with open("/tmp/timeline.txt", "w", encoding="utf-8") as f:
    for t, text in sbv:
        near = [c for ct, _, c in chat if t - 15 <= ct <= t + 30]
        f.write(f"[{fmt(t)}] SBV: {text}\n")
        for c in near[:6]: f.write(f"          chat: {c}\n")

# ---- 2) 集約タイムライン（通読用。20秒窓で本文を連結）----
W = 20
with open("/tmp/condensed.txt", "w", encoding="utf-8") as f:
    t, end = 0, sbv[-1][0] + W
    while t < end:
        txt = "".join(x for s, x in sbv if t <= s < t + W)
        cs = [c for ct, _, c in chat if t <= ct < t + W]
        if txt.strip() or cs:
            f.write(f"[{fmt(t)}] {txt}\n")
            if cs: f.write("   >> " + " / ".join(cs[:10]) + "\n")
        t += W

# ---- 3) 運営候補（# コメントを多く投稿しているアカウント）----
hashers = Counter(u for _, u, c in chat if c.startswith("#"))
print("\n== # コメント投稿数（上位＝運営候補。名前は内部判断のみに使う） ==")
if not hashers:
    print("  なし（コマンド未使用の配信。sbv発言のみを起点にする）")
for u, n in hashers.most_common(5): print(f"  {u}: {n}")

top = hashers.most_common(1)[0][0] if hashers else None
if top:
    print("\n== 運営 # コメント（進行の節目） ==")
    for t, u, c in chat:
        if u == top and c.startswith("#"): print(f"  [{fmt(t)}] {c}")

# ---- 4) コーナー検出（配信者の定型句から構成を割り出す）----
print("\n== コーナーの切れ目候補 ==")
for t, text in sbv:
    if any(k in text for k in CORNER): print(f"  [{fmt(t)}] {text[:45]}")

# ---- 5) チャットが沸いた区間 上位30（＝ハイライト候補）----
buckets = {}
for t, _, c in chat:
    if t < 0 or any(k in c for k in NOISE): continue
    b = t // 30
    hit = sum(1 for k in REACT if k in c)
    d = buckets.setdefault(b, [0, 0]); d[0] += 1; d[1] += hit
hot = sorted(buckets.items(), key=lambda kv: (-kv[1][1], -kv[1][0]))[:30]
print("\n== チャット反応スパイク（時刻 / 件数 / リアクション語数 / 直前のSBV発言） ==")
for b, (n, r) in sorted(hot):
    t = b * 30
    prev = [s for s in sbv if s[0] <= t + 30]
    line = prev[-1][1][:40] if prev else "(SBV該当なし)"
    print(f"  [{fmt(t)}] chat={n} react={r} | {line}")
```

```bash
python3 /tmp/build_timeline.py
```

### 前処理の使い分け

| ファイル | 用途 |
|---------|------|
| `/tmp/condensed.txt` | **通読用。** まずこれを頭から最後まで読んで配信全体の流れを掴む。60分の配信でおよそ400行に収まる |
| `/tmp/timeline.txt` | **時刻確定用。** シーンを決めた後、`grep` で該当発言を引いて秒単位の正確な時刻を確定する |

出力に含まれるユーザー名は運営アカウントの特定など**内部判断にのみ**使い、最終出力には決して載せない。

## タイムスタンプ抽出の統合手順

```
Step 0. 前処理スクリプトを実行し、sbv/chat の件数が正常なことを確認する
  → 0件ならフォーマット違いなので作業を止める

Step 1. info ファイルを読む
  → コマンド体系（@/#の意味）を把握し、チャット解釈の基準を確立する
  → 概要欄の企画名から構成の当たりをつける

Step 2. condensed.txt を頭から通読する
  → 配信者の発言・感情・話題の流れをつかむ
  → 同時にチャット反応も併記されているので、沸いた場所が目で分かる

Step 3. スクリプトの「コーナーの切れ目候補」「運営 # コメント」で構成を確定する
  → コマンド未使用の配信なら、定型句のみで構成を割り出す
  → ここで決めた構成が、後のコメント分割の単位になる

Step 4. 「チャット反応スパイク」でハイライト候補を拾う
  → 各候補について condensed.txt の該当箇所を読み返し、何が起きたか確認する

Step 5. comments ファイルを読む
  → 投稿後コメントから印象的だったシーンのヒントを得る（件数が少なければスキップ可）

Step 6. 候補を優先度で絞り込む
  → timeline.txt を grep して各シーンの正確な時刻を確定する
  → シーン説明を作成 → 複数コメントに分割
```

## タイムスタンプ選別基準

| カテゴリ | 具体的なシグナル | 優先度 |
|---------|----------------|--------|
| **ハプニング・事件** | エラー・バグ・予期しない展開（運営 `#` の訂正・謝罪も含む） | 高 |
| **感動シーン** | チャットに「泣いた」「エモ」「いい話」が集中 | 高 |
| **笑いどころ・ネタ** | チャットに「草」「ｗ」「マジか」が集中 | 中 |
| **正解・不正解の盛り上がり** | クイズ・ゲーム系での正解発表、チャットが沸く瞬間 | 中 |
| **話題の転換点** | コーナーの開始、運営 `#` による「次の問題」などの節目 | 低 |
| **視聴者参加の見せ場** | 順番待ち `@` コメントへの返答、視聴者との特定のやりとり | 低 |

## 配信時間別タイムスタンプ数の目安

| 配信時間 | 個数 |
|---------|------|
| 30分以下 | 10〜15 |
| 30〜60分 | 20〜30 |
| 60分以上 | 30〜50 |

**この数値はあくまで目安であり、ノルマではない。** 数を埋めるために中身の薄いタイムスタンプを量産してはならないし、逆に見どころが密集している区間を上限に縛られて切り捨ててもならない。

- 淡々と進む配信なら目安を下回ってよい
- 面白い展開が連続する区間は、2〜3分に複数個並んでも構わない
- 判断基準は常に「そのタイムスタンプを見て、視聴者がクリックしたくなるか」の一点
- 数合わせで入れた説明が 1 つでもあると目次全体の信頼度が落ちる。**削る方を優先する**

## シーン説明の作成ルール

### ルール1: 「要約」ではなく「予告（チラ見せ）」にする【最重要】

オチ、発言の答え、ハプニングの結末など、**それを読んで満足してしまう内容は絶対に書かない。** 「好奇心の空白（Curiosity Gap）」を刺激し、クリックしたくなる寸止め表現にする。

- 良い例: `[28:30] まさかの爆弾発言でチャット凍りつく`
- 悪い例: `[28:30] 〇〇は嫌いだと発言し爆笑`（オチを書き切っているためNG）

### ルール1補足: 「謎かけ→即答え」の連続ネタバレを防ぐ【最重要】

**「謎かけ」タイムスタンプの直後に「答え」タイムスタンプを置かない。**

- NG: `[5:50] チャットを惑わす第1問` → `[6:37] 「牛乳を注ぐ女」スタート`
- OK: `[5:50] チャットを惑わす第1問` → `[6:37] ようやく合点がいったチャット欄`

連想ゲーム・クイズの答え・ハプニングの顛末を列挙する説明はNG。

### ルール2: 自動文字起こしの誤変換を出力に持ち込まない【最重要】

sbv ファイルは自動文字起こしであり、**固有名詞・専門用語・早口部分は高確率で誤変換されている。** 実例:

- 「しずく」→ しず子 / 雫し / 静 / しく / しずの / 水
- 「あき先生」→ 秋先生 / 秋先線 / 全キさん
- 「SpaceX」→ スパセックス、「機種変」→ 機種編、「有言実行」→ 有限実行

守るべき規則:

1. **人物名・固有名詞は必ず正規表記に直して出力する。** 誤変換をそのまま見出しに使わない
2. **意味を確定できない崩れた行を起点にタイムスタンプを作らない。** 前後の文脈と繋がらない、明らかに文が壊れている、といった行は「配信者がおかしなことを言った」のではなく**単なる文字起こしの失敗**である可能性が高い
3. 特に「配信者が矛盾したことを言った」「言い間違えた」「自爆した」という趣旨の説明を書きそうになったら、**それは誤変換を実在の発言と誤認している疑いを最優先で検討する。** 前後 30 秒を読み直し、確証が持てなければそのシーンごと落とす
4. チャットの反応が裏取りに使える。本当に配信者が言い間違えたなら、チャットが必ず反応している。チャットが無反応なら誤変換と判断してよい

**迷ったら書かない。** 誤変換由来の説明は事実無根の記述であり、ハルシネーションと同じ扱いになる。

### ルール3: 熱心なリスナー目線のトーン

事務的な議事録ではなく、配信を楽しんでいるファンの目線で書く。「草」「エモい」「限界化」「沼る」など配信カルチャーの語彙を自然に使う。

### ルール4: 適切なトピックの粒度を保つ

「雑談」「ゲーム開始」など中身が想像できない大雑把な見出しは避ける。些細な出来事を2〜3分ごとに並べる細かすぎる見出しも避ける。

### ルール5: 簡潔さを優先

1つのシーン説明は **1〜2行（最大30文字程度）** に収める。

### ルール6: チャット反応を活用

その時刻前後のチャットから意味を読み取り、説明に反映させる。

- 例: sbv が「叩いてアピールします」のみでも、チャットが「痛くないですｗ」で沸いていれば → `謎のアピール方法にチャット突っ込みどころ満載`

### ルール7: 重要な人物名は記載

複数人が登場する配信では、誰のアクション・発言か明記する。

### ルール8: センシティブな話題の扱い

下ネタ・際どい話題は、**面白い盛り上がり方をしていない限り、そもそも取り上げない。** 配信中に一定時間その話題が続いていたとしても、タイムスタンプにする義務はない。無視してよい。

そのうえで、**面白く盛り上がっていた場合でも次は絶対に出力しない**:

- 配信者が無理をして捌いているであろう、閉鎖的で無自覚なセンシティブないじり
- 視聴者による無自覚ないじめの構造になっているやりとり
- 配信者が困っている・受け流している状態を「盛り上がり」と誤認したもの

チャットが沸いているかどうかだけで判断してはならない。**いじる側が盛り上がっているだけの場面は、盛り上がりではない。** 配信者側が明確にノって展開を広げている場合のみ、取り上げてよい。

取り上げる場合も、直接的な語を見出しに使わず「持論が展開される」程度の匂わせに留め、切り抜き的に強調しない。

### ルール9: タイムスタンプは必ず sbv の発言か運営 `#` コメントを起点にする【ハルシネーション防止】

- 各タイムスタンプは、対応する sbv の発言エントリ、または運営者の `#` コメント（節目・補足・進行情報）を必ず起点にする
- live_chat の視聴者コメントは「チャット反応の補足情報」として参照してよいが、**それだけを根拠にタイムスタンプを作ってはならない**
  - NG: 視聴者の `#感想` や通常コメントが面白くても、しずくの対応発言が sbv に無い場合
  - NG: `@質問コメント` が投稿されたが、しずくが応答しないまま流れた場合
- 「チャットが面白い」だけでは不十分。**しずくが実際に発言した証拠**（対応時刻の sbv エントリ）を確認してから説明文を書く
- sbv の内容が読み取れない時間帯は、その区間のタイムスタンプ数を絞り、確認できた範囲のみ記載する

## 出力形式

YouTube コメント欄は 1 コメント約 4000 文字が上限で、「続きを読む」で折りたたまれる。**折りたたまれない冒頭部分に最も魅力的なハイライトと注意書きを配置する。**

コピペしやすいよう、コメント（①②…）ごとにコードブロックで区切ってチャットに出力する。

```
【タイムスタンプ集】① オープニング～〇問目
🌟ハイライト：[MM:SS] （このパートで最も気になるシーンの寸止め説明）
※これは自動文字起こしからAIによって生成したタイムスタンプのため、ネタバレや誤り、時間のズレを含む可能性があります。

[MM:SS] シーン説明
[MM:SS] シーン説明
…
```

```
【タイムスタンプ集】② 〇問目 ～ 〇問目
🌟ハイライト：[MM:SS] （このパートの目玉シーン）

[MM:SS] シーン説明
…
```

- 注意書きは**最初のコメント（①）の冒頭にのみ**記載する
- **🌟ハイライトに挙げたシーンは、本文のリストにも同じ時刻・同じ説明で再掲する。** コピペ後にリストが飛び飛びになるのを防ぐため
- タイムスタンプ形式は 60 分未満なら `[MM:SS]`、超える場合は `[H:MM:SS]` を使用する
- 分割は配信の構成（コーナー単位・問題単位）に沿わせる。分割不要なら1コメントでよい
- 1 コメントあたり 10〜15 個が読みやすいが、これも目安。コーナーの区切りを優先する

## 禁止事項

- [ ] オチ・結末・発言の核心など「ネタバレ・完全な要約」を記載しない（チラ見せに徹する）
- [ ] 「謎かけ」直後のタイムスタンプで答えを書く「連続ネタバレ」をしない
- [ ] ログに存在しない事象や発言を推測・捏造（ハルシネーション）しない
- [ ] **自動文字起こしの誤変換をそのまま見出しに使わない**（人物名・固有名詞は正規表記に直す）
- [ ] **意味を確定できない崩れた行を根拠にタイムスタンプを作らない**（誤変換を実在の発言と誤認しない）
- [ ] **配信者が無理をして捌いている、無自覚ないじり／いじめ構造のやりとりを取り上げない**
- [ ] sbv の発言テキストをそのまま丸写しにしない
- [ ] 「雑談」「ゲーム開始」など中身が想像できない大雑把な見出しを作らない
- [ ] 個数の目安を埋めるためだけの、中身の薄いタイムスタンプを作らない
- [ ] 個人特定につながる内容を記載しない
- [ ] チャットのユーザー名（運営アカウント含む）を出力に含めない
- [ ] 説明を3行以上にしない
- [ ] YouTube のリンクやスパムコンテンツを紛れ込ませない
- [ ] sbv で対応する発言を確認せず、live_chat の視聴者コメント単独を根拠に説明文を作らない
- [ ] `.srt` ファイルを参照しない

## 出力品質チェックリスト

出力前に必ず全項目を確認する。

- [ ] 前処理スクリプトが sbv を正常に読めていたか（0件でないことを確認したか）
- [ ] シーン説明が動画のオチを明かしておらず、「好奇心の空白」を刺激する予告になっているか
- [ ] 「謎かけ」直後に答えになるタイムスタンプを置いていないか（隣接タイムスタンプを前後で読み直して確認）
- [ ] 人物名・固有名詞が誤変換のまま残っていないか
- [ ] 「配信者が言い間違えた／矛盾した」系の説明を書いていないか。書いたなら誤変換でないと確証があるか
- [ ] センシティブな話題を、配信者がノっていない状態で取り上げていないか
- [ ] 冒頭ハイライト配置など、YouTube の「続きを読む」UI を考慮した構成になっているか
- [ ] 注意書きが「※これは自動文字起こしからAIによって生成した〜時間のズレを含む可能性があります。」になっているか
- [ ] 配信カルチャーに沿ったリスナー目線のトーン（Vibe）が反映されているか
- [ ] タイムスタンプが大雑把すぎず、細かすぎない粒度か
- [ ] ハプニング・感動・笑いどころなど重要ハイライトが含まれているか
- [ ] すべてのタイムスタンプが `[MM:SS]` または `[H:MM:SS]` 形式か
- [ ] sbv と live_chat の時刻をきちんと突き合わせているか
- [ ] 運営 `#` コメントを節目・補足として正しく活用し、ユーザー名は出力に含めていないか（コマンド未使用の配信では定型句からコーナーを検出したか）
- [ ] 各タイムスタンプの説明が sbv の対応発言または運営 `#` コメントを起点にしているか
- [ ] 数合わせで入れた中身の薄いタイムスタンプが混ざっていないか
