# YouTube配信ログ → コメント用タイムスタンプ生成

## 目的

YouTube からダウンロードした 4 種類の生ファイルを直接読み込み、YouTube コメント欄に貼付可能なタイムスタンプ付きシーン説明を生成する。

単なる事務的な事象の羅列（議事録）ではなく、配信の熱量や文脈（Vibe）が伝わる魅力的な目次を作る。特に **「要約」ではなく「予告（Teaser）」** として機能させ、視聴者が「何があったのか」気になって思わずタイムスタンプをクリックしたくなるよう誘導することが最大の目的である。

出力は**チャットに直接**返す。ファイルは作らない。

## 配信者の扱い

メイン配信者は基本的に**「しずく」**として扱ってよい。ただしイベント回などで配信者が入れ替わる可能性があるため、次を確認してから書き始める。

- `.info.txt` のタイトル・概要欄、`.sbv.txt` 冒頭の自己紹介に別名義が出ていないか
- ユーザーが配信者名を明示している場合は、そちらを最優先で採用する

以降の記述で「しずく」とあるのは「その回のメイン配信者」と読み替えること。

---

## 入力ファイルと各フォーマット

4 ファイルすべてを入力として読み込む。通常は `/mnt/user-data/uploads/` に同一ベース名で置かれている。欠けているファイルがある場合は、その旨を伝えたうえで揃っているファイルだけで進めてよい（ただし `.sbv.txt` は必須。無い場合はハルシネーション防止のため作業を止めてユーザーに確認する）。

### ① `.info.txt`（動画メタ情報）

```
# 動画情報
タイトル  : （動画タイトル）
投稿日    : YYYY-MM-DD
動画ID    : （ID文字列）
URL       : https://www.youtube.com/watch?v=（ID）

────────
【説明】
────────
（概要欄テキスト）
```

読み取るべき情報:

- 配信タイトル・投稿日（出力ヘッダーへの参照用）
- 概要欄のコマンド説明（`@` `#` プレフィックスの意味を理解するために必須）
  - `@` なし = 普通のコメント（ランダムに一つ反応）
  - `@` 先頭 = 順番待ち列に入るコメント（必ず読まれる）
  - `#` 先頭 = しずくにスルーされるコメント（感想・リアクション専用）

### ② `.sbv.txt`（字幕・発言ログ）

```
[H:MM:SS]
（発言テキスト）

[H:MM:SS]
🎵 [音楽]
```

- タイムスタンプ形式は `[H:MM:SS]`（例 `[0:04:43]`）。**次の行**が発言内容
- `🎵 [音楽]` はBGMのみで発言なし
- エントリ間は空行で区切られる
- これは**配信者の発言のみ**を記録したもの
- `.live_chat.txt` の `[M:SS]` と単位が異なる。相互参照時は秒数に揃えて照合する（SBVの `[0:04:43]` = チャットの `[4:43]`）

### ③ `.live_chat.txt`（ライブチャットログ）

```
# ライブチャット一覧
# 動画: （タイトル）
# URL : （URL）
# 件数: （件数）

[-M:SS] @ユーザー名: コメント内容   ← 配信開始前（負の時刻）
[M:SS] @ユーザー名: コメント内容    ← 配信中（正の時刻）
```

- タイムスタンプ形式は `[M:SS]`。60分を超える場合は `[H:MM:SS]` になることもある
- 負のタイムスタンプは配信開始前の待機中コメント
- 各行は `[タイムスタンプ] @ユーザー名: メッセージ`

コメント種別の判別（`.info.txt` のコマンド説明と照合する）:

| 行の先頭パターン | 意味 | 扱い |
|----------------|------|------|
| `@ユーザー名: （普通の本文）` | 通常のビューワーコメント | 視聴者反応として参照する |
| `@ユーザー名: @（本文）` | 順番待ち列コメント（質問・話しかけ） | 配信者が応じた可能性あり。SBVの返答と照合 |
| `@ユーザー名: #（本文）` | 視聴者の感想・リアクション専用 | 反応の補足情報として参照 |
| **運営者の `#` コメント** | 配信設定・ゲーム進行の説明・訂正 | シーン理解に非常に有用（例「#1問目」「#正解です！」「#次へ行きます」） |

運営 `#` コメントの見分け方: 特定のユーザーが `#` 付きで進行情報・訂正・補足を繰り返し投稿していれば、そのアカウントは運営とみなしてよい（例 `@aki5503: #すみません、答え設定間違えましたｗｗ`）。配信の内部進行を知る重要な手がかりなので積極的に参照する。ただし**チャットのユーザー名は出力に一切含めない**。

### ④ `.comments.txt`（投稿後コメント）

```
# コメント一覧
# 動画: （タイトル）
# URL : （URL）
# 件数: （件数）

[YYYY-MM-DD HH:MM UTC] @ユーザー名（👍 N）
コメント内容
```

- 動画投稿後の通常コメント。時刻は動画内時刻ではなく投稿日時なので、シーンの時刻とは対応しない
- 視聴後の感想・評価として参照する
- 件数が少ない場合や、罵倒・スパム系のみの場合は無視してよい

## 前処理（ログが大きい場合）

まず規模を確認する。

```bash
wc -l /mnt/user-data/uploads/*.sbv.txt /mnt/user-data/uploads/*.live_chat.txt
```

`.sbv.txt` が 500 行を超える、または `.live_chat.txt` が 2000 行を超える場合は、目視で全部追うと時刻照合がずれてハルシネーションの原因になる。次のスクリプトを `/tmp/build_timeline.py` に保存して実行し、その出力を起点に候補を選ぶ。小規模ならこの工程は飛ばして直接読んでよい。

```python
import re, sys, glob
from collections import Counter

BASE = sys.argv[1] if len(sys.argv) > 1 else "/mnt/user-data/uploads"
REACT = ["草","ｗ","笑","泣","エモ","すご","ヤバ","やば","マジ","まじ","神","かわい",
         "!?","！？","？？","88","おめ","天才","尊い","惜し","正解","不正解","www"]

def to_sec(ts):
    neg = ts.startswith("-"); s = 0
    for p in ts.lstrip("-").split(":"): s = s * 60 + int(p)
    return -s if neg else s

def fmt(sec):
    h, r = divmod(abs(sec), 3600); m, s = divmod(r, 60)
    sign = "-" if sec < 0 else ""
    return f"{sign}{h}:{m:02d}:{s:02d}" if h else f"{sign}{m}:{s:02d}"

sbv = []
for path in glob.glob(f"{BASE}/*.sbv.txt"):
    lines = open(path, encoding="utf-8", errors="replace").read().splitlines()
    for i, line in enumerate(lines):
        m = re.fullmatch(r"\[(\d+(?::\d{2})+)\]", line.strip())
        if m and i + 1 < len(lines) and lines[i + 1].strip():
            sbv.append((to_sec(m.group(1)), lines[i + 1].strip()))
sbv.sort()

chat = []
for path in glob.glob(f"{BASE}/*.live_chat.txt"):
    for line in open(path, encoding="utf-8", errors="replace"):
        m = re.match(r"\[(-?\d+(?::\d{2})+)\]\s*(@[^:]+):\s*(.*)", line.rstrip("\n"))
        if m: chat.append((to_sec(m.group(1)), m.group(2), m.group(3).strip()))
chat.sort()

# 1) 完全マージ済みタイムラインをファイルに出力（後で grep / 部分読みする用）
with open("/tmp/timeline.txt", "w", encoding="utf-8") as f:
    for t, text in sbv:
        near = [c for ct, _, c in chat if t - 15 <= ct <= t + 30]
        f.write(f"[{fmt(t)}] SBV: {text}\n")
        for c in near[:6]: f.write(f"          chat: {c}\n")

# 2) 運営候補（# コメントを多く投稿しているアカウント）
hashers = Counter(u for _, u, c in chat if c.startswith("#"))
print("== # コメント投稿数（上位＝運営候補。名前は内部判断のみに使う） ==")
for u, n in hashers.most_common(5): print(f"  {u}: {n}")

# 3) 運営 # コメント（進行の節目）を時刻付きで列挙
top = hashers.most_common(1)[0][0] if hashers else None
print("\n== 運営 # コメント（進行の節目） ==")
for t, u, c in chat:
    if u == top and c.startswith("#"): print(f"  [{fmt(t)}] {c}")

# 4) チャットが沸いた区間 上位30（= ハイライト候補）
buckets = {}
for t, _, c in chat:
    if t < 0: continue
    b = t // 30
    hit = sum(1 for k in REACT if k in c)
    d = buckets.setdefault(b, [0, 0]); d[0] += 1; d[1] += hit
hot = sorted(buckets.items(), key=lambda kv: (-kv[1][1], -kv[1][0]))[:30]
print("\n== チャット反応スパイク（時刻 / 件数 / リアクション語数 / 直前のSBV発言） ==")
for b, (n, r) in sorted(hot):
    t = b * 30
    prev = [s for s in sbv if s[0] <= t + 30]
    line = prev[-1][1][:40] if prev else "(SBV該当なし)"
    print(f"  [{fmt(t)}] chat={n} react={r} | {line}")
```

```bash
python3 /tmp/build_timeline.py
```

スクリプト出力に含まれるユーザー名は運営アカウントの特定など**内部判断にのみ**使い、最終出力には決して載せない。

## タイムスタンプ抽出の統合手順

```
Step 1. .info.txt を読む
  → コマンド体系（@/#の意味）を把握し、チャット解釈の基準を確立する

Step 2. .sbv.txt を時系列で読む
  → 配信者の発言・感情・話題の流れをつかむ
  → 🎵[音楽] のみの区間はBGMタイム（発言なし）

Step 3. .live_chat.txt と .sbv.txt を時刻で突き合わせる
  → 発言と同時刻〜前後30秒のチャット反応を確認する
  → 「草」「すごい」「!?」「泣いた」「エモ」などの集中区間を特定する
  → 運営#コメントで節目（問題番号・正解発表・次の話題への移行）を把握する

Step 4. .comments.txt を読む
  → 投稿後コメントから印象的だったシーンのヒントを得る（件数が少なければスキップ可）

Step 5. 候補を優先度で絞り込み → シーン説明を作成 → 複数コメントに分割
```

## タイムスタンプ選別基準

| カテゴリ | 具体的なシグナル | 優先度 |
|---------|----------------|--------|
| **ハプニング・事件** | エラー・バグ・予期しない展開（運営 `#` の訂正・謝罪も含む） | 高 |
| **感動シーン** | チャットに「泣いた」「エモ」「いい話」が集中 | 高 |
| **笑いどころ・ネタ** | チャットに「草」「ｗ」「マジか」が集中 | 中 |
| **正解・不正解の盛り上がり** | クイズ・ゲーム系での正解発表、チャットが沸く瞬間 | 中 |
| **話題の転換点** | 運営 `#` による「次の問題」「エンディング」などの節目 | 低 |
| **視聴者参加の見せ場** | 順番待ち `@` コメントへの返答、視聴者との特定のやりとり | 低 |

## 配信時間別タイムスタンプ数の目安

| 配信時間 | 個数 |
|---------|------|
| 30分以下 | 10〜15 |
| 30〜60分 | 20〜30 |
| 60分以上 | 30〜50 |

## シーン説明の作成ルール

### ルール1: 「要約」ではなく「予告（チラ見せ）」にする【最重要】

オチ、発言の答え、ハプニングの結末など、**それを読んで満足してしまう内容は絶対に書かない。** 「好奇心の空白（Curiosity Gap）」を刺激し、クリックしたくなる寸止め表現にする。

- 良い例: `[28:30] まさかの爆弾発言でチャット凍りつく`
- 悪い例: `[28:30] 〇〇は嫌いだと発言し爆笑`（オチを書き切っているためNG）

### ルール1補足: 「謎かけ→即答え」の連続ネタバレを防ぐ【最重要】

**「謎かけ」タイムスタンプの直後に「答え」タイムスタンプを置かない。**

- NG: `[5:50] チャットを惑わす第1問` → `[6:37] 「牛乳を注ぐ女」スタート`
- OK: `[5:50] チャットを惑わす第1問` → `[6:37] ようやく合点がいったチャット欄`

連想ゲーム・クイズの答え・ハプニングの顛末を列挙する説明はNG。

### ルール2: 熱心なリスナー目線のトーン

事務的な議事録ではなく、配信を楽しんでいるファンの目線で書く。「草」「エモい」「限界化」「沼る」など配信カルチャーの語彙を自然に使う。

### ルール3: 適切なトピックの粒度を保つ

「雑談」「ゲーム開始」など中身が想像できない大雑把な見出しは避ける。些細な出来事を2〜3分ごとに並べる細かすぎる見出しも避ける。

### ルール4: 簡潔さを優先

1つのシーン説明は **1〜2行（最大30文字程度）** に収める。

### ルール5: チャット反応を活用

その時刻前後のチャットから意味を読み取り、説明に反映させる。

- 例: SBVが「叩いてアピールします」のみでも、チャットが「痛くないですｗ」で沸いていれば → `謎のアピール方法にチャット突っ込みどころ満載`

### ルール6: 重要な人物名は記載

複数人が登場する配信では、誰のアクション・発言か明記する。

### ルール7: タイムスタンプは必ず `.sbv.txt` の発言か運営 `#` コメントを起点にする【ハルシネーション防止】

- 各タイムスタンプは、対応する `.sbv.txt` の発言エントリ、または運営者の `#` コメント（節目・補足・進行情報）を必ず起点にする
- `.live_chat.txt` の視聴者コメントは「チャット反応の補足情報」として参照してよいが、**それだけを根拠にタイムスタンプを作ってはならない**
  - NG: 視聴者の `#感想` や通常コメントが面白くても、しずくの対応発言が `.sbv.txt` に無い場合
  - NG: `@質問コメント` が投稿されたが、しずくが応答しないまま流れた場合
- 「チャットが面白い」だけでは不十分。**しずくが実際に発言した証拠**（対応時刻の `.sbv.txt` エントリ）を確認してから説明文を書く
- `.sbv.txt` の内容が読み取れない時間帯は、その区間のタイムスタンプ数を絞り、確認できた範囲のみ記載する

## 出力形式

YouTube コメント欄は 1 コメント約 4000 文字が上限で、「続きを読む」で折りたたまれる。**折りたたまれない冒頭部分に最も魅力的なハイライトと注意書きを配置する。**

コピペしやすいよう、コメント（①②…）ごとにコードブロックで区切ってチャットに出力する。

```
【タイムスタンプ集】① オープニング～〇問目
🌟ハイライト：[MM:SS] （このパートで最も気になるシーンの寸止め説明）
※これは自動文字起こしからAIによって生成したタイムスタンプのため、ネタバレや誤り、時間のズレを含む可能性があります。

[MM:SS] シーン説明
[MM:SS] シーン説明
…
```

```
【タイムスタンプ集】② 〇問目 ～ 〇問目
🌟ハイライト：[MM:SS] （このパートの目玉シーン）

[MM:SS] シーン説明
…
```

- 注意書きは**最初のコメント（①）の冒頭にのみ**記載する
- タイムスタンプ形式は `.sbv.txt` に合わせ `[MM:SS]` または `[H:MM:SS]` を使用する
- 分割は配信の構成（問題単位・コーナー単位）に沿わせる。分割不要なら1コメントでよい

## 禁止事項

- [ ] オチ・結末・発言の核心など「ネタバレ・完全な要約」を記載しない（チラ見せに徹する）
- [ ] 「謎かけ」直後のタイムスタンプで答えを書く「連続ネタバレ」をしない
- [ ] ログに存在しない事象や発言を推測・捏造（ハルシネーション）しない
- [ ] SBV の発言テキストをそのまま丸写しにしない
- [ ] 「雑談」「ゲーム開始」など中身が想像できない大雑把な見出しを作らない
- [ ] 個人特定につながる内容を記載しない
- [ ] チャットのユーザー名（運営アカウント含む）を出力に含めない
- [ ] 説明を3行以上にしない
- [ ] YouTube のリンクやスパムコンテンツを紛れ込ませない
- [ ] `.sbv.txt` で対応する発言を確認せず、`.live_chat.txt` の視聴者コメント単独を根拠に説明文を作らない

## 出力品質チェックリスト

出力前に必ず全項目を確認する。

- [ ] シーン説明が動画のオチを明かしておらず、「好奇心の空白」を刺激する予告になっているか
- [ ] 「謎かけ」直後に答えになるタイムスタンプを置いていないか（隣接タイムスタンプを前後で読み直して確認）
- [ ] 冒頭ハイライト配置など、YouTube の「続きを読む」UI を考慮した構成になっているか
- [ ] 注意書きが「※これは自動文字起こしからAIによって生成した〜時間のズレを含む可能性があります。」になっているか
- [ ] 配信カルチャーに沿ったリスナー目線のトーン（Vibe）が反映されているか
- [ ] タイムスタンプが大雑把すぎず、細かすぎない粒度か
- [ ] ハプニング・感動・笑いどころなど重要ハイライトが含まれているか
- [ ] すべてのタイムスタンプが `[MM:SS]` または `[H:MM:SS]` 形式か
- [ ] `.sbv.txt` と `.live_chat.txt` の時刻をきちんと突き合わせているか
- [ ] 運営 `#` コメントを節目・補足として正しく活用し、ユーザー名は出力に含めていないか
- [ ] 各タイムスタンプの説明が `.sbv.txt` の対応発言または運営 `#` コメントを起点にしているか
- [ ] 配信時間に対して個数の目安に収まっているか
