# コマンド制の配信チャット（`@` / `#`）の扱い

**このファイルは、クイズ・ゲームなど進行管理のあるイベント配信でのみ必要になる。**

雑談配信・ASMR・歌枠などの通常配信では `@` `#` コマンドは基本的に登場しない。次のいずれかに該当する場合のみ、このファイルを参照する。

- info ファイルの概要欄に `@` `#` コマンドの説明が書かれている
- live_chat ファイルの本文（ユーザー名の後）が `@` や `#` で始まる行が実際に見られる
- **OCR復元版（`live_chat_ocr`）しか無く、info の概要欄にコマンドの説明がある**（記号が脱落している可能性があるため、行の見た目だけで判断しない）

該当しない場合は、live_chat のコメントはすべて通常の視聴者反応として扱えばよく、このファイルを読む必要はない。

---

## コマンド体系

info ファイルの概要欄に、その配信独自のコマンド説明が書かれていることが多い。まずそちらを確認し、次の一般的な意味と照合する。

- `@` なし = 普通のコメント（ランダムに一つ反応）
- `@` 先頭 = 順番待ち列に入るコメント（必ず読まれる）
- `#` 先頭 = しずくにスルーされるコメント（感想・リアクション専用）

## コメント種別の判別

| 行の先頭パターン | 意味 | 扱い |
|----------------|------|------|
| `@ユーザー名: （普通の本文）` | 通常のビューワーコメント | 視聴者反応として参照する |
| `@ユーザー名: @（本文）` | 順番待ち列コメント（質問・話しかけ） | 配信者が応じた可能性あり。sbv の返答と照合 |
| `@ユーザー名: #（本文）` | 視聴者の感想・リアクション専用 | 反応の補足情報として参照 |
| **運営者の `#` コメント** | 配信設定・ゲーム進行の説明・訂正 | シーン理解に非常に有用（例「#1問目」「#正解です！」「#次へ行きます」） |

運営 `#` コメントの見分け方: 特定のユーザーが `#` 付きで進行情報・訂正・補足を繰り返し投稿していれば、そのアカウントは運営とみなしてよい（例 `@aki5503: #すみません、答え設定間違えましたｗｗ`）。配信の内部進行を知る重要な手がかりなので積極的に参照する。ただし**チャットのユーザー名は出力に一切含めない**。

## 該当条件で開いたが、実際には 0 件だった場合

info ファイルにコマンドの説明はあったが、実際の配信では使われなかった、というケースもある。

1. まず本当にゼロかを確認する。`grep -c ': #' *live_chat*.txt` と `grep -c ': @' *live_chat*.txt` を実行する
2. どちらもゼロなら、**運営 `#` コメントによる節目検出は諦め、sbv ファイルの発言のみを起点とする**
3. 節目（コーナーの切れ目）は、SKILL.md 本体の「コーナー検出」で配信者の定型句から拾う
4. **「運営コメントが 0 件」という結果を、パース失敗と取り違えないこと。** 前処理スクリプトが表示する件数（sbv 件数・chat 件数）が正常であることを先に確認する

**OCR復元版（`live_chat_ocr`）の場合は、0件の解釈をもう一段慎重に行う。** OCRでは行頭の `#` `@` が脱落・誤読されやすく、「使われなかった」のか「読み取れなかった」のか区別がつかない。

- info の概要欄にコマンド説明があるのに0件なら、**OCRによる脱落を第一に疑う**
- 運営らしき同一アカウントが進行情報（「1問目」「正解です」など）を記号なしで繰り返し投稿していないか、`grep` で本文を直接探す。記号が落ちているだけで、内容から運営コメントと判別できることがある
- それでも判別できなければ、無理に運営コメントを推定せず sbv の発言のみを起点とする。**曖昧な推定で節目を作るより、節目が少ないほうがよい**
