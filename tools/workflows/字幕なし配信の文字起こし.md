# 字幕なし配信の文字起こし

YouTubeから字幕を正常に確認できたものの、字幕ファイルがない配信をspeech.cppで文字起こしします。既定は日本語指定が認識に反映される `qwen3-asr-1.7b --language ja` と発話検出・話者分離の組み合わせです。生成物はYouTubeの字幕と区別して `<動画ID>.transcribe.txt` に保存します。

## 必要なもの

- Pythonとyt-dlp（既存のログ取得ツールと共通）
- ffmpeg（PATHに配置）
- speech.cpp（`--vad`・`--diarize`・JSON出力に対応する版）
- `qwen3-asr-1.7b`（ASR）、`silero-vad`（発話検出）、`nemotron-3-diarization`（話者分離）を実行できるメモリとディスク容量
- 従来の認識を比較する場合のみ `nemotron-3.5-transcribe`（`--profile nemotron`）

speechは `SPEECH_EXE`、PATH、Windows標準のインストール先の順に検索します。モデルはspeech.cppが初回利用時に取得します。取得済みモデルの保存先はspeech.cppの `SPEECH_MODEL_DIR` で指定できます。モデルキャッシュは作業終了時にも削除しません。

CLIの仕様は `speech asr --help`、日本語指定の仕様は [speech.cppのQwen3-ASR説明](https://github.com/nyosegawa/speech.cpp/blob/main/docs/models/qwen3-asr.md) を参照してください。

## 通常のログ更新

```powershell
python tools/scripts/update_shizuku_logs.py --apply
```

新たに取得する配信に字幕がない場合、既存の `dys.cmd --auto` → `download_youtube_subtitles.py` から文字起こしが自動で実行されます。字幕取得のコマンド自体が失敗した場合は、字幕の有無を断定せず失敗として報告します。

既存ログは動画IDで収録済みと判定されるため、この更新コマンドだけでは過去の字幕欠落分を補完しません。次の単独実行を使用してください。ダウンローダーを直接使う場合は `--no-transcribe` で文字起こしを省略できます。

## 収録済みログを補完する

```powershell
python tools/scripts/transcribe_youtube.py u2T4jUpRDlM
```

指定したIDの `.info.txt` を `logs/youtube/` 内で検索し、その動画フォルダへ保存します。複数IDも指定できます。字幕または空でない `.transcribe.txt` が既にある場合は何も取得せずスキップします。既存ファイルは上書きしません。

空の `.transcribe.txt` がある場合も、上書きせず停止します。原因と内容を確認してから再実行してください。

必要な場合のみ実行ファイルやモデルを変更します。ユーザー固有の絶対パスや設定値をリポジトリへ保存しないでください。

```powershell
$env:SPEECH_EXE = Join-Path $env:LOCALAPPDATA 'Programs/speech.cpp/current/speech.exe'
python tools/scripts/transcribe_youtube.py u2T4jUpRDlM --chunk-minutes 55
```

ローカルGGUFを使う場合は `--model <GGUFのパス>` を指定できます。自動ダウンローダー側では標準モデル名を使うため、キャッシュの設定は `SPEECH_MODEL_DIR` で指定してください。

モデルを変更するときはプロファイルのオプションとの対応も確認してください。従来のNemotronの話者付きASRは `--profile nemotron` で指定できます。ASRだけを別のモデルへ差し替えても、非対応のオプションは自動で読み替えません。

## 既存字幕と比較するNemotron文字起こし

```powershell
# 収録済みの動画を1件だけ処理
python tools/scripts/transcribe_youtube.py hewYVVuoPyQ --profile nemotron-comparison

# 収録済みの全動画を1件ずつ処理
python tools/scripts/transcribe_youtube.py --all --profile nemotron-comparison
```

`logs/youtube/` にある `<動画ID>.info.txt` を基に対象を選び、同じフォルダに `<動画ID>.nemotron-3.5-transcribe.txt` を追加します。既存字幕や `.transcribe.txt` がある動画も対象です。比較用ファイルが保存済みならスキップし、空のファイルがある場合はエラーにします。`--all` は各動画の失敗後も次へ進み、最後に保存・保存済み・失敗の件数と失敗したIDを表示します。

合成音声を発話検出で取りこぼした例があるため、比較用では `speech asr nemotron-3.5-transcribe --speakers` に全音声を入力します。1時間以上の音声は55分ごとに分割します。各区間を1分ずつ認識し、各入力の開始時刻を認識結果に足して結合します。造語やローマ字を含め、認識結果の語句と表記はそのまま残します。発話時刻が得られない場合は、認識に使った音声の範囲と本文が残ります。

一時ファイルは `outputs/shizuku-nemotron-comparison/run_<動画ID>_<ランダム値>/` に置き、保存・再読込の成功後に実行フォルダを削除します。失敗時のフォルダには診断ログが残ります。取得済みのWAVがある場合は、対象IDと `--profile nemotron-comparison --resume-workdir <作業フォルダ>` を指定して再開できます。

## 既存字幕と比較するQwen3-ASR文字起こし

```powershell
python tools/scripts/transcribe_youtube.py YuJ4oOGNGxg --profile qwen-comparison
```

Nemotron比較用と同じ音声の分割方法で、全音声をQwen3-ASR 1.7Bの日本語指定（`--language ja`）で認識し、`<動画ID>.qwen3-asr-1.7b.txt` に追加します。発話検出を使わず、本文の時刻は入力した音声の範囲で示します。作業フォルダは `outputs/shizuku-qwen-comparison/` です。GPUで別の処理を実行中は `--device cpu` でCPUを指定できます。

## 既存ASRを日本語で再生成する

```powershell
python tools/scripts/transcribe_youtube.py u2T4jUpRDlM --profile japanese --replace-transcript
```

`--replace-transcript` は明示的な再生成専用です。旧ASRを作業フォルダへ退避し、全区間が成功するまで動画フォルダの旧ファイルを保持します。置換直前に内容のハッシュを照合し、処理中に人が変更した場合は置換しません。YouTube提供字幕・動画情報・チャット・コメントは置き換えません。

内容確認が必要な場合は `--keep-staging` を付けると成功後も作業データを保持します。新しい出力を確認してから、その実行の専用フォルダだけを削除してください。フォルダ名の推測や一括削除は行いません。

## 処理と保存形式

1. `outputs/shizuku-transcribe/run_<動画ID>_<ランダム値>/` を作ります。
2. yt-dlpで映像と音声を取得します。映像は原則480p以下に制限します。
3. ffmpegで16kHz・モノラル・16bit PCMのWAVへ変換します。
4. 1時間以下ならそのまま、1時間を超える場合は55分ごとのWAVへ分割します。分割長は1〜59分で変更できます。音声フレームを連続して切り分け、意図的な重複は設けません。
5. 各区間を `speech asr qwen3-asr-1.7b --language ja --vad silero-vad --diarize nemotron-3-diarization --format json <WAV>` で処理します。
   モデルの出力上限（終了コード3または `stop: model_limit`）に達した区間は不完全な本文を採用せず、5分以下に再分割して自動再試行します。さらに上限へ達する場合は半分程度へ短縮し、1分以下の区間でも失敗した場合は停止します。その他のエラーは再分割で隠さず停止します。
6. 全区間の正常終了とJSONを確認し、区間の開始秒を加えて元動画基準の時刻へ戻し、順番に結合します。
7. UTF-8で保存・再読込検証した結果を動画フォルダへ配置します。既定では上書きせず、明示的な再生成時だけ上の確認後に旧ASRを置き換えます。
8. 成功した実行の専用作業フォルダだけを削除します。既存の動画情報・チャット・コメント・字幕、他の作業フォルダやモデルは削除しません。

出力例（書式説明用の架空データ）:

```text
# 自動文字起こし [AI生成・未確認]
# 動画ID: u2T4jUpRDlM
# URL: https://www.youtube.com/watch?v=u2T4jUpRDlM
...
## 区間002 [00:55:00.000 --> 01:15:47.000]
[00:55:01.250 --> 00:55:03.000] 区間002/話者0: 本文
```

既定プロファイルの時刻は発話検出区間の境界で、単語単位の時刻ではありません。話者番号は区間ごとに独立しています。同じ番号でも区間をまたいだ同一人物と推定しません。複数話者が検出された区間は、本文のどの部分を誰が話したかは未確認として表示します。CLIが時刻を返せない場合は「時刻未取得」として原文を残し、時刻を推測しません。

### 日本語表記の注意

2026-11-01に `u2T4jUpRDlM` をspeech.cpp 0.10.0・IQ4_NL・`--speakers` で処理した結果、ローマ字表記が多いことを確認しました。処理の正常終了は日本語字幕としての品質を保証しません。

[speech.cppのNemotron仕様](https://github.com/nyosegawa/speech.cpp/blob/main/docs/models/nemotron-transcribe.md)では、このモデルの `language` は指定値の検証のみで出力言語・表記の誘導には使われず、`speakers` と `prompt` も併用できません。同じ音声の30秒で `--speakers --language ja` と `--timestamps --language ja` を比較しましたが、いずれもローマ字でした。一方、Qwen3-ASRの `--language ja` では漢字・仮名の日本語出力を確認したため、既定を日本語プロファイルへ変更しました。ローマ字を推測で漢字・仮名へ書き換えず、音声から再認識します。

## 失敗・中断時

- ASRの上限到達（終了コード3を含む）の不完全な本文、途中終了、不正JSON、不正な時刻、根拠のない空の本文を成功扱いしません。上限到達だけは上の再分割を試します。発話検出が空の区間を明示した場合は「発話区間検出で認識対象なし・要確認」と記録し、無音や発話がなかったことまでは断定しません。
- 全区間が成功するまでは最終ファイルを作りません。再確認用に、その実行の動画・WAV・分割音声・JSON・診断ログを `outputs/` に残します。作業ログにはローカルパス等が含まれるため公開しません。
- 原因を解消して動画IDを指定し直すと、新しい作業フォルダで再実行します。失敗した実行のフォルダは自動削除・自動再利用しません。
- ダウンロードと音声化が済んでいる場合は、`--resume-workdir` でその実行のフォルダを明示し、取得済みWAVから再開できます。動画ID・URLを記録した `request.json` と音声形式を照合し、別動画や専用フォルダ外からの再開は拒否します。認識は新しい試行用サブフォルダで行い、全区間成功後は元の実行フォルダをまとめて削除します。
- 自動更新中に失敗した場合、取得済みの動画情報等は保存されることがあります。そのIDを上の単独コマンドで再実行してください。
- 最終ファイルはASRの未確認結果です。歌唱・固有名詞・分割境界では特に誤認識や欠落が起こり得ます。引用や事実確認では元動画へ戻り、手作業の訂正をする際は原文との区別と根拠を残します。

再開の書式例（`run_...` は実際に表示された実行フォルダへ置き換え）:

```powershell
python tools/scripts/transcribe_youtube.py u2T4jUpRDlM --chunk-minutes 5 --resume-workdir outputs/shizuku-transcribe/run_u2T4jUpRDlM_...
```
