# Wiki記事の素材にする配信ログを20万トークン以内にまとめる手順

編集者が、数日間の企画で何が起きたかを読み通し、記事に使いたい発言を元動画で探せる資料を作る。納品用のTXTには、動画別の目次、場面の短い説明、根拠になる字幕・投稿・説明欄、確認が必要な点を収める。場面説明には「要約」、原文には資料の種類を明記する。

## 実行順

### 1．動画と出典を固定する

動画ごとにID、タイトル、投稿日、長さ、入力ファイル名・ハッシュ・件数・欠落を作業記録に残す。元ログは読み取り専用で扱う。今回の2日目前半は「チャット未収録」と記し、反応がなかったとは推定しない。フォルダ日付、説明欄にある予定日時、動画内の経過時間を区別する。前後半・別日の再生時計は動画ごとにゼロから扱う。

字幕の照合基準は元SRTとする。SBVは時刻と本文をSRTと突き合わせ、固有の差分を調べる。変換によって字幕の終了位置が延びたり、音楽だけの区間が消えたりすることがある。監査記録と伏せ字も確認する。例えば `_9Eg156xD6A` のSBV監査記録は、SRTブロック1750、`3:33:22.920` の「ありがとうございます」を実際の繰り返しか判断できず保持したと記す。この種の反復は自動削除から外す。

### 2．意味を変えずに削り、計測する

SRTとSBVの照合済みの重複、装飾罫線、余分な空行、繰り返されるヘッダを省く。共通の説明欄は該当動画IDの一覧とともに一度だけ収録する。章の追加、期限、参加ルール、次回予告などの差分は各回に残す。匿名IDを短縮する場合は全編で一貫した番号を使い、元の匿名IDへ引けるようにする。

この段階では発言の内容を選別しない。動画別・資料種別に、変更前後のトークン数を記録する。以後も各段階で測り、予算に届いた時点でそれ以上の削減を止め、検証へ進む。

### 3．全編を読み、先に残す場面を決める

長時間の前後半は元動画基準の短い区間に分けて通読し、境目は前後を重ねて読む。各動画について、出来事・原資料の区間・話者の確度・後で照合する回をメモする。説明欄の章や通常コメントの目次を探索に使い、目次のない区間も順に確認する。通常コメントには投稿日時と、本文中で視聴者が挙げた再生時刻の両方があり、記事候補には後者が指す元資料を当てる。

残す単位は、状況の説明から問い、返答、結果または訂正までを追える一場面。短い「はい」「違う」でも選択を決めた発言なら前後ごと残す。予告と実際の結果、劇中設定と運営説明、その場の受け止めと楽屋裏・後日の説明を、動画IDと時刻で相互に引けるようにする。時刻の近さだけで応答や因果を確定しない。

今回の読みどころの一例は、説明欄に記された「しずくが選択する期限」と、実際に選択が示された場面の関係。説明欄の時計時刻から本編の再生位置を逆算せず、各回の字幕・チャットから探す。本人の語り、作中の登場人物、運営の投稿、視聴者の解釈が混ざる箇所には資料ごとのラベルを残す。

### 4．低優先度の部分から段階的に短くする

| 順番 | 対象と処理 | 残すもの |
| --- | --- | --- |
| 先に集約 | 場面に新しい情報を加えない待機・挨拶・連続した同文反応 | 必要な場面では実例1件の原時刻、集計区間、投稿数。選択・合図・訂正・呼び掛けへの返答なら短文でも個別採録。 |
| 次に抜粋 | すでに示された話題の繰り返し、企画の流れに影響の薄い雑談 | 各回の日常の様子や関係性が伝わるやり取りを、きっかけと応答を含めて採録。同じ挨拶でも関係の変化を示す再登場は残す。 |
| さらに必要なら要約 | 長い区間で同じ状態・話題が続く部分 | 区間の開始・終了、短い経過説明、前後の転換点。別場面をつなぐときは省略区間を明示する。 |
| 最後まで保護 | 選択の条件と結果、説明の変更、告白、反証・訂正、関係の変化、結末、後日談、記事で引用したい言葉 | 最小限の連続した原文、元の時刻、話者または話者未確認、関連する前後の場面。 |

「#」など当時のコマンド、音楽・沈黙、絵文字の一斉投稿も、投票・転換・演出を示す場合がある。頻度、文字数、盛り上がり、語句一致だけで重要度を決めない。集計した同文は投稿件数として記し、参加人数・有効票・全体の総意には読み替えない。時間割や配信尺に一律の削減率を掛けず、10本すべてに場面説明と出典を確保してから、転機の密度に合わせて残りの予算を配る。

### 5．採録した発言を元の再生位置に結び付ける

- 字幕原文の各行にはSRTの開始・終了をミリ秒まで保持する。ライブチャットの個別投稿は原ログの時刻と発言者区分を保持する。配信開始前の負の時刻も符号ごと保存する。収録のない時刻は「時刻なし」とする。
- 要約には根拠区間の両端、集計には集計した時間幅を付ける。時刻が飛ぶ抜粋は行を分ける。説明欄の設定や後日のコメントを、本編でその時刻に発せられた台詞として並べない。
- 出典の単位は「動画ID・資料種別・元時刻」。動画IDとファイル名は各動画の冒頭で宣言し、正の再生位置には必要に応じて開始秒を切り捨てたYouTubeリンクを添える。原時刻は併記する。負の時刻には動画本体のURLと「開始前」を付ける。
- 字幕だけでは確定しにくい話者・固有名詞・言い回しは原文とともに「要試聴」とする。後日コメントで見つけた候補も同様に扱う。記事で逐語引用するときは実際の音声で確認する。

**実例**　完結編の通常コメントにある `4:25:46` を手掛かりに、`fouEm9-QB0w.ja.srt` の `04:25:46,159 --> 04:25:50,340` まで戻れる。字幕本文は「私はそれでも人間を信じたいですもう一度」で、文は次の区間へ続く。この場面を採る際は `04:26:07,780` までの続きも一緒に読み、聞き取りが怪しい箇所を含めて要試聴とする。同じ秒の視聴者投稿には独立した時刻とラベルを付ける。

### 6．記事を書けるか、出典に戻れるか、上限に収まるかを検証する

1. 入力台帳の動画IDと納品版の10本を照合する。採録した字幕・個別投稿は**全件**、本文・時刻・参照元を機械照合する。同文集計は元行を再集計し、欠落・省略・集計による省スペース化を区別して件数を記録する。
2. 重要場面を要約から元ログへ、元ログの転機から要約へ双方向に確認する。問いだけ、結論だけ、後から否定された説明だけが残ったら前後を戻す。長い未採録区間、静かな時間帯、前後半の境界、チャット欠落回、完結編と楽屋裏を重点的に読み返す。音声未確認の引用候補にはその状態を残す。
3. 目次・凡例・出典を含む最終TXT全体をGemma 4とo200k_baseで再計測する。今回は大きい方で**18万〜18.5万を作業目安、20万を上限**とする。余裕があれば、文脈審査で戻したかった原文から復元する。予算が足りなければ低優先度の要約を再調整し、根拠が薄くなる場面を断定的に書かない。
4. 納品は1つのUTF-8 TXTを基本とする。入力台帳や詳しい採否記録は作業用に置く。納品時には両方式の計測値、動画別の収録・省略状況、欠落資料、要試聴箇所を報告する。対象モデルの実測が得られた場合は、ローカル推定と区別して記録する。

記事化の際は、[しずくWikiの記事の調査・編集手順](../skills/shizuku-wiki/references/article-workflow.md)に沿って、圧縮ログに記載された元資料を確認する。
