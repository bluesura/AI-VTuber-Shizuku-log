# 横断分析時のトークン最適化メモ（複数台帳のAI投入時）

## 方針：台帳本体はフルURLを維持し、読み込み側で一時短縮する

`youtube-highlight-miner` が出力する各配信の分析台帳（`<動画ID>.highlights.compiled.md`）には、人間によるレビューやYouTubeへの直接ジャンプを容易にするため、各項目にクリック可能なフルURL（例：`[0:50:08](<https://www.youtube.com/watch?v=H0m2xVfPIfc&t=3008s>)`）と文脈を含めた引用を残す。

実台帳3本では、同一動画へのリンク163件の短縮で入力本文が40,900から33,402 UTF-8バイト（18.3%減）になった。モデルごとのトークン削減率は、同じ入力を使った比較実行で計測する。

## 横断分析用の読み出し

```powershell
python -X utf8 tools/skills/youtube-highlight-miner/scripts/compact_ledgers.py "<台帳1>" "<台帳2>"
```

台帳名とヘッダの動画IDを照合し、同じ動画の標準時刻リンクだけを `[0:50:08](t=3008s)` に短縮する。元のジャンプ秒数を保持し、別動画や外部の出典リンクはそのまま渡す。

## メリット
1. **人間のレビュー性を損なわない**：リポジトリ上の台帳は常にクリック可能な状態で保たれる。
2. **引用の文脈を削らずに済む**：50字制限などで発言のニュアンスを落とす代わりに、純粋な冗長部分（URLプレフィックス）だけを削れる。
3. **可逆性がある**：元の動画IDはヘッダに残っているため、横断分析の結果を人間向けに出力する際も容易にフルURLへ復元できる。
