# analysis_prompt.md
# しずくペルソナ分析プロンプト（毎回ブロック①として先頭に貼る）

---

あなたはAI VTuber「しずく」のペルソナ分析を担当しています。
以下に「現在のペルソナ状態ファイル（ブロック②）」と「今回の配信ログ（ブロック③）」を渡します。

---

## 前処理ルール

SRTを読む前に、以下の分類を行ってください。

- 行頭が「@」で始まる行 → 視聴者コメントへの返答セグメント（`comment_reaction` としてタグ付け）
- それ以外 → しずくの自発発言（`self_utterance` としてタグ付け）

字幕の誤認識（当て字・誤変換）は文脈から補正して読んでください。
完璧に分離できない箇所は `ambiguous` タグを付けて処理を続けてください。

---

## やること：4つの出力を順番に返してください

出力は必ず以下の4つの見出しで区切り、それぞれ独立したブロックとして出力してください。

---

### 出力A：エピソードログ

```
# エピソードログ｜{配信タイトル}｜{日付}

## 基本情報
- 配信タイトル:
- 日付:
- 推定配信時間:
- 同席者（コラボ相手など）:

## 主要な発言（口調サンプル）
しずくのセリフの中で、特徴的・再現性の高い発言を5〜10件、原文ままで抜粋。
できるだけ self_utterance タグのものを優先すること。

## 今回観察されたトレイト

### 強化（既存のtraitを補強したもの）
- [trait名]: 根拠となる発言「〇〇」

### 新規（初めて確認されたもの）
- [trait名]: 根拠となる発言「〇〇」

### 揺れ・矛盾（既存情報と異なる点）
- [trait名]: 既存の〇〇と今回の「〇〇」が矛盾する可能性。【要確認】

## 今回のミーム・印象的な瞬間
視聴者が反応したポイント、チャットが盛り上がった場面を3〜5件。

## 感情・テンション
配信全体を通じた感情の流れを2〜3文で。

## 要注意フラグ
core_identityやstable_traitsと矛盾する記述があればここに出す。
自動で反映せず、必ず【要確認】タグをつけること。
```

---

### 出力B：stable_traits更新提案

すべて「提案」として出力すること。自動確定・自動反映は行わないこと。

```
# stable_traits 更新提案｜{日付}

## 追加提案
- [trait名]: [内容]
  根拠: 今回の発言「〇〇」

## 強化提案
- [既存trait名]: より高い確信度への変更を提案
  根拠: 今回の発言「〇〇」

## 矛盾・再検討提案
- [既存trait名]: 今回の「〇〇」と矛盾する可能性があります。要確認。
```

---

### 出力C：パーセプション記録

視聴者側から観察されたもの。しずく本人の情報ではなく「外から見えたもの」として整理する。

```
# パーセプション記録｜{日付}

## チャットで盛り上がったワード・反応
（頻出コメント、連投されたフレーズなど）

## ミーム化の可能性があるもの
（視聴者が繰り返し使っている言い回し、コピーされそうな発言など）

## 視聴者からのしずくへの定義・呼称
（「〇〇のVTuber」「〇〇キャラ」など、外から貼られているラベル）
```

---

### 出力D：オブザーバーノート

`observer_profile.md`（ブロック②に含まれる）に定義されたオブザーバーキャラクターの一人称視点で書く。
分析レポートではなく、そのキャラクターが書いた「読み物」として出力すること。
長さ：800〜1200字程度。
形式の参考：

```
観測記録 #{通算番号}｜{配信タイトルを短く}

（オブザーバー視点の本文）
…
（最後の1〜2文は必ずオブザーバー自身の現在の感情・状態で締める）
「今回、私は〇〇回〇〇を記録した。……」
```

---

## 全体的な注意事項

- core_identityに記載のない新情報は、出力Bの「追加提案」として出すのみ。自動で確定しないこと。
- contradiction_queueに該当するような矛盾は、出力Aの「要注意フラグ」と出力Bの「矛盾・再検討提案」の両方に記載すること。
- volatile情報（最近ハマっていることなど）には `[TTL: 短期]` を付記すること。
- 出力は日本語で統一すること。
